🧰 Glossário de ferramentas (leia uma vez antes das abas!)
  • Linguagem de programação (Python, Java): o “idioma” com regras próprias para escrever o código. Python é a linguagem mais usada em ciência de dados hoje; Java é outra linguagem (o Weka foi escrito nela).
  • Biblioteca: um pacote de código pronto que outra pessoa escreveu e você reaproveita, em vez de começar do zero. 💡 Como usar mistura de bolo pronta.
  • Como se lê um código: nome(algo) significa “chame a função nome passando algo”. Função = comando pronto que faz uma tarefa; o que vai entre parênteses é o parâmetro (o ajuste).
  • scikit-learn (biblioteca de Python): a caixa de ferramentas de aprendizagem de máquina mais famosa. modelo.fit(X, y) — “fit” = ajustar: entrega a tabela de exemplos (X) com as respostas (y) e o algoritmo monta o modelo. modelo.predict(novo) — “predict” = prever. Resumindo: fit = aprender; predict = aplicar o que aprendeu.
  • Weka (programa em Java, sem código): janelas e botões: abre a tabela, escolhe o algoritmo, clica e pronto. IBk = k-NN, J48 = árvore de decisão.
  • Dataset: a tabela de exemplos (linha = exemplo, coluna = atributo). pandas: biblioteca de Python para mexer em tabelas.

01 — Como os sistemas digitais aprendem

🌍 No mundo real
  • Filtro de spam: cada e-mail que você marca como “spam” vira um exemplo; o sistema generaliza e reconhece spams que nunca viu.
  • Criança aprendendo “gato”: depois de ver vários gatos, ela generaliza — e às vezes chama um tigre de gato (generalização em construção!).
🛠️ Nas ferramentas — explicado em detalhe
  • Linguagem de programação: o “idioma” do código. Python = a mais usada em dados; Java = outra (o Weka é feito nela).
  • Biblioteca: código pronto. 💡 Mistura de bolo.
  • Como ler código: nome(algo) = função + parâmetro.
  • scikit-learn (Python): modelo.fit(X, y) entrega a tabela com as respostas e o algoritmo “estuda”; modelo.predict(novo) aplica. fit = aprender; predict = aplicar.
  • Weka (Java, sem código): janelas e botões. IBk = k-NN, J48 = árvore.
🔤 Mini-dicionário
  • Algoritmo: uma “receita de passos” para resolver algo. Modelo: o “resumo/lição” que o algoritmo constrói depois de ver os exemplos.
  • Exemplo/instância: um caso concreto (linha da tabela). Atributo: cada característica (coluna). Rótulo/classe: a resposta que queremos prever.
  • Representação fatorada: descrever cada exemplo por pares atributo–valor, ou seja, uma tabela — o formato que a maioria dos algoritmos consome.
📖 Conceitos + analogias
  • Os 4 fatores de Simon (o que torna o aprendizado possível): (1) dados/experiência, (2) conhecimento prévio, (3) representação dos exemplos e hipóteses, (4) capacidade de generalização. 💡 Estudante: boa apostila (dados), base anterior (prévio), bom jeito de fazer resumo (representação) e saber resolver questões novas (generalização).
  • Dedução: do geral para o caso; conclusão necessária se as premissas forem verdadeiras. 💡 “Todo mamífero tem pulmão; baleia é mamífero → baleia tem pulmão.”
  • Indução: dos casos para o geral; conclusão provável, não garantida. 💡 “Vi 100 cisnes brancos → todo cisne é branco” (até aparecer um negro!). Aprendizagem de máquina é indutiva.
🎤 Plano de testes
  1. Passo 0 — entender a tela: dois painéis: os 4 fatores do aprendizado (🗂️🎯) e os dois tipos de raciocínio (➡️/⬅️).
  2. Teste 1 — os 4 fatores. Clicar: os quatro botões, um de cada vez. Vê: um texto explicando cada fator. Significa: para um sistema aprender ajudam quatro coisas — dados bons e em quantidade, o que ele já sabia antes, uma boa forma de anotar os exemplos (a tabela fatorada) e a capacidade de aplicar a lição a casos novos; se qualquer um falha, o aprendizado falha, como um estudante sem apostila ou sem base.
  3. Teste 2 — dedutivo. Clicar: ➡️ Dedutivo. Vê: a REGRA aparece primeiro e o caso depois. Significa: deduzir é aplicar uma regra geral a um caso particular; se a regra estiver certa, a conclusão é garantida — mas nada de novo é aprendido, só aplicado.
  4. Teste 3 — indutivo. Clicar: ⬅️ Indutivo. Vê: vários CASOS primeiro e a regra só no final. Significa: induzir é o caminho contrário e arriscado: inventar uma regra geral a partir de poucos casos; a regra é “provavelmente” certa, não “certamente” — e é exatamente esse salto que um sistema de aprendizagem de máquina dá.

02 — Aprendizado supervisionado: treino, teste e generalização

🌍 No mundo real
  • “Supervisionado” = com gabarito: cada exemplo de treino vem com a resposta certa, como exercício corrigido pelo professor.
  • Simulado vs prova oficial: você estuda com simulados (treino), mas o que vale é a prova (teste) — com questões novas. Decorar o simulado e travar na prova = overfitting.
🛠️ Nas ferramentas — explicado em detalhe
  • scikit-learn (Python): train_test_split(X, y, test_size=0.3) é uma função que embaralha e divide a tabela: 70% treino, 30% teste (o 0.3 é o parâmetro).
  • Weka (sem código): aba Classify → “percentage split 70/30”.
  • Por que dividir? Treino = simulado com gabarito; teste = prova com questões novas: é nele que vemos se generalizou ou só decorou.
🔤 Mini-dicionário
  • Conjunto de treino: exemplos com resposta usados para construir o modelo. Conjunto de teste: exemplos separados, que o modelo não vê no treino. Ruído: erros/irregularidades nos dados.
  • Generalização: acertar exemplos novos. Overfitting: decora o gabarito (e o ruído) e vai mal no teste. Underfitting: simples demais, erra até no treino.
🎤 Plano de testes
  1. Passo 0 — entender a tela: pontos azuis cheios = treino (simulado); círculos laranja = teste (prova); linha vermelha = o modelo; o controle deslizante = a complexidade do modelo.
  2. Teste 1 — modelo simples. Clicar: arraste o controle para 1–2. Vê: uma linha quase reta, com acurácia média nos dois conjuntos. Significa: o modelo é simples demais para capturar o desenho dos dados — underfitting, o aluno que estudou de menos: erra o simulado e a prova.
  3. Teste 2 — modelo na medida. Clicar: arraste para 5–6. Vê: a linha acompanha o padrão dos pontos e os dois percentuais sobem juntos. Significa: o modelo aprendeu a regra geral e acerta também o que não viu — isso é generalizar, o objetivo de tudo.
  4. Teste 3 — modelo complexo. Clicar: arraste para 9–10. Vê: a linha “serpenteia” para passar por cada ponto azul; treino chega a ~100% e o teste despenca. Significa: overfitting — o modelo decorou o gabarito, inclusive os erros (ruído) da apostila, e trava diante de questões novas. Desconfie de “100% no treino”!

2) Por que separar um conjunto de teste?

03 — Lógica indutiva: estratégias e pré-processamento

🌍 No mundo real
  • Cozinhar: lavar e cortar os ingredientes antes da receita = pré-processamento.
  • Formulário com faixas etárias: “18–25, 26–59, 60+” = discretização; igual a roupas P/M/G.
  • Aprender vivendo vs estudar tudo de uma vez: incremental vs em lote.
🛠️ Nas ferramentas — explicado em detalhe
  • pandas (Python): o “super Excel” do código. fillna() = “preencher os NA” (Not Available, faltantes), p.ex. com a média — o que fizemos com a idade do Beto na demo.
  • Discretização no scikit-learn: KBinsDiscretizer = “discretizador em K caixas”.
  • No Weka (sem código): filtros ReplaceMissingValues e Discretize, no menu Filters.
🔤 Mini-dicionário
  • Estratégia incremental: o modelo é atualizado a cada exemplo novo que chega. 💡 Aprender com cada experiência do dia. Não incremental (em lote): o modelo é construído de uma vez, com todos os exemplos. Ler o livro inteiro e só então fazer o resumo.
  • Pré-processamento: limpar e preparar os dados: faltantes, textos inconsistentes, erros. Discretização: transformar número contínuo em categorias/faixas.
  • Atributos numéricos vs nominais: números (idade) vs categorias/rótulos (“alto/baixo”).
🎤 Plano de testes
  1. Passo 0 — entender a tela: a tabela mostra 4 clientes; repare no “?” (idade faltando) e na renda escrita de três jeitos diferentes.
  2. Teste 1 — dado cru. Clicar: “ver tabela crua”. Vê: a idade do Beto faltando e “alto/Alto/baixo” como se fossem coisas diferentes. Significa: dados reais chegam sujos; algoritmo recebendo dado sujo se confunde — “lixo entra, lixo sai”.
  3. Teste 2 — pré-processar. Clicar: “pré-processar”. Vê: o “?” vira 42 (a média das outras idades) e a renda fica padronizada. Significa: pré-processar é lavar e cortar os ingredientes antes da receita: preencher faltantes e padronizar rótulos para o algoritmo conseguir aprender.
  4. Teste 3 — discretizar. Clicar: “discretizar”. Vê: as idades viram jovem/adulto/idoso. Significa: discretizar é trocar o número exato por faixas; simplifica, reduz ruído e muitos algoritmos (como árvores) preferem categorias.
  5. Teste 4 — estratégias. Clicar: os dois botões de estratégia. Vê: as duas explicações lado a lado. Significa: no incremental o modelo muda a cada exemplo novo (o k-NN apenas guarda cada exemplo na hora); no não incremental, como a árvore, todos os exemplos são analisados juntos para montar o modelo de uma vez.

04 — k-nearest neighbors (k-NN)

🌍 No mundo real
  • “Dize-me com quem andas…”: para adivinhar a turma de um aluno novo, olhe os colegas mais próximos dele no pátio.
  • Recomendação: “clientes parecidos com você também compraram…” é k-NN na prática.
🛠️ Nas ferramentas — explicado em detalhe
  • scikit-learn (Python): KNeighborsClassifier(n_neighbors=3) = “classificador pelos vizinhos mais próximos com k=3”. .fit(X,y) só guarda (lazy); .predict(novo) mede distâncias, acha os k e vota.
  • Weka (sem código): IBk; no campo “KNN” você digita o k.
🔤 Mini-dicionário
  • Vizinhos mais próximos: os k exemplos de treino com menor distância até o novo. Distância euclidiana: a “régua reta”: √((x₁−x₂)²+(y₁−y₂)²); entre (0,0) e (3,4) dá 5.
  • Votação por maioria: a classe do novo é a mais votada entre os k vizinhos. Lazy: não constrói modelo no treino — só guarda os exemplos.
🎤 Plano de testes
  1. Passo 0 — entender a tela: pontos azuis = gatos, laranja = cães (2 atributos: peso e altura). Clicar no gráfico coloca um animal novo (ponto preto).
  2. Teste 1 — k=3. Clicar: “k=3” e depois numa área vazia perto dos azuis. Vê: o ponto preto, 3 linhas até os vizinhos mais próximos e a votação (ex.: 2 gatos, 1 cão → gato). Significa: o k-NN não cria regra: procura os k “amigos” mais parecidos já guardados e copia a maioria — como adivinhar o gosto musical de alguém pelos 3 melhores amigos.
  3. Teste 2 — k=1. Clicar: “k=1” no mesmo lugar. Vê: uma linha só decide tudo. Significa: julgar por UM amigo: se ele for atípico (ruído), você erra — k=1 é instável.
  4. Teste 3 — k=5 e a régua. Clicar: “k=5”. Vê: mais linhas, voto “democrático” e os tamanhos das linhas embaixo. Significa: k maior = consultar mais amigos (mais estável; exagerou, puxa gente de longe); os números são a distância euclidiana — e como ela soma atributos, escala grande (salário) atropela a pequena (idade): normalizar antes é obrigatório no k-NN.

05 — Árvore de decisão

🌍 No mundo real
  • Triagem de pronto-socorro: “tem febre? → sim → há quanto tempo?…” — você já decide em árvores sem perceber.
  • Banco: renda, histórico, idade… cada pergunta afunila até “aprova/nega”.
🛠️ Nas ferramentas — explicado em detalhe
  • scikit-learn (Python): DecisionTreeClassifier; parâmetros controlam crescimento e poda (ex.: ccp_alpha); export_text(modelo) imprime as regras SE–ENTÃO.
  • Weka (sem código): J48, com checkbox de poda: desligue e veja “decorar” o treino; ligue e veja simplificar — igual ao ✂️ da demo.
🔤 Mini-dicionário
  • Nó raiz: a primeira pergunta, por onde todo exemplo entra. Ramos: as respostas possíveis que levam adiante. Folhas: os nós finais com a decisão (a classe). Poda: cortar ramos que memorizaram ruído, para generalizar melhor.
🎤 Plano de testes
  1. Passo 0 — entender a tela: o desenho é a árvore: a pergunta do topo é a raiz; as setas “— sim/não →” são os ramos; os retângulos laranja no fim são as folhas (decisões).
  2. Teste 1 — sem chuva. Clicar: “chove: não”. Vê: o caminho acende em verde direto até a folha “Jogar ⚽”. Significa: classificar é descer a árvore respondendo perguntas até cair numa folha; cada caminho é uma regra legível — “SE não chove, ENTÃO jogar” — por isso a árvore é um modelo “caixa branca” (dá para explicar o porquê da decisão).
  3. Teste 2 — com chuva. Clicar: “chove: sim” e depois “vento: sim/não”. Vê: o caminho passa por uma segunda pergunta antes da folha. Significa: a árvore é montada de cima para baixo escolhendo, a cada nó, a pergunta que melhor separa as decisões; árvores muito fundas tendem a decorar o treino (overfitting).
  4. Teste 3 — podar. Clicar: “✂️ podar”. Vê: o pedaço do “vento?” some e vira uma folha só: “Não jogar (maioria)”. Significa: podar é cortar o ramo que só existia para memorizar casos raros; a árvore fica menor e erra menos em casos novos — o remédio clássico contra o sobreajuste. Clique de novo para repor.

06 — Considerações sobre os algoritmos supervisionados

🌍 No mundo real
  • “No free lunch” (não há almoço grátis): nenhum algoritmo é o melhor para tudo — você não toma sopa com faca.
  • Médico vs caixa-preta: em decisões críticas vale um modelo explicável (árvore), mesmo um pouco menos preciso.
📖 Comparativo k-NN × Árvore
k-NNÁrvore de decisão
Treinoquase zero (lazy: só guarda)constrói o modelo em lote
Previsãolenta (calcula distâncias)rápida (desce a árvore)
Interpretabilidadebaixaalta (regras SE–ENTÃO)
Escala dos atributoscrítica (exige normalização)não afeta
Overfittingk pequenoárvore profunda → poda
Comum aos doissupervisionados, indutivos, dependem de pré-processamento e de treino/teste para medir generalização
🎤 Plano de testes
  1. Passo 0 — entender a tela: a tabela compara os dois algoritmos linha a linha; leia de cima para baixo.
  2. Teste 1 — o comparativo. Clicar: nada — apenas leia a tabela em voz alta. Vê: o k-NN não gasta nada no treino, mas paga caro e sensível à escala em cada previsão; a árvore faz o contrário e ainda se explica. Significa: “no free lunch”: não há vencedor universal; e quando é preciso explicar (médico, banco, juiz), a interpretabilidade da árvore vale ouro.
  3. Teste 2 — o fio condutor. Clicar: volte nas abas 01–05 rapidamente. Vê: o mesmo roteiro se repetindo. Significa: todo método supervisionado faz o mesmo movimento: recebe exemplos rotulados bem pré-processados, generaliza por indução (k-NN por vizinhança, árvore por perguntas) e só vale se acertar o que não viu — por isso treino/teste, overfitting e generalização são o coração da unidade.
🗺️ Mapa da aula (visão geral)

Dados crus → 🧹 pré-processamento → dividir treino/teste → 🤖 algoritmo indutivo (k-NN por vizinhança | árvore por perguntas) → avaliar no TESTE (generalização; overfitting → escolha de k / poda) → ✅ modelo em uso.

Os 4 fatores de Simon atravessam tudo: dados, conhecimento prévio, representação e generalização.

📝 Cola rápida (uma linha por termo)
  • Indução: casos → regra provável (é assim que o sistema “aprende”).
  • Treino/teste: simulado com gabarito / prova com questões novas.
  • Overfitting: decorou o gabarito; underfitting: não estudou o suficiente.
  • Pré-processamento: passar a receita a limpo; discretização: trocar medidas por P/M/G.
  • k-NN: “dize-me com quem andas”; k = quantos amigos consultar; régua = distância euclidiana; lazy.
  • Árvore: fluxograma de perguntas (raiz → ramos → folhas); poda = cortar exceções; caixa branca.
  • No free lunch: nenhuma ferramenta serve para tudo.
