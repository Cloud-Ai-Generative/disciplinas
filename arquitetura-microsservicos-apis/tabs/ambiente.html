5 GitHub: conta, fork, clone e autorização ⏱️ 20 min

5.1 Criar a conta (pule se já tiver)
  1. Entre em github.com/signup e informe e-mail, senha e nome de usuário (ou entre com uma conta Google). O usuário aparece no endereço dos seus repositórios e no seu portfólio: prefira algo profissional, como nome-sobrenome.
  2. Digite o código que o GitHub manda para o seu e-mail e escolha o plano Free, que atende toda a disciplina.
  3. Ative a verificação em duas etapas (2FA): no seu avatar, Settings → Password and authentication. Use um app autenticador ou uma chave de acesso (passkey) e guarde os códigos de recuperação. O GitHub recomenda fortemente a 2FA e pode passar a exigi-la de contas que enviam código; ativando agora, você não é interrompido no meio de uma entrega.

As telas do GitHub mudam com o tempo. Em caso de dúvida, siga a documentação oficial: Criar uma conta no GitHub e Configurar a autenticação de dois fatores.

🍴 Fork, clone e origin: três cópias, três papéis

  • Repositório da disciplina (Cloud-Ai-Generative/paguai): é o original, mantido pelo professor. Você pode ler e baixar, mas não pode enviar nada para ele. É dele que vêm as tags de cada sprint.
  • Fork (SEU-USUARIO/paguai): é uma cópia do repositório da disciplina dentro da sua conta do GitHub. Ela é sua: você pode enviar commits, criar branches e guardar os seus ADRs sem mexer no original nem no fork dos colegas. É também o que aparece no seu portfólio.
  • Clone (a pasta paguai no seu computador): é a cópia do seu fork na sua máquina, onde você roda o Docker e edita o código. No clone, o nome origin aponta para o seu fork. Por isso o git push origin envia para o seu fork, e não para o repositório da disciplina.

Por que fork, e não só clone? Só com um clone do repositório da disciplina, você não teria para onde enviar o seu trabalho. O fork te dá um lugar seu no GitHub.

Como chegam as sprints novas? O seu fork não recebe sozinho o que o professor publica depois. Por isso, no início de cada sprint, o laboratório busca as tags novas direto no repositório da disciplina:

terminal, na pasta paguai (o seu clone)
git fetch https://github.com/Cloud-Ai-Generative/paguai.git --tags

📐 D-00 Fluxo De onde vem e para onde vai o código

👀 Como ler: você faz o fork uma vez e o clone uma vez. Depois, o seu trabalho sobe para o seu fork (git push), e as sprints novas descem do repositório da disciplina (git fetch ... --tags).

📚
Analogia: o fork é como tirar uma cópia de um livro da biblioteca para a sua estante: você pode anotar nela à vontade, e o livro da biblioteca não muda. A analogia vale até aqui: ela explica por que você pode mexer sem estragar o original. A partir daqui ela engana: a sua cópia não se atualiza sozinha quando a biblioteca recebe uma edição nova; você precisa buscar.

5.3 Autorizar o envio de código

Para enviar os seus ADRs ao seu fork (git push), o terminal precisa de autorização. A senha da conta não funciona no terminal. Escolha um caminho:

  1. Pelo VS Code (recomendado): abra a pasta paguai no VS Code. No primeiro git push, o VS Code abre o navegador para você entrar no GitHub e autorizar. Funciona igual em Windows, macOS e Linux.
  2. Só pelo terminal: instale o GitHub CLI e rode gh auth login, escolhendo GitHub.com, HTTPS e login pelo navegador.
  3. No Codespaces: já vem autorizado.

Teste agora, para descobrir um problema de acesso hoje e não na entrega do ADR. No terminal do VS Code, na pasta do seu clone:

terminal, na pasta paguai (o seu clone)
git switch -c teste-acesso
git commit --allow-empty -m "Teste de acesso ao meu fork"
git push -u origin teste-acesso
git switch -
git push origin --delete teste-acesso
🔍 Entenda os comandos, parte por parte
git switch -c teste-acessoCria uma branch de teste a partir de onde você está.
git commit --allow-empty -m "..."Cria um commit sem mudar nenhum arquivo, só para ter o que enviar.
git push -u origin teste-acessoEnvia a branch para o seu fork (origin). Aqui o VS Code ou o gh pedem a autorização.
git switch - e git push origin --delete teste-acessoVoltam para onde você estava e apagam a branch de teste do fork.
✅ Resultado esperado: o git push termina com * [new branch] teste-acesso -> teste-acesso, e a branch aparece no seu fork no GitHub até você apagá-la. Se der Authentication failed ou Permission denied, veja "Git, GitHub e tags" em Problemas comuns.
💼 O seu fork também é o seu portfólio. Você pode achar que o GitHub é só o lugar onde o código da disciplina fica guardado. Ele é também uma vitrine do seu trabalho. Ao longo das 14 sprints, o seu fork da PagUai vai reunir o que você construiu: um monólito que virou microsserviços, contratos de API, mensageria, contêineres, testes e os ADRs em que você justificou cada decisão. Empresas e recrutadores costumam olhar o perfil do GitHub para conhecer as tecnologias que a pessoa domina e como ela trabalha. Se você ainda não tem uma conta, crie uma; o plano gratuito atende toda a disciplina. Se já tem, este projeto entra ao lado dos que você já mostra.
  • Faça commits com mensagens claras, que contem o que você fez e por quê.
  • Escreva os seus ADRs. Eles mostram como você pensa, não só o código que você escreveu.
  • Fixe o repositório no seu perfil (botão "Customize your pins") e escreva no seu README pessoal o que você aprendeu.

A PagUai é uma empresa fictícia, e o código tem vulnerabilidades de propósito para as sprints de segurança. Diga isso a quem visitar o seu perfil: no README do seu fork ou na descrição do repositório.

☁️ Plano B: GitHub Codespaces

Pouca memória, computador da empresa sem permissão de instalar ou instalação travada? Use o Codespaces: um ambiente completo no navegador, já com Docker e .NET 10.

  1. No seu fork, clique em Code, aba Codespaces, e em Create codespace on main.
  2. Espere o ambiente abrir (alguns minutos na primeira vez) e siga os laboratórios no terminal dele.
🏢 Na empresaAmbientes de desenvolvimento na nuvem, como o Codespaces, são comuns em empresas grandes: todo o time começa com a mesma configuração. O plano gratuito do GitHub tem um limite mensal de horas; desligue o codespace quando não estiver usando.
