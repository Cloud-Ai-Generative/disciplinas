1 VS Code: o seu editor de código ⏱️ 15 min

O que é: o Visual Studio Code (VS Code) é um editor de código gratuito da Microsoft, para Windows, macOS e Linux. É onde você vai abrir o projeto da PagUai, ler o código, editar os ADRs, rodar comandos no terminal embutido e acompanhar o Git. Ele é leve e ganha recursos por extensões (passo 5). Outros editores, como Rider, Visual Studio ou IntelliJ, também servem; os passos desta disciplina usam o VS Code.

Os botões dos instaladores estão em inglês: aqui eles aparecem como você vai vê-los, com a tradução ao lado.

Windows
  1. Entre em code.visualstudio.com e clique no botão azul Download for Windows ("Baixar para Windows"). Vem um arquivo como VSCodeUserSetup-x64-1.xx.x.exe.
  2. Abra a pasta Downloads e dê dois cliques no arquivo. Se o Windows perguntar se o aplicativo pode fazer alterações, clique em Sim.
  3. License Agreement (contrato de licença): marque I accept the agreement ("Eu aceito") → Next ("Avançar").
  4. Select Destination Location e Select Start Menu Folder (onde instalar e pasta no Menu Iniciar): não mude nada → Next → Next.
  5. Select Additional Tasks (tarefas adicionais), a tela mais importante. Deixe marcados:
    • Add "Open with Code" action para arquivos e para pastas: cria a opção "Abrir com Code" no botão direito do mouse.
    • Add to PATH: deixa o terminal encontrar o VS Code pelo comando code. Já vem marcado; não desmarque.
    • Create a desktop icon (opcional): atalho na área de trabalho.
    → Next.
  6. Ready to Install → Install ("Instalar"). Na tela final, deixe marcado Launch Visual Studio Code e clique em Finish ("Concluir").

2 O terminal ⏱️ 10 min

O que é: o terminal é uma janela onde você conversa com o computador digitando comandos em vez de clicar. Parece antigo, mas é o jeito mais rápido e repetível de fazer muitas coisas: instalar programas, usar o Git, subir a PagUai com o Docker. O VS Code tem um terminal embutido, e é ele que vamos usar em toda a disciplina.

  1. No menu do topo do VS Code, clique em Terminal → New Terminal ("Novo terminal"). Atalho: Ctrl+` (a tecla de crase, à esquerda do 1).
  2. O painel abre embaixo, com uma linha terminando em > ou $ e o cursor piscando: ele está esperando um comando. A pasta que aparece nessa linha é a pasta onde o comando vai rodar.
  3. Digite o comando abaixo e aperte Enter:
    terminal do VS Code
    code --version
✅ Resultado esperado: aparece o número da versão do VS Code, como 1.xx.x. Se aparecer "code não é reconhecido como comando" ou "command not found", veja o passo 1 (no Windows, a opção Add to PATH; no macOS, o comando Shell Command) e abra um terminal novo.
SistemaO terminal que abre no VS CodeCopiar e colar no terminal
WindowsPowerShellCtrl+C e Ctrl+V, ou o botão direito do mouse
macOSzshCmd+C e Cmd+V
LinuxbashCtrl+Shift+C e Ctrl+Shift+V
📋 Como ler os comandos desta disciplina: cada bloco diz, no alto, onde rodar (por exemplo, "terminal, na pasta paguai"). Use o botão 📋 Copiar, cole no terminal e aperte Enter. Quando o bloco tem várias linhas, pode colar tudo de uma vez. Depois de instalar um programa, feche e abra o terminal de novo: terminais que já estavam abertos não enxergam o que foi instalado depois.

3 Git ⏱️ 10 min

O que é: o Git guarda o histórico do código: cada mudança vira um commit, com autor, data e mensagem. É com ele que você baixa a PagUai, troca de sprint pelas tags e envia os seus ADRs para o seu fork (passo 7).

Windows
  1. Entre em git-scm.com/install/windows e clique em Click here to download. Vem um arquivo como Git-2.xx.x-64-bit.exe.
  2. Dê dois cliques no arquivo e clique em Sim se o Windows pedir permissão.
  3. O instalador tem várias telas. Clique em Next em todas, mantendo o que já vem marcado, com uma exceção: na tela Choosing the default editor used by Git (editor padrão), escolha Use Visual Studio Code as Git's default editor.
  4. Na última tela, clique em Install e depois em Finish.
  5. Feche o VS Code e abra de novo, para o terminal dele enxergar o Git.

winget install --id Git.Git -e
macOS

No terminal do VS Code, rode o comando abaixo. Ele instala as ferramentas de linha de comando da Apple, que incluem o Git. Se aparecer uma janela, clique em Instalar. Se aparecer "already installed", o Git já está aí.

Diga ao Git quem é você

Todo commit leva o nome e o e-mail de quem fez. Sem isso, o Git recusa o primeiro commit com a mensagem Please tell me who you are. Use o mesmo e-mail da sua conta do GitHub (passo 7): assim os commits aparecem no seu perfil e contam no seu portfólio.

terminal do VS Code (qualquer pasta)
git config --global user.name "Seu Nome Completo"
git config --global user.email "seu-email@exemplo.com"
git config --global init.defaultBranch main
🔍 Entenda os comandos, parte por parte
git config --globalgrava uma configuração que vale para todos os projetos deste computador
user.name e user.emailo nome e o e-mail que vão em cada commit; troque pelos seus, mantendo as aspas
init.defaultBranch mainnovos repositórios começam na branch main, como no GitHub
✅ Resultado esperado: git config --global --list mostra o seu user.name e o seu user.email.

4 Docker ⏱️ 15 a 25 min

O que é: o Docker roda programas dentro de contêineres, caixas isoladas que já trazem tudo de que o programa precisa. Com ele, a PagUai, o PostgreSQL, o RabbitMQ e o Mailpit rodam igual em qualquer computador, sem você instalar nenhum deles.

Windows
  1. Entre na página de instalação do Docker Desktop para Windows e clique em Docker Desktop for Windows - x86_64 (quase todo computador com Windows; a versão Arm é só para processadores Snapdragon).
  2. Dê dois cliques em Docker Desktop Installer.exe e clique em Sim se o Windows pedir permissão.
  3. Na tela Configuration, deixe marcado Use WSL 2 instead of Hyper-V (usar o WSL 2 em vez do Hyper-V) → Ok. Espere instalar e clique em Close ("Fechar"). Se o instalador pedir, reinicie o computador.
  4. Abra o Docker Desktop pelo menu Iniciar, aceite os termos (Accept). O login com conta Docker é opcional: pode pular (Skip).
  5. Se ele avisar que falta o WSL 2: clique com o botão direito no menu Iniciar → Terminal (Admin) ou Windows PowerShell (Admin), rode o comando abaixo e reinicie o computador.
    PowerShell como administrador
    wsl --install

    O WSL 2 (Subsistema do Windows para Linux) é um Linux leve dentro do Windows; o Docker Desktop roda os contêineres nele.

⌨️ Prefere instalar por comando? (PowerShell)
terminal do VS Code (PowerShell)
winget install --id Docker.DockerDesktop -e
macOS
  1. Entre na página de instalação do Docker Desktop para Mac e baixe a versão do seu processador: Apple Silicon (M1 ou mais novo) ou Intel. Na dúvida: menu → Sobre este Mac.
  2. Abra o Docker.dmg e arraste o Docker para Aplicativos.
  3. Abra o Docker pela pasta Aplicativos, aceite os termos e autorize o que ele pedir. O login com conta Docker é opcional.
Linux · Ubuntu

curl -fsSL https://get.docker.com -o get-docker.sh

🔍 Entenda os comandos, parte por parte

7 GitHub: conta, fork, clone e autorização ⏱️ 20 min

7.1 Criar a conta (pule se já tiver)
  1. Entre em github.com/signup e informe e-mail, senha e nome de usuário (ou entre com uma conta Google). O usuário aparece no endereço dos seus repositórios e no seu portfólio: prefira algo profissional, como nome-sobrenome.
  2. Digite o código que o GitHub manda para o seu e-mail e escolha o plano Free, que atende toda a disciplina.
  3. Ative a verificação em duas etapas (2FA): no seu avatar, Settings → Password and authentication. Use um app autenticador ou uma chave de acesso (passkey) e guarde os códigos de recuperação. O GitHub recomenda fortemente a 2FA e pode passar a exigi-la de contas que enviam código; ativando agora, você não é interrompido no meio de uma entrega.

As telas do GitHub mudam com o tempo. Em caso de dúvida, siga a documentação oficial: Criar uma conta no GitHub e Configurar a autenticação de dois fatores.

🍴 Fork, clone e origin: três cópias, três papéis

  • Repositório da disciplina (Cloud-Ai-Generative/paguai): é o original, mantido pelo professor. Você pode ler e baixar, mas não pode enviar nada para ele. É dele que vêm as tags de cada sprint.
  • Fork (SEU-USUARIO/paguai): é uma cópia do repositório da disciplina dentro da sua conta do GitHub. Ela é sua: você pode enviar commits, criar branches e guardar os seus ADRs sem mexer no original nem no fork dos colegas. É também o que aparece no seu portfólio.
  • Clone (a pasta paguai no seu computador): é a cópia do seu fork na sua máquina, onde você roda o Docker e edita o código. No clone, o nome origin aponta para o seu fork. Por isso o git push origin envia para o seu fork, e não para o repositório da disciplina.

Por que fork, e não só clone? Só com um clone do repositório da disciplina, você não teria para onde enviar o seu trabalho. O fork te dá um lugar seu no GitHub.

Como chegam as sprints novas? O seu fork não recebe sozinho o que o professor publica depois. Por isso, no início de cada sprint, o laboratório busca as tags novas direto no repositório da disciplina:

terminal, na pasta paguai (o seu clone)
git fetch https://github.com/Cloud-Ai-Generative/paguai.git --tags

📐 D-00 Fluxo De onde vem e para onde vai o código

👀 Como ler: você faz o fork uma vez e o clone uma vez. Depois, o seu trabalho sobe para o seu fork (git push), e as sprints novas descem do repositório da disciplina (git fetch ... --tags).

📚
Analogia: o fork é como tirar uma cópia de um livro da biblioteca para a sua estante: você pode anotar nela à vontade, e o livro da biblioteca não muda. A analogia vale até aqui: ela explica por que você pode mexer sem estragar o original. A partir daqui ela engana: a sua cópia não se atualiza sozinha quando a biblioteca recebe uma edição nova; você precisa buscar.

  2. Clone o seu fork, trocando SEU-USUARIO pelo seu usuário do GitHub:

7.3 Autorizar o envio de código

Para enviar os seus ADRs ao seu fork (git push), o terminal precisa de autorização. A senha da conta não funciona no terminal. Escolha um caminho:

  1. Pelo VS Code (recomendado): abra a pasta paguai no VS Code. No primeiro git push, o VS Code abre o navegador para você entrar no GitHub e autorizar. Funciona igual em Windows, macOS e Linux.
  2. Só pelo terminal: instale o GitHub CLI e rode gh auth login, escolhendo GitHub.com, HTTPS e login pelo navegador.
  3. No Codespaces: já vem autorizado.

Teste agora, para descobrir um problema de acesso hoje e não na entrega do ADR. No terminal do VS Code, na pasta do seu clone:

terminal, na pasta paguai (o seu clone)
git switch -c teste-acesso
git commit --allow-empty -m "Teste de acesso ao meu fork"
git push -u origin teste-acesso
git switch -
git push origin --delete teste-acesso
🔍 Entenda os comandos, parte por parte
git switch -c teste-acessoCria uma branch de teste a partir de onde você está.
git commit --allow-empty -m "..."Cria um commit sem mudar nenhum arquivo, só para ter o que enviar.
git push -u origin teste-acessoEnvia a branch para o seu fork (origin). Aqui o VS Code ou o gh pedem a autorização.
git switch - e git push origin --delete teste-acessoVoltam para onde você estava e apagam a branch de teste do fork.
✅ Resultado esperado: o git push termina com * [new branch] teste-acesso -> teste-acesso, e a branch aparece no seu fork no GitHub até você apagá-la. Se der Authentication failed ou Permission denied, veja "Git, GitHub e tags" em Problemas comuns.
💼 O seu fork também é o seu portfólio. Você pode achar que o GitHub é só o lugar onde o código da disciplina fica guardado. Ele é também uma vitrine do seu trabalho. Ao longo das 14 sprints, o seu fork da PagUai vai reunir o que você construiu: um monólito que virou microsserviços, contratos de API, mensageria, contêineres, testes e os ADRs em que você justificou cada decisão. Empresas e recrutadores costumam olhar o perfil do GitHub para conhecer as tecnologias que a pessoa domina e como ela trabalha. Se você ainda não tem uma conta, crie uma; o plano gratuito atende toda a disciplina. Se já tem, este projeto entra ao lado dos que você já mostra.
  • Faça commits com mensagens claras, que contem o que você fez e por quê.
  • Escreva os seus ADRs. Eles mostram como você pensa, não só o código que você escreveu.
  • Fixe o repositório no seu perfil (botão "Customize your pins") e escreva no seu README pessoal o que você aprendeu.

A PagUai é uma empresa fictícia, e o código tem vulnerabilidades de propósito para as sprints de segurança. Diga isso a quem visitar o seu perfil: no README do seu fork ou na descrição do repositório.
