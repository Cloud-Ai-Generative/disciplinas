📐 Como o ambiente está montado

📐 D-04 C4 · Contêineres Dois contêineres, uma rede

👀 Como ler: cada caixa dentro do retângulo é um contêiner. A API encontra o banco pelo nome db, pela rede interna que o Compose cria. Da sua máquina, você acessa a API pela porta 8000.

📐 D-05 UML · Sequência O que acontece no docker compose up

👀 Como ler: a API só começa depois que o banco responde ao healthcheck. Sem isso, ela tentaria conectar num banco ainda ligando e cairia.

💡 Conceito: imagem, contêiner e Compose

📦 Três palavras

  • Imagem: a "receita congelada" de um ambiente: sistema, Python e dependências. É descrita no Dockerfile.
  • Contêiner: uma imagem em execução, isolada do resto da máquina.
  • Docker Compose: descreve vários contêineres que trabalham juntos (API + banco) num único arquivo YAML.

O docker-compose.yml do projeto, resumido (o arquivo completo tem comentários linha a linha):

api/docker-compose.yml
services:
  db:
    image: postgres:17-alpine          # imagem oficial do PostgreSQL
    environment:
      POSTGRES_USER: ${POSTGRES_USER}  # valores vêm do .env
      POSTGRES_PASSWORD: ${POSTGRES_PASSWORD}
      POSTGRES_DB: ${POSTGRES_DB}
    volumes:
      - dados-postgres:/var/lib/postgresql/data   # os dados sobrevivem ao "down"
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U $${POSTGRES_USER} -d $${POSTGRES_DB}"]

  api:
    build: .                           # imagem feita a partir do Dockerfile
    environment:
      DATABASE_URL: postgresql+psycopg://${POSTGRES_USER}:${POSTGRES_PASSWORD}@db:5432/${POSTGRES_DB}
    ports:
      - "${API_PORT:-8000}:8000"
    volumes:
      - ./:/app                        # seu código dentro do contêiner
    depends_on:
      db:
        condition: service_healthy     # espera o banco ficar pronto
💡 Repare no endereço do banco: dentro da rede do Compose, o banco se chama db, e não localhost. Para a API, localhost é o próprio contêiner dela.
📝 As decisões: ADR 0003 e ADR 0006
ADR 0003 · Docker Compose para todo o ambiente aceita

Contexto: turma com Windows, macOS e Linux e versões diferentes de Python; o clássico "na minha máquina funciona".

Decisão: API e banco em contêineres, descritos num docker-compose.yml; o código é montado no contêiner para recarregar ao salvar.

Alternativas: instalar Python e PostgreSQL em cada máquina; ou só o banco no Docker.

Consequências: o aluno não instala Python nem PostgreSQL e sobe tudo com um comando; em troca, o Docker pede memória e virtualização (plano B: Codespaces).

ADR 0006 · Configuração por variáveis de ambiente (.env) aceita

Contexto: o repositório é público; senha no código é senha publicada.

Decisão: tudo vem de variáveis de ambiente; o .env fica fora do Git e o repositório traz só o modelo .env.example.

Alternativas: valores fixos no código; arquivo de configuração versionado.

Consequências: nenhum segredo no GitHub e o mesmo código roda em qualquer ambiente; em troca, é preciso lembrar de criar o .env.

Arquivos completos: ADR 0003 · ADR 0006

3 Teste a rota de saúde

4 Leia a app factory

Abra app/__init__.py. A função create_app() monta a aplicação: lê a configuração, liga o banco, registra o formato de erro e as rotas. Nos testes, criamos a mesma API com outra configuração (SQLite em memória) sem mudar uma linha do código.

api/app/__init__.py (trecho)
def create_app(config=None):
    app = Flask(__name__)
    app.config.from_object(Config)          # lê DATABASE_URL do ambiente
    if config:
        app.config.update(config)           # os testes trocam o banco aqui

    db.init_app(app)
    registrar_erros(app)

    @app.get("/saude")
    def saude():
        db.session.execute(db.text("SELECT 1"))
        return {"status": "ok", "banco": "ok"}

    with app.app_context():
        db.create_all()
    return app
✋ Errou? Casos comuns desta etapa
port is already allocated (porta 8000 ou 5432 ocupada)

Outro programa usa a porta (por exemplo, um PostgreSQL instalado na máquina). Mude a porta no .env (API_PORT=8001 ou DB_PORT=5433) e rode docker compose up -d de novo.

variable is not set. Defaulting to a blank string (POSTGRES_USER)

Você esqueceu de criar o .env, ou rodou o comando fora da pasta api. Rode cp .env.example .env (Windows: copy .env.example .env) na pasta api.

A api fica "unhealthy" ou reiniciando

Veja o motivo nos logs: docker compose logs api --tail 40. Se trocou a senha no .env depois da primeira subida, o banco antigo ainda usa a senha velha: zere com docker compose down -v e suba de novo.
