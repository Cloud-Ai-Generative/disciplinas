A função validar_doacao() confere todas as regras e devolve todos os erros de uma vez. Trecho da regra da quantidade:

api/app/validacao.py (trecho)
    # quantidade: obrigatória, número inteiro maior que zero
    quantidade = dados.get("quantidade")
    if quantidade is None:
        erros.append("quantidade é obrigatória")
    elif isinstance(quantidade, bool) or not isinstance(quantidade, int):
        erros.append("quantidade deve ser um número inteiro")
    elif quantidade <= 0:
        erros.append("quantidade deve ser maior que zero")
🕵️ Bug encontrado pelo Lucas: a primeira versão da validação tinha só if quantidade <= 0. O Lucas mandou "quantidade": "10" (texto): o Python quebrou ao comparar texto com número e a API devolveu 500. Depois mandou true, que passou como 1, porque em Python bool é um tipo de int. Por isso conferimos o tipo antes do valor.
⌨️ O código da aula: a rota POST

Esta é a rota escrita ao vivo. São poucas linhas, porque cada responsabilidade está no seu arquivo (ADR 0005).

api/app/routes.py (acrescentar)
@bp.post("")
def cadastrar():
    dados, erros = validar_doacao(request.get_json(silent=True))
    if erros:
        return jsonify({"erros": erros}), 400

    doacao = Doacao(**dados)
    db.session.add(doacao)
    db.session.commit()

    local = url_for("doacoes.consultar", doacao_id=doacao.id)
    return jsonify(doacao.to_dict()), 201, {"Location": local}
  • get_json(silent=True): se o corpo não for JSON, devolve None em vez de quebrar; a validação transforma isso em 400.
  • 201 + cabeçalho Location: o padrão REST para "criei, e ela está neste endereço".
  • Não esqueça os imports no topo: request e url_for do Flask, e validar_doacao de .validacao.

❓ O que é um ADR e como ler?

ADR 0004 · Validação escrita à mão, sem biblioteca aceita

Contexto: o desafio exige rejeitar doações inválidas com respostas adequadas.

Decisão: a função validar_doacao(), que devolve todos os erros de uma vez, em português.

Alternativas: Marshmallow ou Pydantic, maduras, mas escondem a lógica que a turma precisa entender agora.

Consequências: regras legíveis e fáceis de testar; em troca, mais código para manter quando a API crescer.

ADR 0007 · Formato único de erro em JSON e códigos de status aceita

Contexto: o aplicativo precisa saber se deu certo e, se não, mostrar o motivo.

Decisão: status pelo significado (201, 400, 404...) e todo erro no formato {"erros": ["..."]}.

Alternativas: Problem Details (RFC 9457), o padrão oficial e próximo passo natural; responder sempre 200 com um campo "sucesso", que esconde o erro do HTTP.

Consequências: o aplicativo trata qualquer erro do mesmo jeito; em troca, é um formato próprio.

Arquivos completos: ADR 0004 · ADR 0007
