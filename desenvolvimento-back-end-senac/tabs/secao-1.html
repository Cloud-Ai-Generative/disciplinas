👀 Como ler: a caixa destacada é o que a turma de Back-end constrói. O aplicativo não fala direto com o banco: ele pede à API, e a API decide o que é válido.

💡 Conceito: o que é uma API

⚙️ API (Application Programming Interface)

Uma API é um conjunto de regras para que um programa peça coisas a outro. Aqui, o aplicativo do Marcos pede: "guarde esta doação", "me mostre todas as doações", "apague esta". A API recebe o pedido, confere se faz sentido, conversa com o banco e responde.

O back-end é a parte do sistema que roda no servidor, longe dos olhos de quem usa. É ele que garante que nenhuma doação "sem tipo" ou com "quantidade -5" entre no banco, não importa qual aplicativo esteja do outro lado.

🍽️
Analogia: a API é o garçom de um restaurante. Você (o aplicativo) não entra na cozinha (o banco); faz o pedido ao garçom, que confere se o prato existe no cardápio, leva à cozinha e traz a resposta. Até onde vale: explica por que o cliente não acessa o banco direto. Onde engana: um garçom lembra de você entre um pedido e outro; uma API REST, não (cada pedido chega completo, como veremos na etapa 2).
