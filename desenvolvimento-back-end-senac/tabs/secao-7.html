RotaComportamento esperado
PUT /doacoes/{id}Recebe a doação completa (todos os campos, como no cadastro) e substitui a existente. Responde 200 com a doação atualizada; 400 se os dados forem inválidos (sem alterar nada); 404 se a doação não existir.
DELETE /doacoes/{id}Exclui a doação. Responde 204 sem corpo; 404 se a doação não existir.

@bp.put("/<int:doacao_id>")
def atualizar(doacao_id):
    doacao = db.get_or_404(Doacao, doacao_id, description=NAO_ENCONTRADA)

    dados, erros = validar_doacao(request.get_json(silent=True))
    if erros:
        return jsonify({"erros": erros}), 400

    for campo, valor in dados.items():
        setattr(doacao, campo, valor)
    db.session.commit()
    return jsonify(doacao.to_dict())


@bp.delete("/<int:doacao_id>")
def excluir(doacao_id):
    doacao = db.get_or_404(Doacao, doacao_id, description=NAO_ENCONTRADA)
    db.session.delete(doacao)
    db.session.commit()
    return "", 204

Sobre a pergunta "404 ou 400?": o gabarito busca a doação antes de validar, então responde 404. Faz sentido: não adianta corrigir os dados de algo que não existe. As duas escolhas são defensáveis, desde que a decisão seja consistente e documentada.
