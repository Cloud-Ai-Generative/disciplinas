💻 Instalação
SintomaCausaSolução
'git' não é reconhecido como um comando (ou code, docker)O terminal foi aberto antes da instalaçãoFeche e abra o terminal (ou o VS Code) de novo. Se persistir, reinicie o computador
Docker Desktop: "Virtualization support not detected" ou "WSL 2 installation is incomplete"Virtualização desligada na BIOS/UEFI, ou WSL não instaladoRode wsl --install no PowerShell como administrador e reinicie. Se ainda falhar, ligue a virtualização na BIOS (procure "Intel VT-x", "SVM" ou "Virtualization Technology"); a tecla para entrar na BIOS varia por fabricante (F2, F10, Del). Sem acesso à BIOS: use o Codespaces
wsl --install mostra só a ajudaWSL já instalado, sem distribuiçãowsl --install -d Ubuntu, depois wsl --update
permission denied while trying to connect to the Docker daemon socket (Linux)Seu usuário não está no grupo dockersudo usermod -aG docker $USER, saia da sessão e entre de novo
macOS: "Docker.app is damaged" ou não abreVersão do chip errada (Intel × Apple Silicon)Apague e baixe a versão certa (Menu → Sobre Este Mac mostra o chip)
A extensão REST Client não mostra "Send Request"Arquivo sem a extensão .http, ou extensão não instaladaConfira o nome requests.http e se humao.rest-client aparece em code --list-extensions
🐳 Docker e Docker Compose
SintomaCausaSolução
Cannot connect to the Docker daemonDocker instalado, mas paradoAbra o Docker Desktop (Windows e macOS) ou sudo systemctl start docker (Linux)
Bind for 0.0.0.0:8000 failed: port is already allocated (ou 5432)Outro programa usa a porta; com 5432, quase sempre um PostgreSQL instalado na máquinaNo .env, troque API_PORT=8001 ou DB_PORT=5433 e rode docker compose up -d. Para descobrir quem usa a porta: netstat -ano | findstr :8000 (Windows), lsof -i :8000 (macOS), sudo ss -ltnp | grep :8000 (Linux)
The "POSTGRES_USER" variable is not setFalta o .env, ou o comando foi rodado fora da pasta apicp .env.example .env (Windows: copy .env.example .env) dentro da pasta api
no configuration file provided: not foundVocê não está na pasta apicd desenvolvimento-back-end-senac/api
Mudei o requirements.txt ou o Dockerfile e nada mudouA imagem não foi refeitadocker compose up -d --build
Quero o banco zerado, com os exemplos de novoO volume guarda os dados entre execuçõesdocker compose down -v e depois docker compose up -d
Windows: exec format error ou \r: command not foundArquivos com quebra de linha do Windows (CRLF)O projeto já força LF pelo .gitattributes. Se editou fora dele: git config --global core.autocrlf input, apague a pasta e clone de novo
🐘 API e banco de dados
SintomaCausaSolução
password authentication failed for user "vila"A senha do .env mudou depois que o banco foi criado; o volume guarda a senha antigadocker compose down -v e docker compose up -d (apaga os dados)
RuntimeError: DATABASE_URL não definidaA API rodou fora do Compose, sem a variávelRode pelo Compose: docker compose up -d
404 em /doacoesVocê está na tag da etapa 3, que ainda não tem as rotas de doaçõesgit checkout backend-senac-etapa-4 (ou mais recente) e docker compose up -d --build
flask: No such command 'seed'A imagem é de uma etapa mais nova que o códigodocker compose up -d --build
Senha com @, : ou / quebra a conexãoEsses caracteres têm significado no endereço do bancoUse só letras, números e hífen na senha do .env
🔀 Git e tags
SintomaCausaSolução
error: pathspec 'backend-senac-etapa-5' did not matchAs tags não foram baixadasgit fetch --tags
Your local changes would be overwritten by checkoutVocê alterou arquivos da etapa atualGuarde as mudanças: git stash (para recuperar depois: git stash pop), ou crie um branch e faça commit
"You are in 'detached HEAD' state"Normal ao fazer checkout de uma tagSó um aviso. Para trabalhar em cima: git switch -c meu-branch. Para voltar: git checkout main
fatal: detected dubious ownership in repository (Linux)Você está como root (prompt terminando em #), mas a pasta é do seu usuárioSaia do root com exit e rode o comando como o seu usuário. Não use o safe.directory sugerido: os arquivos criados ficariam com dono root. Se entrou como root por causa do Docker, use sudo usermod -aG docker $USER e entre de novo na sessão
Support for password authentication was removed ou Authentication failed no git pushO GitHub não aceita a senha da conta no terminalRode o git push pelo terminal do VS Code (Ctrl+J): ele abre o navegador para o login (passo B2)
