A Conferir os requisitos ⏱️ 5 min

Para que serve: o Docker cria pequenas máquinas isoladas (contêineres) e precisa de memória e de virtualização ligada no computador.

ItemMínimoRecomendado
Memória RAM4 GB8 GB ou mais
Espaço livre em disco10 GB20 GB
SistemaWindows 10 ou 11 (64 bits), macOS recente ou Ubuntu 22.04 ou mais novo
PermissãoDe administrador, para instalar programas
Windows

Confira se a virtualização está ligada: abra o Gerenciador de Tarefas (Ctrl+Shift+Esc) → aba Desempenho → CPU. Procure "Virtualização: Habilitado".

Para ver a memória: na mesma aba, clique em Memória.

macOS

Menu → Sobre Este Mac. Anote o chip (Apple M1, M2, M3... ou Intel): você vai precisar dele no passo E. A virtualização já vem ligada.

Linux
terminal: memória, disco e virtualização
free -h
df -h ~
grep -Ec '(vmx|svm)' /proc/cpuinfo

O último comando deve mostrar um número maior que zero.

✅ Deu certo se: você tem pelo menos 4 GB de RAM, 10 GB livres e a virtualização habilitada.
Virtualização desabilitada? Ela é ligada na BIOS/UEFI do computador. Veja Problemas comuns. Se não puder mexer na BIOS, use o Codespaces.

B Instalar e configurar o Git ⏱️ 10 min

Para que serve: o Git guarda o histórico do código e baixa o projeto do GitHub para a sua máquina.

Windows

Abra o PowerShell (menu Iniciar → digite "PowerShell") e rode:

PowerShell
winget install --id Git.Git -e --source winget

Sem o winget? Baixe o instalador em git-scm.com e clique em "Next" mantendo as opções padrão.

Feche e abra o PowerShell de novo para ele reconhecer o Git.

macOS

Abra o Terminal (⌘+Espaço → digite "Terminal") e rode o comando abaixo. Se aparecer uma janela pedindo para instalar as "ferramentas de linha de comando", aceite.

Terminal
git --version
Linux (Ubuntu)
terminal
sudo apt update
sudo apt install -y git

Configure o seu nome e e-mail (aparecem em cada commit; use o e-mail da sua conta do GitHub):

terminal (qualquer sistema)
git config --global user.name "Seu Nome"
git config --global user.email "seu-email@exemplo.com"
✅ Deu certo se: git --version mostra algo como git version 2.47.1.
Ainda não tem conta no GitHub? Sem problema: o próximo passo, B2, explica tudo. Por enquanto, use no git config o e-mail que você vai usar no GitHub.

B2 Conta no GitHub ⏱️ 10 min

Para que serve: o GitHub guarda o projeto na internet. Você precisa de conta para usar o Codespaces e para entregar o desafio pelo GitHub.

📷
Git e GitHub não são a mesma coisa. O Git é a câmera: tira "fotos" (commits) do seu projeto, na sua máquina. O GitHub é o álbum on-line: um site onde essas fotos ficam guardadas e podem ser compartilhadas. O Git funciona sem o GitHub; o GitHub usa o Git.
ParaPrecisa de conta no GitHub?
Baixar o projeto (git clone) e navegar pelas etapas da aula❌ Não: o repositório é público
Usar o Codespaces (passo H)✅ Sim
Entregar o desafio pelo GitHub (opcional, Seção 7)✅ Sim

1. Crie a conta

  1. Acesse github.com/signup e informe e-mail, senha e um nome de usuário. O nome de usuário aparece no endereço dos seus projetos (github.com/seu-usuario): prefira algo profissional.
  2. Confirme o e-mail com o código que o GitHub enviar.
  3. Ative a verificação em duas etapas quando o GitHub pedir (menu da sua foto → Settings → Password and authentication). Um aplicativo autenticador no celular resolve.
  4. É estudante? Peça o GitHub Student Developer Pack: é gratuito e dá acesso a ferramentas pagas.

2. Ligue o Git à sua conta

Use no Git o mesmo e-mail da conta do GitHub, para os seus commits aparecerem no seu perfil:

terminal (qualquer sistema)
git config --global user.email "o-email-da-sua-conta@exemplo.com"
git config --global user.email

A segunda linha mostra o e-mail configurado, para você conferir.

3. Login: deixe o VS Code cuidar disso

Você não precisa criar senha nem token à mão. Na primeira vez que enviar algo para o GitHub (git push) pelo terminal do VS Code, ele abre o navegador para você autorizar. Depois disso, fica tudo conectado.

⚠️ Atenção: o GitHub não aceita a senha da conta no terminal. Se um terminal comum pedir "Password", use o terminal do VS Code (Ctrl+J), que faz o login pelo navegador.
✅ Deu certo se: você entra em github.com/seu-usuario e vê o seu perfil, e git config --global user.email mostra o e-mail da conta.

C Instalar o VS Code ⏱️ 10 min

Para que serve: é o editor onde você vai ler e escrever o código, rodar o terminal e enviar requisições para a API.

Windows
PowerShell
winget install --id Microsoft.VisualStudioCode -e --source winget

Ou baixe em code.visualstudio.com. No instalador, marque "Adicionar ao PATH" e "Abrir com Code".

macOS
  1. Baixe em code.visualstudio.com e arraste o VS Code para a pasta Aplicativos.
  2. Abra o VS Code, aperte ⌘+Shift+P, digite shell command e escolha "Install 'code' command in PATH". Isso permite abrir pastas pelo terminal com code .
Linux (Ubuntu)
terminal
sudo snap install code --classic

Sem snap? Baixe o pacote .deb em code.visualstudio.com e instale com sudo apt install ./arquivo.deb.

✅ Deu certo se: num terminal novo, code --version mostra o número da versão.

✅ Deu certo se: code --list-extensions mostra as cinco extensões. Reinicie o VS Code para o idioma mudar.

E Instalar o Docker ⏱️ 20 a 30 min

Para que serve: o Docker roda a API e o banco de dados em contêineres, iguais em todas as máquinas da turma. O Docker Compose já vem junto.

Windows

1. Instale o WSL 2 (o Linux dentro do Windows, que o Docker usa por baixo). Abra o PowerShell como administrador (botão direito → "Executar como administrador"):

PowerShell (administrador)
wsl --install

Reinicie o computador quando terminar. Se abrir uma janela do Ubuntu pedindo usuário e senha, crie (é só para o Linux interno).

2. Instale o Docker Desktop:

PowerShell
winget install --id Docker.DockerDesktop -e --source winget

Ou baixe em docs.docker.com. No instalador, mantenha a instalação por usuário (o padrão recomendado, que não exige administrador para instalar nem atualizar) e o backend WSL 2.

💡 WSL 2 é o recomendado: é o padrão do Docker Desktop e funciona também no Windows Home. Se o instalador pedir para ativar o WSL 2, aceite: ligar o WSL pela primeira vez pode pedir senha de administrador. Sem acesso de administrador? Use o Codespaces.

3. Abra o Docker Desktop, aceite os termos e espere a baleia 🐳 na barra de tarefas ficar parada ("Engine running").

macOS
  1. Baixe o Docker Desktop em docs.docker.com, escolhendo a versão do seu chip (anotado no passo A): Apple Silicon (M1, M2, M3...) ou Intel.
  2. Abra o arquivo .dmg e arraste o Docker para Aplicativos.
  3. Abra o Docker, aceite os termos e espere a baleia 🐳 na barra de menus ficar parada.
Linux (Ubuntu)

No Linux usamos o Docker Engine, direto, sem o Desktop. O script oficial instala tudo, inclusive o Compose:

terminal
curl -fsSL https://get.docker.com -o get-docker.sh
sudo sh get-docker.sh
sudo usermod -aG docker $USER

O último comando deixa você usar o Docker sem sudo. Saia da sessão e entre de novo (ou reinicie) para valer.

✅ Deu certo se: docker --version e docker compose version mostram as versões.
💡 Licença: o Docker Desktop é gratuito para estudo, uso pessoal e pequenas empresas. No Linux, o Docker Engine é software livre. Em computadores de laboratório da instituição, confirme com a TI antes de instalar.

F Verificar tudo ⏱️ 5 min

Para que serve: confirmar, num lugar só, que as quatro ferramentas estão funcionando antes de baixar o projeto.

terminal (abra um NOVO)
git --version
code --version
docker --version
docker compose version
docker run --rm hello-world
saída esperada (os números das versões variam)
git version 2.47.1 1.95.3 Docker version 28.0.1, build 068a01e Docker Compose version v2.33.1 Hello from Docker! This message shows that your installation appears to be working correctly.
✅ Deu certo se: nenhum comando respondeu "não reconhecido" ou "command not found", e apareceu Hello from Docker!
✋ Errou? Cannot connect to the Docker daemon: o Docker está instalado, mas parado. Abra o Docker Desktop (Windows e macOS) ou rode sudo systemctl start docker (Linux). Outros casos em Problemas comuns.

G Subir o projeto pela primeira vez ⏱️ 10 min

Para que serve: baixar a API de doações e ver tudo funcionando antes da aula.

1. Baixe o projeto e entre na pasta da API. O git clone copia o repositório inteiro do GitHub para a sua máquina, com todo o histórico; não precisa de login. ❓ Entenda os comandos do Git

terminal
git clone https://github.com/Cloud-Ai-Generative/disciplinas.git
cd disciplinas/desenvolvimento-back-end-senac/api

2. Crie o seu arquivo de configuração a partir do modelo (ADR 0006):

PowerShell
copy .env.example .env
terminal
cp .env.example .env

3. Suba o banco e a API:

terminal, na pasta api
docker compose up -d --build
docker compose ps
✅ Resultado esperado: dois contêineres, vila-esperanca-db-1 e vila-esperanca-api-1, com (healthy) no status. Na primeira vez demora alguns minutos: o Docker baixa as imagens do Python e do PostgreSQL.

4. Teste no navegador: abra http://localhost:8000/doacoes.

✅ Resultado esperado: uma lista em JSON com 5 doações de exemplo, começando por "Pacote de arroz 5 kg".

5. Abra o projeto no VS Code e teste o REST Client:

terminal, na pasta api
code .

Abra o arquivo requests.http e clique em Send Request, que aparece em cima de GET {{base}}/saude.

✅ Resultado esperado: abre um painel com HTTP/1.1 200 OK e {"status": "ok", "banco": "ok"}.

6. Para desligar quando terminar (os dados ficam guardados):

terminal, na pasta api
docker compose down

H Plano B: GitHub Codespaces ⏱️ 10 min opcional

Para que serve: se o seu computador não roda Docker (pouca memória, sem virtualização, sem permissão de administrador), o Codespaces abre o projeto inteiro no navegador, num computador do GitHub, com Docker e as extensões já instalados.

  1. Entre na sua conta do GitHub e abra github.com/Cloud-Ai-Generative/disciplinas.
  2. Clique no botão verde Code → aba Codespaces → ... → New with options.
  3. Em Dev container configuration, escolha "Desenvolvimento Back-end Senac: API Vila Esperança" e clique em Create codespace.
  4. Espere abrir o VS Code no navegador (alguns minutos na primeira vez). O terminal já abre na pasta da API, com o .env criado.
  5. No terminal, rode:
    terminal do Codespaces
    docker compose up -d --build
  6. Quando aparecer o aviso da porta 8000, clique em Abrir no navegador e acrescente /doacoes no endereço.
✅ Resultado esperado: as mesmas 5 doações de exemplo do passo G.
💡 Cota gratuita: contas pessoais do GitHub têm horas gratuitas de Codespaces por mês. Ao terminar, pare o codespace (menu Codespaces → Stop current codespace) para não gastar a cota à toa.
🎉 Tudo pronto! Com a API respondendo em /doacoes, seu ambiente está pronto para a aula. Comece pela aba 1 · O problema.
