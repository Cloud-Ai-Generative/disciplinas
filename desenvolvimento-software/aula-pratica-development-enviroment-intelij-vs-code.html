💡 Conceito em 60 Segundos: O Fim do "Na Minha Máquina Funciona"

O maior desperdício de tempo no onboarding de engenharia ocorre quando cada desenvolvedor usa uma versão ligeiramente diferente do compilador, do SDK ou do banco de dados local. Um bug misterioso em produção frequentemente se resume a um desenvolvedor compilando com Java 17 enquanto o pipeline de produção executa Java 21 LTS.

Garantir a Paridade de Ambiente (Environment Parity) significa tratar a configuração da máquina de desenvolvimento como código versionável: usando Version Pinning (arquivos .sdkmanrc e global.json), Gerenciadores de Pacotes Idempotentes (Winget no Windows, APT no Linux) e Dev Containers (Docker).

🍳
Analogia da Cozinha Industrial: Se numa confeitaria de franquia cada cozinheiro usar uma xícara de tamanho diferente ou uma balança descalibrada, o bolo de cada filial sairá com sabor e textura diferentes. Todos os chefs devem usar a mesma fita métrica e a mesma receita trancada!

💡 Conceito em 60 Segundos: IntelliJ IDEA & Gerenciamento de JDKs

O ecossistema Java moderno possui múltiplas distribuições do OpenJDK (Eclipse Temurin, Amazon Corretto, GraalVM, Azul Zulu). A equipe nunca deve baixar instaladores soltos manualmente de sites variados.

No Linux/WSL, a ferramenta padrão da indústria é o SDKMAN!, que lê o arquivo .sdkmanrc na raiz do projeto e troca a versão do Java automaticamente. No Windows, o próprio instalador de JDK do IntelliJ (Project Structure → SDKs → Download JDK) ou o Winget garantem a versão exata sem poluir o PATH do sistema.

💡 Conceito em 60 Segundos: VS Code & .NET 10 (LTS)

O .NET 10 é a versão com suporte de longo prazo (LTS), oferecendo máxima estabilidade, compilador C# 14 otimizado e recursos nativos de conteinerização.

Para garantir que todo o time use o .NET 10 sem surpresas, a Microsoft recomenda o uso do arquivo global.json. Ele trava a versão exata do SDK (ex: 10.0.100) usada pelo comando dotnet build em qualquer máquina da equipe.

💡 Conceito em 60 Segundos: O Pipeline do Zero ao CRUD Funcional

Ter o ambiente configurado só faz sentido quando a equipe consegue rodar a aplicação completa sem dores de cabeça. Nosso fluxo padrão consiste em:

  1. Infraestrutura Local: Subir o MySQL via docker compose up -d com volume persistente e porta 3306.
  2. Migração do Banco: Criar a tabela produtos automaticamente.
  3. Execução da API: Iniciar a aplicação (em Java Spring Boot ou C# .NET 10 Web API).
  4. Consumo HTTP: Disparar requisições REST de CRUD (POST, GET, PUT, DELETE) e verificar a persistência.
