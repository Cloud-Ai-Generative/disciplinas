💡 Conceito em 60 Segundos: O Fim do "Na Minha Máquina Funciona"

O maior desperdício de tempo no onboarding de engenharia ocorre quando cada desenvolvedor usa uma versão ligeiramente diferente do compilador, do SDK ou do banco de dados local. Um bug misterioso em produção frequentemente se resume a um desenvolvedor compilando com Java 17 enquanto o pipeline de produção executa Java 21 LTS.

Garantir a Paridade de Ambiente (Environment Parity) significa tratar a configuração da máquina de desenvolvimento como código versionável: usando Version Pinning (arquivos .sdkmanrc e global.json), Gerenciadores de Pacotes Idempotentes (Winget no Windows, APT no Linux) e Dev Containers (Docker).

🍳
Analogia da Cozinha Industrial: Se numa confeitaria de franquia cada cozinheiro usar uma xícara de tamanho diferente ou uma balança descalibrada, o bolo de cada filial sairá com sabor e textura diferentes. Todos os chefs devem usar a mesma fita métrica e a mesma receita trancada!

💡 Conceito em 60 Segundos: IntelliJ IDEA & Java Moderno (19+) com Spring Boot

O Spring Boot 3.x exige obrigatoriamente no mínimo o Java 17, funcionando com excelência a partir do Java 19, 21 LTS e 25 LTS. A partir do Java 19/21, recursos como Virtual Threads (Project Loom) e Record Patterns revolucionaram a performance de APIs de alto tráfego.

Para garantir que todos usem o mesmo JDK, a equipe deve padronizar a distribuição (ex: Eclipse Temurin da Adoptium) e utilizar o arquivo .sdkmanrc para travar a versão no Linux/WSL, enquanto no Windows o IntelliJ gerencia o SDK via Project Structure.

☕ Laboratório: Seletor de Versão JDK (>= 19) & Configuração no IntelliJ

🌱 Spring Initializr ↗ 🛠️ Download IntelliJ IDEA ↗
🎯 Escolha a Versão do JDK (>= 19):
Arquivo de Trava de Versão da Equipe (.sdkmanrc na raiz):
# .sdkmanrc (Version Pinning)
java=21.0.4-tem

📋 Passo a Passo para Iniciar Projeto no IntelliJ com Spring Boot:

  1. Criar o Projeto: Acesse File → New → Project → Spring Initializr (ou gere via start.spring.io).
  2. Configurar Metadados: Escolha Language: Java, Type: Maven, e na opção JDK escolha a versão selecionada acima.
  3. Dependências Mandatórias: Adicione:
    • Spring Web (para expor endpoints REST)
    • Spring Data JPA (para persistência relacional)
    • MySQL Driver (conector JDBC do banco)
    • Lombok (para reduzir código boilerplate)
  4. Configurar SDK no IntelliJ: Acesse File → Project Structure → Project e confirme que o Project SDK e o Language Level estão apontando para o JDK escolhido.

💡 Conceito em 60 Segundos: VS Code & C# Moderno com .NET 10 (LTS)

O .NET 10 traz o suporte de longo prazo (LTS), suporte pleno a C# 14, Minimal APIs de alta velocidade e Native AOT.

Para que ninguém na equipe compile com versões desatualizadas, utilizamos o arquivo global.json. Ele define qual SDK exato o comando dotnet build ou o VS Code deve usar ao abrir a solução.

🔷 Laboratório: Seletor de SDK do .NET & Extensões do VS Code

🌐 Download .NET 10 SDK ↗ 🛠️ Download VS Code ↗
🎯 Escolha a Versão do .NET SDK da Equipe:
Arquivo de Trava de Versão da Equipe (global.json):
{
  "sdk": {
    "version": "10.0.100",
    "rollForward": "latestFeature"
  }
}

📋 Passo a Passo para Criar e Configurar Projeto no VS Code:

  1. Criar a Solução e Projeto Web API via Terminal: 
    dotnet new webapi -n LojaApi -controllers
cd LojaApi
dotnet new globaljson --sdk-version 10.0.100 --roll-forward latestFeature
  2. Instalar Pacotes NuGet para Conectar no MySQL: 
    dotnet add package Pomelo.EntityFrameworkCore.MySql
dotnet add package Microsoft.EntityFrameworkCore.Design
  3. Abrir no VS Code: Execute code .. O VS Code detectará o projeto e gerará a pasta .vscode/ com tarefas de compilação e depuração.
🔌 Extensões Mandatórias via `.vscode/extensions.json`:
🔷 C# Dev Kit

Gerenciador de soluções (.sln), testes integrados e IntelliCode oficial da Microsoft.
🔍 C# Base Extension

Suporte do Roslyn para realce de sintaxe, navegação por referências e refatoração.
⚡ Thunder Client / REST Client
rangav.vscode-thunder-client
Permite disparar chamadas HTTP CRUD diretamente de dentro do VS Code sem precisar de Postman.
🐳 Docker Extension
ms-azuretools.vscode-docker
Visualizador de containers, volumes e imagens do Docker com atalhos de depuração.

💡 Conceito em 60 Segundos: O Exemplo Prático Completo do Zero

Abaixo está o código real, reproduzível e completo para rodar a aplicação nos dois ecossistemas (IntelliJ + Spring Boot e VS Code + .NET 10), conectando em um banco de dados **MySQL 8.4** provisionado via Docker.

🐬 Etapa 1: Provisionamento do MySQL com Docker Compose

Crie um arquivo chamado docker-compose.yml na pasta raiz da solução: 

services:
  mysql-db:
    image: mysql:8.4
    container_name: mysql_dev_server
    environment:
      MYSQL_ROOT_PASSWORD: root123
      MYSQL_DATABASE: loja_db
    ports:
      - "3306:3306"
    volumes:
      - mysql_dev_data:/var/lib/mysql

volumes:
  mysql_dev_data:
    driver: local
