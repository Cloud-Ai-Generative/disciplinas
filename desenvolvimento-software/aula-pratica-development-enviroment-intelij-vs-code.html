💡 Conceito em 60 Segundos: O Fim do "Na Minha Máquina Funciona"

O maior desperdício de tempo no onboarding de engenharia ocorre quando cada desenvolvedor usa uma versão ligeiramente diferente do compilador, do SDK ou do banco de dados local. Um bug misterioso em produção frequentemente se resume a um desenvolvedor compilando com Java 17 enquanto o pipeline de produção executa Java 21 LTS.

Garantir a Paridade de Ambiente (Environment Parity) significa tratar a configuração da máquina de desenvolvimento como código versionável: usando Version Pinning (arquivos .sdkmanrc e global.json), Gerenciadores de Pacotes Idempotentes (Winget no Windows, APT no Linux) e Dev Containers (Docker).

🍳
Analogia da Cozinha Industrial: Se numa confeitaria de franquia cada cozinheiro usar uma xícara de tamanho diferente ou uma balança descalibrada, o bolo de cada filial sairá com sabor e textura diferentes. Todos os chefs devem usar a mesma fita métrica e a mesma receita trancada!

💡 Conceito em 60 Segundos: IntelliJ IDEA, Java 19+ e o Ecossistema JPA/Hibernate

O Spring Boot 3.x exige no mínimo o Java 17, operando com suporte nativo a partir do Java 19, 21 LTS e 25 LTS. A partir do Java 19 e 21, as Virtual Threads (Project Loom) permitem que requisições HTTP escalem sem sobrecarregar threads do sistema operacional.

O Hibernate ORM atua sob a especificação JPA (Jakarta Persistence): ele intercepta as classes de modelo anotadas com @Entity e gerencia conexões, geração de DDL e execução SQL no banco relacional.

☕ Guia Visual do Menu: Como Instalar Plugins e JDK no IntelliJ IDEA

🌱 Spring Initializr ↗ 🛠️ SDKMAN! Oficial ↗

🧭 Navegação Passo a Passo nos Menus do IntelliJ IDEA:

1. Como Instalar Plugins via Menu:

Menu Superior → File → Settings (ou Ctrl+Alt+S / Preferences no macOS) → Plugins

Clique na aba Marketplace no topo da janela. Digite o nome do plugin (ex: Lombok, SonarLint, JPA Buddy), clique no botão verde Install e em seguida clique em Restart IDE.

2. Como Ativar o Processamento de Anotações do Lombok:

Settings → Build, Execution, Deployment → Compiler → Annotation Processors

Marque a caixa de seleção ☑ Enable annotation processing e clique em Apply. Sem isso, o compilador não reconhece os getters/setters gerados em tempo de compilação.

3. Como Baixar e Escolher a Versão do JDK (>= 19) no IntelliJ:

File → Project Structure (ou Ctrl+Alt+Shift+S) → Project Settings → Project

No campo SDK, clique na caixa de seleção → selecione Add SDK → Download JDK.... Escolha Version: 21 (ou 19 / 25) e Vendor: Eclipse Temurin (Adoptium). Clique em Download. Em seguida, ajuste o Language Level para a mesma versão.

🎯 Seletor de Versão do JDK do Projeto:

💡 Conceito em 60 Segundos: Subindo MySQL, MongoDB e Cargas Iniciais (DDL/DML)

Para que a aplicação seja capaz de conectar e ter dados de teste prontos no primeiro boot, montamos scripts na pasta interna /docker-entrypoint-initdb.d/ dos contêineres:

  • MySQL: Executa automaticamente scripts .sql de DDL (Data Definition Language) criando tabelas e de DML (Data Manipulation Language) inserindo registros de semente (seed).
  • MongoDB: Executa automaticamente scripts .js inicializando coleções e documentos JSON/BSON.

🐳 Comandos Essenciais do Docker Compose (Explicados Detalhadamente)

docker compose up -d
Baixa as imagens caso não existam, cria os volumes de disco, monta as redes virtuais e inicia os containers em segundo plano (background), liberando o terminal.
docker compose ps
Lista o status de saúde de todos os serviços declarados, mostrando quais portas estão mapeadas (ex: 3306 e 27017) e se o processo está "Up" ou "Exited".
docker compose stop
Interrompe a execução dos contêineres sem remover as redes nem os dados. Ideal quando você precisa liberar memória RAM temporariamente no computador.
docker compose down -v
Derruba os contêineres, remove as redes e a flag -v deleta os volumes de disco. Use quando quiser resetar todo o banco de dados do zero!
Arquivo docker-compose.yml na raiz com inicialização DDL/DML automática: 
services:
  # -------------------------------------------------------------------
  # 1. BANCO RELACIONAL: MySQL 8.4
  # -------------------------------------------------------------------
  mysql-db:
    image: mysql:8.4
    container_name: dev_mysql_server
    restart: unless-stopped
    environment:
      MYSQL_ROOT_PASSWORD: root123    # Senha de superusuário administrativo
      MYSQL_DATABASE: loja_db         # Nome do database relacional criado no boot
      MYSQL_USER: devuser             # Usuário de conexão da aplicação
      MYSQL_PASSWORD: devpass         # Senha do usuário de desenvolvimento
    ports:
      - "3306:3306"                   # Mapeia porta do seu computador para o container
    volumes:
      - mysql_dev_data:/var/lib/mysql # Persistência de arquivos de dados
      - ./init-sql:/docker-entrypoint-initdb.d # Executa automaticamente scripts DDL/DML (.sql)!
    networks:
      - dev_network

  # -------------------------------------------------------------------
  # 2. BANCO NOSQL: MongoDB 7.0 (Preparado para a Migração)
  # -------------------------------------------------------------------
  mongo-db:
    image: mongo:7.0
    container_name: dev_mongo_server
    restart: unless-stopped
    environment:
      MONGO_INITDB_ROOT_USERNAME: root
      MONGO_INITDB_ROOT_PASSWORD: root123
      MONGO_INITDB_DATABASE: loja_nosql
    ports:
      - "27017:27017"                 # Porta padrão do protocolo MongoDB
    volumes:
      - mongo_dev_data:/data/db       # Persistência de documentos BSON
      - ./init-mongo:/docker-entrypoint-initdb.d # Executa automaticamente scripts Mongo (.js)!
    networks:
      - dev_network

volumes:
  mysql_dev_data:
    driver: local
  mongo_dev_data:
    driver: local

networks:
  dev_network:
    driver: bridge

🔌 Como Conectar nas Bases & Scripts de Carga Inicial (DDL e DML)

🐬 MySQL: Conexão & Script DDL/DML

Como Conectar via Terminal:
docker exec -it dev_mysql_server mysql -u root -proot123 loja_db
Ou configure no DBeaver / IntelliJ: Host=localhost, Porta=3306, User=root, Pass=root123.

Arquivo init-sql/01-init.sql (Executado no primeiro boot): 
-- DDL: Criação da estrutura relacional da tabela
CREATE TABLE IF NOT EXISTS produtos (
    id BIGINT AUTO_INCREMENT PRIMARY KEY,
    nome VARCHAR(100) NOT NULL,
    preco DECIMAL(10,2) NOT NULL,
    estoque INT NOT NULL
);

-- DML: Carga inicial de sementes (Seed Data)
INSERT INTO produtos (nome, preco, estoque) VALUES
('Teclado Mecanico RGB', 349.90, 15),
('Mouse Gamer 16000 DPI', 189.50, 20),
('Headset 7.1 Surround', 420.00, 10);

🍃 MongoDB: Conexão & Script de Inicialização

Como Conectar via Terminal:
docker exec -it dev_mongo_server mongosh -u root -p root123
Ou conecte via MongoDB Compass: mongodb://root:root123@localhost:27017/?authSource=admin.

⚡ Como Testar a Aplicação (Swagger UI, Thunder Client e cURL)

Método 1: Teste Interativo Visual pelo Swagger / OpenAPI

Inicie sua API e abra o navegador no endereço oficial gerado automaticamente:
• Java Spring Boot: Acesse http://localhost:8080/swagger-ui/index.html
• C# .NET 10: Acesse http://localhost:8080/swagger ou http://localhost:8080/openapi/v1.json
Você verá todos os endpoints (GET, POST, PUT, DELETE) com botão "Try it out" para enviar dados e inspecionar os códigos de status HTTP (200, 201, 204, 404).

Método 2: Comandos cURL Explicados

# POST: Insere registro enviando cabeçalho JSON (-H) e payload (-d)
curl -X POST http://localhost:8080/api/produtos -H "Content-Type: application/json" -d '{"nome":"Monitor Gamer","preco":1499.00,"estoque":7}'

# GET: Retorna a lista de todos os registros persistidos
curl -X GET http://localhost:8080/api/produtos

# PUT: Atualiza o registro com ID 1 enviando os novos dados no corpo
curl -X PUT http://localhost:8080/api/produtos/1 -H "Content-Type: application/json" -d '{"nome":"Monitor 240Hz","preco":1699.00,"estoque":5}'

# DELETE: Remove o item do banco de dados físico
curl -X DELETE http://localhost:8080/api/produtos/1
