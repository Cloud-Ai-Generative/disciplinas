🌐 Fundamentos de Engenharia & Paridade Operacional

Antes de escrever código, garantimos paridade ambiental estrita: instalação declarativa e idempotente das ferramentas, eliminando o "na minha máquina funciona".

🛡️ O 10º Fator do Twelve-Factor App: Dev/Prod Parity

O 10º fator estabelece que o ambiente de desenvolvimento deve ser o mais parecido possível com o de produção. Divergências sutis (versão do JDK, libc, kernel) causam bugs silenciosos que só aparecem em produção.

🎯 Os 3 Pilares da Paridade

  1. Gerenciadores Declarativos: winget (Windows), apt (Linux), brew (macOS) — scripts auditáveis commitados no Git.
  2. Isolamento com WSL2: contêineres Docker sobre kernel Linux real (não emulado), com I/O e syscalls idênticos à produção.
  3. Trava de Versão via Git: .sdkmanrc (Java) e global.json (.NET) forçam a mesma versão de compiladores para todo o time.
🍳
Analogia da Cozinha Industrial: se cada chef usar balanças descalibradas e fogões diferentes, o prato nunca sai igual. Toda a rede usa a mesma fita métrica, os mesmos termômetros e a mesma bancada padronizada!

package com.example.hello.controller;

import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.RestController;

import java.time.Instant;
import java.util.Map;

/**
 * Controller REST de demonstração (smoke test do ambiente).
 *
 * <p>{@code @RestController} = {@code @Controller} + {@code @ResponseBody}:
 * todo retorno é serializado como JSON automaticamente.</p>
 *
 * @since 1.0.0
 */
@RestController
public class HelloController {

    /**
     * GET /hello — responde um JSON com mensagem, thread e horário.
     *
     * <p>A chave {@code thread} prova que o Tomcat atendeu a requisição
     * (e mostra o nome da thread que processou).</p>
     *
     * @return mapa serializado como JSON pelo Spring
     */
    @GetMapping("/hello")
    public Map<String, Object> hello() {
        return Map.of(
            "mensagem", "Hello World com Spring Boot + Java 21!",
            "thread", Thread.currentThread().toString(),
            "horarioUtc", Instant.now().toString()
        );
    }

    /**
     * GET / — healthcheck simples com roteiro de testes.
     *
     * @return mapa JSON com status e próximo endpoint a testar
     */
    @GetMapping("/")
    public Map<String, String> raiz() {
        return Map.of(
            "status", "API Spring Boot no ar",
            "roteiro", "GET /hello"
        );
    }
}

git add .

git pull origin main

# GitHub: após o push, o site mostra o botão "Compare & pull request"

# GitLab: após o push, o site mostra o botão "Create merge request"

git stash

git stash pop

# Desfaz o ÚLTIMO commit mantendo as mudanças na área de trabalho
git reset --soft HEAD~1

🎯 Por que usar SDKMAN? (o sentido disso)

Problema: um dev tem Java 17, outro 21, o CI usa 25 — builds quebram "do nada". Instalar JDK à mão = ZIP + editar PATH/JAVA_HOME por versão.

SDKMAN resolve: gerenciador de versões com várias JDKs lado a lado; .sdkmanrc commitado declara a versão por projeto e sdk env troca sozinho.

🧰
Analogia: caixa de ferramentas com gavetas etiquetadas — o .sdkmanrc é o bilhete na ordem de serviço dizendo qual gaveta usar.
🖥️ Terminal: IntelliJ Alt+F12 · VS Code Ctrl+` · ou terminal do SO. SDKMAN funciona em Linux/WSL/macOS.
terminal - SDKMAN do zero 
# Instala o SDKMAN (script oficial)
curl -s "https://get.sdkman.io" | bash

# Carrega o SDKMAN no shell atual
source "$HOME/.sdkman/bin/sdkman-init.sh"

# Lista JDKs disponíveis ("tem" = Eclipse Temurin, recomendado)
sdk list java | grep tem

# Instala o JDK 21 LTS e define como padrão da máquina
sdk install java 21.0.4-tem
sdk default java 21.0.4-tem

# Dentro de um projeto com .sdkmanrc: aplica a versão declarada
sdk env

# Valida
java -version

.../domain/ProdutoRepository.java 
package com.loja.domain;

import java.util.List;
import java.util.Optional;

/**
 * Porta de saída do domínio para persistência de {@link Produto}.
 *
 * <p>Define o CONTRATO que a infrastructure deve implementar, permitindo
 * trocar o mecanismo de persistência sem alterar o domínio (DIP).</p>
 *
 * @since 1.0.0
 */
public interface ProdutoRepository {

    /**
     * Persiste (insere ou atualiza) um produto.
     *
     * @param produto entidade a persistir
     * @return a entidade persistida, com {@code id} gerado pelo banco
     */
    Produto salvar(Produto produto);

    /**
     * Busca um produto por ID.
     *
     * @param id identificador único
     * @return {@link Optional} contendo o produto se existir
     */
    Optional<Produto> buscarPorId(Long id);

    /**
     * Lista todos os produtos.
     *
     * @return lista imutável (nunca {@code null})
     */
    List<Produto> listarTodos();

    /**
     * Verifica existência por ID (mais performático que {@link #buscarPorId}).
     *
     * @param id identificador a verificar
     * @return {@code true} se existir
     */
    boolean existePorId(Long id);

    /**
     * Remove fisicamente o produto.
     *
     * @param id identificador do produto
     */
    void deletarPorId(Long id);
}

    public Produto obterPorId(Long id) {
        return repository.buscarPorId(id)
            .orElseThrow(() -> new DomainException("Produto não encontrado: " + id));
    }

    /** {@inheritDoc} */
    @Override
    public void excluirProduto(Long id) {
        if (!repository.existePorId(id)) throw new DomainException("Produto inexistente: " + id);
        repository.deletarPorId(id);
    }

    /** Valida invariantes (fail-fast na primeira violação). */
    private void validarParaCriacao(Produto p) {
        if (p == null) throw new DomainException("Produto não pode ser nulo");
        if (p.getNome() == null || p.getNome().trim().isEmpty())
            throw new DomainException("O nome do produto é obrigatório");
        if (p.getNome().length() < 2)
            throw new DomainException("O nome deve ter pelo menos 2 caracteres");
        if (p.getPreco() == null || p.getPreco().compareTo(BigDecimal.ZERO) <= 0)
            throw new DomainException("O preço deve ser maior que zero");
        if (p.getEstoque() == null || p.getEstoque() < 0)
            throw new DomainException("O estoque não pode ser negativo");
    }
}

 * <p>Ativado quando {@code persistence.provider=relational} (padrão).</p>

@Repository

public class ProdutoRepositoryAdapter implements ProdutoRepository {

    public ProdutoRepositoryAdapter(SpringDataProdutoRepository jpaRepo) { this.jpaRepo = jpaRepo; }

    }

    }

namespace LojaApi.Domain.Entities;

/// <summary>
/// Aggregate Root de Produto — entidade rica (DDD).
/// </summary>
/// <remarks>
/// Setters PRIVADOS garantem que toda modificação passe pelas validações
/// internas, protegendo as invariantes de domínio.
/// </remarks>
public class Produto
{
    /// <summary>Identificador único (gerado pelo banco).</summary>
    public int Id { get; private set; }

    /// <summary>Nome do produto.</summary>
    public string Nome { get; private set; } = string.Empty;

    /// <summary>Preço unitário em R$.</summary>
    public decimal Preco { get; private set; }

    /// <summary>Quantidade em estoque.</summary>
    public int Estoque { get; private set; }

    /// <summary>Timestamp UTC de criação.</summary>
    public DateTime CriadoEm { get; private set; }

    /// <summary>Construtor protegido — usado pelo EF Core para materializar.</summary>
    protected Produto() { }

    /// <summary>Construtor para entidade já persistente.</summary>
    /// <param name="id">Identificador já atribuído.</param>
    /// <param name="nome">Nome.</param>
    /// <param name="preco">Preço.</param>
    /// <param name="estoque">Estoque.</param>
    /// <exception cref="Exceptions.DomainException">Se invariante violada.</exception>
    public Produto(int id, string nome, decimal preco, int estoque)
    {
        ValidarEAtribuir(nome, preco, estoque);
        Id = id;
        CriadoEm = DateTime.UtcNow;
    }

    /// <summary>Factory Method para criação de novo produto.</summary>
    /// <param name="nome">Nome (2–100 caracteres).</param>
    /// <param name="preco">Preço &gt; 0.</param>
    /// <param name="estoque">Estoque &gt;= 0.</param>
    /// <returns>Nova instância com Id = 0.</returns>
    /// <exception cref="Exceptions.DomainException">Se invariante violada.</exception>
    public static Produto Criar(string nome, decimal preco, int estoque)
        => new Produto(0, nome, preco, estoque);

    /// <summary>Remove unidades do estoque com guarda de suficiência.</summary>
    /// <param name="quantidade">Quantidade positiva a remover.</param>
    /// <exception cref="Exceptions.DomainException">Se quantidade inválida ou estoque insuficiente.</exception>
    public void RemoverEstoque(int quantidade)
    {
        if (quantidade <= 0) throw new Exceptions.DomainException("Quantidade deve ser positiva");
        if (Estoque < quantidade)
            throw new Exceptions.DomainException($"Estoque insuficiente. Disponível: {Estoque}");
        Estoque -= quantidade;
    }

    private void ValidarEAtribuir(string nome, decimal preco, int estoque)
    {
        if (string.IsNullOrWhiteSpace(nome)) throw new Exceptions.DomainException("Nome obrigatório");
        if (nome.Length < 2) throw new Exceptions.DomainException("Nome mínimo 2 caracteres");
        if (nome.Length > 100) throw new Exceptions.DomainException("Nome máximo 100 caracteres");
        if (preco <= 0) throw new Exceptions.DomainException("Preço deve ser maior que zero");
        if (estoque < 0) throw new Exceptions.DomainException("Estoque não pode ser negativo");
        Nome = nome.Trim(); Preco = preco; Estoque = estoque;
    }
}

❓ FAQ

HTTPS ou SSH no Git: qual escolher?

HTTPS + token é mais rápido para começar (não configura nada). SSH é melhor no dia a dia: após cadastrar a chave pública, você nunca mais digita credenciais. Em CI/CD, use tokens/variáveis de ambiente, nunca SSH interativo.

Pull Request (GitHub) e Merge Request (GitLab) são a mesma coisa?

Sim, na prática: ambos abrem uma revisão de código de um branch para a main, com comentários, CI e aprovação. Muda só o nome e a interface.

Por que o laboratório Java usa Spring Boot e não Java puro?

Porque o objetivo é validar o fluxo real de trabalho: Maven/wrapper, auto-configuração, Tomcat embutido, controller REST e terminal. Java puro é ótimo para entender a JVM, mas não prova que o ecossistema Spring — usado no resto do guia — está funcionando.

O curl retornou "connection refused". E agora?

1) A aplicação/container está realmente rodando? (docker compose ps ou console da IDE). 2) A porta está certa? O .NET imprime a porta real no console (Now listening on: ...). 3) Firewall/WSL: em Windows+WSL, teste localhost e, se falhar, o IP do WSL (hostname -I).

Vejo a documentação ao passar o mouse na IDE?

Sim! IntelliJ renderiza Javadoc no hover; VS Code com C# Dev Kit renderiza XML Doc. Gerar HTML: ./mvnw javadoc:javadoc (Java) e docfx (.NET).

Scripts init não rerodam. Por quê?

Só no 1º boot com volume vazio. Use docker compose down -v && docker compose up -d.
