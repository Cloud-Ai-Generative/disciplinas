🌐 Fundamentos de Engenharia & Paridade Operacional

Antes de escrever código, garantimos paridade ambiental estrita: instalação declarativa e idempotente das ferramentas, eliminando o "na minha máquina funciona".

🛡️ O 10º Fator do Twelve-Factor App: Dev/Prod Parity

O 10º fator estabelece que o ambiente de desenvolvimento deve ser o mais parecido possível com o de produção. Divergências sutis (versão do JDK, libc, kernel) causam bugs silenciosos que só aparecem em produção.

🎯 Os 3 Pilares da Paridade

  1. Gerenciadores Declarativos: winget (Windows), apt (Linux), brew (macOS) — scripts auditáveis commitados no Git.
  2. Isolamento com WSL2: contêineres Docker sobre kernel Linux real (não emulado), com I/O e syscalls idênticos à produção.
  3. Trava de Versão via Git: .sdkmanrc (Java) e global.json (.NET) forçam a mesma versão de compiladores para todo o time.
🍳
Analogia da Cozinha Industrial: se cada chef usar balanças descalibradas e fogões diferentes, o prato nunca sai igual. Toda a rede usa a mesma fita métrica, os mesmos termômetros e a mesma bancada padronizada!

🧱 Vocabulário Mínimo: JVM vs JDK vs JRE

🔄 Ciclo de vida do código Java

  1. Você escreve Produto.java.
  2. O javac compila para bytecode Produto.class.
  3. A JVM executa o bytecode (JIT) na máquina local.

🧵 Virtual Threads (Project Loom, Java 21)

  • Threads de SO ~1MB cada; virtuais ~1KB — milhões simultâneas.
  • Em I/O, a JVM desmonta a virtual thread e libera a thread de SO.

📦 JPA + Hibernate 6 + Lombok

  • JPA = especificação; Hibernate 6 = implementação (jakarta.persistence).
  • Lombok injeta getters/setters na AST (exige annotation processing).

🏗️ Maven e o wrapper mvnw

Maven gerencia build/dependências (pom.xml). O wrapper (mvnw) é commitado no repo e baixa a versão correta do Maven sozinho — o projeto garante a própria ferramenta (idem global.json no .NET). O ZIP da Tab 6 já inclui mvnw funcional.

🎯 Por que usar SDKMAN? (o sentido disso)

Problema: um dev tem Java 17, outro 21, o CI usa 25 — builds quebram "do nada". Instalar JDK à mão = ZIP + editar PATH/JAVA_HOME por versão.

SDKMAN resolve: gerenciador de versões com várias JDKs lado a lado; .sdkmanrc commitado declara a versão por projeto e sdk env troca sozinho.

🧰
Analogia: caixa de ferramentas com gavetas etiquetadas — o .sdkmanrc é o bilhete na ordem de serviço dizendo qual gaveta usar.
❌ Sem SDKMAN
  • ZIP manual por versão
  • Editar JAVA_HOME/PATH à mão
  • Uma versão por máquina
  • CI e devs divergem
✅ Com SDKMAN
  • sdk install java 21.0.4-tem
  • Troca por shell: sdk use
  • Por projeto: .sdkmanrc + sdk env
  • CI lê o mesmo arquivo = paridade
terminal - SDKMAN do zero 
curl -s "https://get.sdkman.io" | bash
source "$HOME/.sdkman/bin/sdkman-init.sh"
sdk list java | grep tem
sdk install java 21.0.4-tem
sdk default java 21.0.4-tem
sdk env          # dentro do projeto: aplica .sdkmanrc
java -version

🔒 global.json: por que travar o SDK?

Problema: você tem .NET 10, o colega 11 preview, o CI 9 — três compiladores diferentes p/ o mesmo código. Solução: global.json commitado diz à CLI dotnet qual SDK usar naquele repo (equivalente ao .sdkmanrc).

🎯 Versão do SDK:
global.json (commitado na raiz) 
{
  "sdk": {
    "version": "10.0.100",
    "rollForward": "latestFeature"
  }
}
💡 CLI: dotnet new globaljson --sdk-version 10.0.100 · rollForward: latestFeature | latestPatch | disable

contracts/openapi.yaml 
# CONTRATO OFICIAL - OpenAPI 3.1.0 (única fonte da verdade)
openapi: 3.1.0
info:
  title: Loja de Produtos REST API
  description: API com JWT (RFC 7519) e erros RFC 7807.
  version: 1.0.0

servers:
  - url: http://localhost:4010      # Mock Prism (compose dedicado)
  - url: http://localhost:8080      # Backend real (Spring/.NET)

security:
  - bearerAuth: []

paths:
  /api/auth/login:
    post:
      summary: Autentica e emite JWT
      tags: [🔐 Auth]
      security: []                  # login não exige JWT
      requestBody:
        required: true
        content:
          application/json:
            schema: { $ref: '#/components/schemas/LoginRequest' }
      responses:
        '200':
          description: Token emitido
          content:
            application/json:
              schema: { $ref: '#/components/schemas/LoginResponse' }
        '401': { description: Credenciais inválidas }

  /api/produtos:
    get:
      summary: Lista produtos
      tags: [📦 Produtos]
      responses:
        '200':
          content:
            application/json:
              schema:
                type: array
                items: { $ref: '#/components/schemas/ProdutoResponse' }
    post:
      summary: Cadastra produto
      tags: [📦 Produtos]
      requestBody:
        required: true
        content:
          application/json:
            schema: { $ref: '#/components/schemas/ProdutoRequest' }
      responses:
        '201': { description: Criado }
        '400': { description: Dados inválidos }

  /api/produtos/{id}:
    get:
      summary: Busca por ID
      tags: [📦 Produtos]
      parameters:
        - { name: id, in: path, required: true, schema: { type: integer } }
      responses:
        '200': { description: Encontrado }
        '404': { description: Não encontrado }
    delete:
      summary: Exclui produto
      tags: [📦 Produtos]
      parameters:
        - { name: id, in: path, required: true, schema: { type: integer } }
      responses:
        '204': { description: Excluído }

components:
  securitySchemes:
    bearerAuth: { type: http, scheme: bearer, bearerFormat: JWT }
  schemas:
    LoginRequest:
      type: object
      required: [email, senha]
      properties:
        email: { type: string, format: email, example: dev@loja.com.br }
        senha: { type: string, format: password }
    LoginResponse:
      type: object
      properties:
        tokenAcesso: { type: string, example: eyJhbGciOiJIUzI1NiJ9... }
        tipoToken: { type: string, enum: [Bearer] }
        expiraEmSegundos: { type: integer, example: 3600 }
    ProdutoRequest:
      type: object
      required: [nome, preco, estoque]
      properties:
        nome: { type: string, minLength: 2, maxLength: 100 }
        preco: { type: number, minimum: 0.01, example: 349.90 }
        estoque: { type: integer, minimum: 0, example: 15 }
    ProdutoResponse:
      allOf:
        - $ref: '#/components/schemas/ProdutoRequest'
        - type: object
          properties: { id: { type: integer, example: 1 } }

🐬🍃 Orquestração de Bancos: MySQL 8.4 + MongoDB 7.0

Compose somente com os bancos das APIs. Você conecta e explora primeiro — depois entende de onde vieram os dados (scripts de carga).

🐳 Conceitos

1. Rede Bridge

DNS interno pelo nome: mysql-db:3306, mongo-db:27017; só ports: expõe ao host.

2. Volumes vs Bind Mounts

  • Volumes: persistem (dados).
  • Bind Mounts: pasta do host mapeada (scripts/configs).

3. Healthcheck

Teste periódico (ex.: mysqladmin ping) marca o container como healthy.

🐳 Subir a infraestrutura

up -d
Cria volumes/redes, roda init, background.
ps
Status, portas, saúde.
stop
Para preservando volumes.
down -v
Derruba e APAGA volumes.
logs -f
Logs em tempo real.
exec -it <nome> bash
Shell no container.

📦 Passo 2: De onde vieram os dados? (DDL/DML)

🚪 /docker-entrypoint-initdb.d

Arquivos .sql/.js montados aí rodam uma vez, no primeiro boot com volume vazio, em ordem alfanumérica. DDL cria estruturas; DML insere seed. Para reexecutar: docker compose down -v && docker compose up -d.

🐬 init-sql/01-init.sql

init-sql/01-init.sql 
USE loja_db;

-- DDL: estrutura (idempotente)
CREATE TABLE IF NOT EXISTS produtos (
    id BIGINT AUTO_INCREMENT PRIMARY KEY,
    nome VARCHAR(100) NOT NULL,
    preco DECIMAL(10,2) NOT NULL,
    estoque INT NOT NULL DEFAULT 0,
    criado_em TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    CONSTRAINT chk_preco CHECK (preco > 0),
    CONSTRAINT chk_estoque CHECK (estoque >= 0)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

-- DML: seed
INSERT INTO produtos (nome, preco, estoque) VALUES
('Teclado Mecanico RGB', 349.90, 15),
('Mouse Gamer 16000 DPI', 189.50, 20),
('Headset 7.1 Surround', 420.00, 10);

CREATE INDEX idx_nome ON produtos(nome);

.../application/ProdutoServiceImpl.java 
package com.loja.application;

import com.loja.domain.Produto;
import com.loja.domain.ProdutoRepository;
import com.loja.domain.exception.DomainException;
import java.math.BigDecimal;
import java.util.List;

/**
 * CASOS DE USO - módulo SEM Spring (Clean Arch).
 * O Bean é registrado na infrastructure (CoreBeansConfig).
 */
public class ProdutoServiceImpl implements ProdutoService {

    private final ProdutoRepository repository;

    public ProdutoServiceImpl(ProdutoRepository repository) {
        this.repository = repository;
    }

    @Override
    public Produto criarProduto(Produto produto) {
        if (produto.getNome() == null || produto.getNome().trim().isEmpty())
            throw new DomainException("O nome do produto é obrigatório");
        if (produto.getNome().length() < 2)
            throw new DomainException("O nome deve ter pelo menos 2 caracteres");
        if (produto.getPreco() == null || produto.getPreco().compareTo(BigDecimal.ZERO) <= 0)
            throw new DomainException("O preço deve ser maior que zero");
        if (produto.getEstoque() == null || produto.getEstoque() < 0)
            throw new DomainException("O estoque não pode ser negativo");
        return repository.salvar(produto);
    }

    @Override
    public List listarProdutos() { return repository.listarTodos(); }

    @Override
    public Produto obterPorId(Long id) {
        return repository.buscarPorId(id)
            .orElseThrow(() -> new DomainException("Produto não encontrado: " + id));
    }

    @Override
    public void excluirProduto(Long id) {
        if (!repository.existePorId(id))
            throw new DomainException("Produto inexistente: " + id);
        repository.deletarPorId(id);
    }
}

.../persistence/ProdutoRepositoryAdapter.java 
package com.loja.infrastructure.persistence;

import com.loja.domain.Produto;
import com.loja.domain.ProdutoRepository;
import org.springframework.boot.autoconfigure.condition.ConditionalOnProperty;
import org.springframework.stereotype.Repository;
import java.util.List;
import java.util.Optional;

/** ADAPTER JPA: ativo com persistence.provider=relational (padrão). */
@Repository
@ConditionalOnProperty(name = "persistence.provider", havingValue = "relational", matchIfMissing = true)
public class ProdutoRepositoryAdapter implements ProdutoRepository {

    private final SpringDataProdutoRepository jpaRepo;
    public ProdutoRepositoryAdapter(SpringDataProdutoRepository jpaRepo) { this.jpaRepo = jpaRepo; }

    @Override public Produto salvar(Produto p) { return toDomain(jpaRepo.save(toJpa(p))); }
    @Override public Optional buscarPorId(Long id) { return jpaRepo.findById(id).map(this::toDomain); }
    @Override public List listarTodos() { return jpaRepo.findAll().stream().map(this::toDomain).toList(); }
    @Override public boolean existePorId(Long id) { return jpaRepo.existsById(id); }
    @Override public void deletarPorId(Long id) { jpaRepo.deleteById(id); }

    private ProdutoJpaEntity toJpa(Produto d) {
        ProdutoJpaEntity e = new ProdutoJpaEntity();
        e.setId(d.getId()); e.setNome(d.getNome()); e.setPreco(d.getPreco()); e.setEstoque(d.getEstoque());
        return e;
    }
    private Produto toDomain(ProdutoJpaEntity e) {
        return new Produto(e.getId(), e.getNome(), e.getPreco(), e.getEstoque());
    }
}

namespace LojaApi.Domain.Entities;

/// <summary>AGGREGATE ROOT: setters privados protegem invariantes.</summary>
public class Produto
{
    public int Id { get; private set; }
    public string Nome { get; private set; } = string.Empty;
    public decimal Preco { get; private set; }
    public int Estoque { get; private set; }
    public DateTime CriadoEm { get; private set; }

    protected Produto() { }   // EF Core materializa por aqui

    public Produto(int id, string nome, decimal preco, int estoque)
    {
        ValidarEAtribuir(nome, preco, estoque);
        Id = id;
        CriadoEm = DateTime.UtcNow;
    }

    public static Produto Criar(string nome, decimal preco, int estoque)
        => new Produto(0, nome, preco, estoque);

    public void RemoverEstoque(int quantidade)
    {
        if (quantidade <= 0) throw new DomainException("Quantidade deve ser positiva");
        if (Estoque < quantidade)
            throw new DomainException("Estoque insuficiente. Disponível: " + Estoque);
        Estoque -= quantidade;
    }

    private void ValidarEAtribuir(string nome, decimal preco, int estoque)
    {
        if (string.IsNullOrWhiteSpace(nome)) throw new DomainException("Nome obrigatório");
        if (nome.Length < 2) throw new DomainException("Nome mínimo 2 caracteres");
        if (nome.Length > 100) throw new DomainException("Nome máximo 100 caracteres");
        if (preco <= 0) throw new DomainException("Preço deve ser maior que zero");
        if (estoque < 0) throw new DomainException("Estoque não pode ser negativo");
        Nome = nome.Trim(); Preco = preco; Estoque = estoque;
    }
}

❓ FAQ

O que vem dentro dos ZIPs?

Arquivos exibidos na aba (coletados via data-zip-path) + arquivos de projeto gerados (mvnw, .csproj, .sln, classes de suporte) + README.md em PT-BR com pré-requisitos, passos numerados, diagramas Mermaid e troubleshooting. O ZIP "Projeto Completo" combina tudo com COMO_RODAR.md na raiz.

Por que o Prism não está no compose dos bancos?

Separação de responsabilidades: Prism é ferramenta do contrato. Compose dedicado permite subir só o mock.

Scripts init não rerodam. Por quê?

Só no 1º boot com volume vazio. Use docker compose down -v && docker compose up -d.

Como funciona o toggle de migração?

Java: @ConditionalOnProperty. .NET: switch no DI do Program.cs. Valores: relational | dual | nosql.
