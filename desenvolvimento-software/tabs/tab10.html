🗺️ Diagnóstico, Glossário & FAQ

Feche o ciclo: valide seu ambiente com os sanity checks, consulte o cheat-sheet e o glossário A–Z, e tire dúvidas no FAQ. Tudo filtrável.

✅ Sanity Check (seu ambiente está pronto?)

Rode um card de cada vez e compare com o ✅ Resultado esperado. Se tudo bater, o ambiente está pronto para qualquer aba.

🌿 Git

Qualquer terminal (no Windows, o Git Bash).

git --version
git config --global user.name

✅ Resultado esperado: git version 2.x e, na 2ª linha, o seu nome.

✋ Errou? "git não é reconhecido" → reinstale o Git marcando "Add to PATH" e abra um terminal novo. Nome vazio → refaça a configuração da → Tab 3-G.

🐍 Python

Terminal do VS Code. No Linux/macOS: python3 --version.

python --version

✅ Resultado esperado: Python 3.14.x.

✋ Errou? Abriu a Microsoft Store → o Python não está no PATH: reinstale marcando "Add python.exe to PATH". Veja a → Tab 3-P.

☕ Java + testes

Na pasta loja-api da Tab 6 (no Windows: mvnw test).

java -version
./mvnw test

✅ Resultado esperado: openjdk version "21…" e, no fim, Tests run: 19, Failures: 0 e BUILD SUCCESS.

✋ Errou? Versão 17 ou menor → instale o JDK 21 e ajuste o JAVA_HOME. mvnw não encontrado → você não está na pasta do projeto. → Tab 2

🔷 .NET + testes

Na pasta da solução (onde está o .sln: LojaApi, LojaEventos ou LojaMulti).

dotnet --version
dotnet test

✅ Resultado esperado: 10.0.x e Aprovado! – Com falha: 0 (em inglês: Passed! – Failed: 0). Casos: Tab 7 = 29 · 7-B = 52 · 9 = 57 · 9-B = 60.

✋ Errou? MSB1003 → não há .sln nesta pasta. Versão 8 ou 9 → instale o SDK 10. → Tab 3

🐳 Docker

Na pasta do docker-compose.yml (por exemplo loja-infra, da Tab 5).

docker version
docker compose ps

✅ Resultado esperado: Seções Client e Server, e cada container com Up … (healthy).

✋ Errou? error during connect / Cannot connect to the Docker daemon → o Docker Desktop está fechado: abra e espere Engine running 🟢. Lista vazia → rode docker compose up -d. → Tab 5

🐬 MySQL

Qualquer terminal, com o banco da Tab 5 ligado.

docker exec -it dev_mysql_server mysql -uroot -proot123 -e "SELECT COUNT(*) FROM loja_db.produtos;"

✅ Resultado esperado: Uma tabelinha com um número (3 ou mais, se você fez os exercícios da Tab 5). O aviso "Using a password on the command line…" é normal.

✋ Errou? No such container → o container não está no ar (docker compose ps). Unknown database → recrie o volume (docker compose down -v e up -d).

🍃 MongoDB

Qualquer terminal, com o banco da Tab 5 ligado.

docker exec -it dev_mongo_server mongosh -u root -p root123 --authenticationDatabase admin loja_nosql --quiet --eval "db.produtos.countDocuments()"

✅ Resultado esperado: Um número (0 ou mais).

✋ Errou? Authentication failed → confira usuário/senha e o --authenticationDatabase admin (o root mora no database admin).

⚡ Prism (mock)

Com o docker-compose.prism.yml da Tab 4 ligado. No PowerShell: curl.exe.

curl -i http://localhost:4010/api/produtos

✅ Resultado esperado: HTTP/1.1 200 OK e um JSON de exemplo vindo do contrato.

✋ Errou? Failed to connect → o mock não está no ar (Compose Up no docker-compose.prism.yml). → Tab 4

❓ FAQ

Nunca programei. Por onde eu começo?

Pela Tab 1 (visão geral e glossário), depois a Tab 3-G (Git e GitHub). Em seguida escolha uma linguagem — Java (Tab 2) ou C# (Tab 3) — e siga a trilha dela no 🗺️ Mapa das 15 abas. Não tente fazer as duas ao mesmo tempo.

Posso pular abas?

Algumas sim. As Tabs 3-P (Python) e a trilha da outra linguagem são opcionais. Mas a Tab 4 (contrato) e a Tab 5 (bancos) são usadas por todas as abas de código, e as abas "-B" (6-B, 7-B, 9-B) partem da solução da aba anterior: a 9-B não funciona sem a 9 pronta.

Quanto tempo leva cada aba?

Cada aba de código tem, no topo, o banner 🗺️ O caminho desta aba com o tempo estimado (de ~1h30 nas abas iniciais a ~4h na 7-B). É normal levar o dobro na primeira vez: o tempo extra vai para ler os quadros 💡 e os ✋ Errou?.

Uma porta já está em uso. O que eu faço?

Erro do tipo port is already allocated ou address already in use quer dizer que outro programa já ocupa aquela porta. As portas do guia: 3306 (MySQL da Tab 5) · 3307 (MySQL da Tab 9) · 27017 / 27018 (MongoDB da Tab 5 / 9-B) · 4010 / 4011 (Prism das Tabs 4 / 8) · 5672 e 15672 (RabbitMQ, 7-B) · 8080 (API Java) · 5000 (API C#). Desligue o container de outra aba no Docker Desktop (⏹️) ou feche a API que ficou rodando.

O ZIP da aba e o que eu digitei ficaram diferentes. Qual vale?

O ZIP: ele é a versão de referência, testada. Se o seu código não compila, compare arquivo por arquivo com o do ZIP (no VS Code: botão direito em dois arquivos → Compare Selected).

Um teste ficou vermelho. Quebrei tudo?

Não. Leia a mensagem do teste no Test Explorer (ou no terminal): ela diz o esperado e o obtido. Muitas abas pedem de propósito que você faça um teste ficar 🔴 para ver a rede de proteção funcionando. Se não foi de propósito, desfaça a última mudança (Ctrl+Z ou git restore) e rode de novo.

O que é uma ADR e por que tem tantas?

É o registro de uma decisão de arquitetura: o que foi decidido, por quê e o que se perdeu. A explicação completa está na Tab 4, e a lista de todas (001 a 026) está em 📑 Todas as decisões registradas, acima.

Por que Java e C# ficam em abas separadas?

Para não misturar duas linguagens no mesmo passo a passo. Cada trilha é completa sozinha: Java nas Tabs 2 → 6 → 6-B (IntelliJ) e C# nas Tabs 3 → 7 → 7-B → 9 → 9-B (VS Code). As abas de contrato e de bancos (4, 5 e 8) servem às duas. Veja o 🗺️ Mapa das 15 abas, acima.

Os diagramas têm nome? Onde vejo qual é qual?

Sim: todo diagrama tem cabeçalho 📐 D-XX · tipo — nome. A lista completa, com a aba de cada um, está em 📐 Todos os diagramas, acima.

Estamos usando SOLID? Onde?

Sim. Cada aba de stack tem a tabela SOLID aplicado mapeando cada princípio (S/O/L/I/D) ao arquivo/concretização no projeto, com links.

O que significa cada tag do openapi.yaml?

Abra o quadro "🔎 o que significa CADA tag" na Tab 4: explica linha a linha.

Onde valido o contrato e onde leio a especificação?

Validar: editor.swagger.io. Especificação: spec.openapis.org/oas/v3.1.0. Ambos linkados na Tab 4.
