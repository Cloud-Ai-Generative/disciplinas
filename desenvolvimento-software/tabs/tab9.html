① 🧱 Monolito modular: 4 módulos, 4 bancos, 1 processo

Um monolito modular é um único programa (um processo, um deploy) dividido por dentro em módulos com fronteiras rígidas. Cada módulo é um bounded context do DDD: tem as suas regras, o seu vocabulário, o seu banco — e só conversa com os outros por uma interface pública, nunca mexendo nas classes ou nas tabelas deles.

🏬
Analogia do shopping: um prédio só (o processo da API), mas cada loja (módulo) tem o seu estoque (o seu banco) e a sua porta. A loja de Pedidos não entra no depósito do Catálogo: ela pede no balcão (chamada HTTP). Se um dia o Catálogo virar um prédio separado (microsserviço), o balcão continua igual.

📏 As regras que fazem ser "modular" de verdade

  1. Um módulo não referencia o projeto de outro módulo. Todos conhecem só o Shared.Kernel (Value Objects, exceções, tipos de erro). Quem junta tudo é o host LojaApi.Api.
  2. Cada módulo é dono dos seus dados. Pedidos não lê catalogo_db; pergunta ao Catálogo. Sem JOIN entre databases.
  3. Só a interface pública atravessa a fronteira — aqui, as rotas HTTP de cada módulo (o contrato da Tab 8).
  4. A regra é verificada por teste, não por boa vontade: o ArquiteturaTests (parte ⑥) quebra o build se um módulo usar outro.
  5. Por dentro, cada módulo tem as mesmas camadas (Clean Architecture — próximo quadro).

⚠️ Nota honesta: HTTP entre módulos do MESMO processo é incomum. Num monolito modular "de mercado", Pedidos chamaria o Catálogo por uma interface C# pública do módulo (chamada em memória) ou por eventos — sem rede. Aqui escolhemos HTTP de propósito, para estudar: o contrato da Tab 8 vira código, e você vê o que é uma chamada remota (timeout, 503, token repassado, compensação). O preço: latência de ida e volta pela rede local, serialização de JSON, e uma chamada que pode falhar mesmo com tudo no mesmo processo. Num sistema real, comece pela chamada em memória.

🚀 Como ele evolui

  • Para microsserviço: como Pedidos só conhece o Catálogo pelo endereço em Services:Catalogo (no appsettings.json), separar o Catálogo num processo próprio é mudar essa linha. O código não muda.
  • Para eventos: o Pedido já registra o evento de domínio PedidoCriadoEvent. Publicá-lo numa fila (RabbitMQ, como na Tab 7-B) troca o "pergunta e espera" pelo "avisa e segue".
  • Para outro banco: cada módulo fala com o banco por uma porta; a Tab 9-B troca os 4 por MongoDB só com adapters novos.

🧩 Três ideias que aparecem em todo módulo: DTO, Shared Kernel e Criar × Reconstituir

1. DTO (Data Transfer Object) — o "formulário" da API. É uma classe só com dados, sem regra, no formato exato do contrato da Tab 8. O ProdutoRequest é o que chega no POST; o ProdutoResponse é o que sai no JSON. A entidade Produto nunca sai direto pela API. Por quê?

  • a entidade tem coisas que o cliente não deve ver nem mandar (a lista de eventos, o Reservado escrito à mão);
  • se você renomear uma propriedade da entidade, o JSON — e o contrato — não muda sem querer;
  • o DTO pode juntar ou calcular campos (o Disponivel do response).

A conversão fica num lugar só: ProdutoResponse.De(produto).

2. Shared Kernel — o "dicionário comum" dos módulos. Em DDD, cada contexto tem o seu modelo e não usa o dos outros. Mas algumas peças pequenas e estáveis valem para todos: o Value Object Dinheiro (preço no Catálogo, total no Pedido), a DomainException, os ProblemTypes do contrato, a base AggregateRoot. Elas ficam no projeto LojaApi.Shared.Kernel, o único que todos os módulos podem referenciar. A regra de ouro: o kernel é pequeno e só muda com acordo de todos os times — se começar a crescer, é sinal de que um contexto está vazando para dentro dele.

3. Criar × Reconstituir — nascer ou voltar do banco. Toda entidade tem duas fábricas estáticas (no lugar de um new público):

Produto.Criar(nome, preco, estoque)Produto.Reconstituir(id, nome, preco, estoque, reservado)
Quandoo produto nasce (POST)o produto já existe (lido do banco, do MongoDB na Tab 9-B, ou montado num teste)
Valida?✅ sim: nome 2–100, preço > 0, estoque ≥ 0❌ não: o dado já foi validado quando nasceu
Idnão tem — quem dá é o bancorecebe o id que já existe

Por que não validar sempre? Porque a regra pode mudar: se amanhã o nome mínimo passar a 3 letras, um produto antigo chamado "TV" ainda precisa ser lido do banco — senão a API quebra ao listar. E nos testes, o Reconstituir monta um produto em qualquer estado ("5 em estoque, 3 reservados") numa linha.

🔗 Um pedido, três contextos: HTTP síncrono + compensação

Fazer um pedido precisa de duas respostas de fora: "tem estoque?" (Catálogo) e "esse endereço é do cliente?" (Clientes). O PedidoService pergunta por HTTP e espera (síncrono, com limite de 2 segundos). E se o 2º item não tiver estoque, depois que o 1º já foi reservado? A reserva do 1º é devolvida (liberar): é a compensação, uma saga simples. Sem ela, o estoque ficaria preso para sempre.

# ══════════════════════════════════════════════════════════
# COMPOSE DE INFRAESTRUTURA — MySQL com 4 databases (fronteira por contexto)
# ══════════════════════════════════════════════════════════
# Uso:
#   docker compose up -d          → sobe o banco em background
#   docker compose ps             → verifica status
#   docker compose down           → derruba (mantém volumes)
#   docker compose down -v        → derruba e APAGA volumes (re-run init)
# ══════════════════════════════════════════════════════════

services:
  mysql-db:
    # MySQL 8.4 LTS
    image: mysql:8.4

    # Nome fixo do container (facilita docker exec)

    # Reinicia sozinho se cair
    restart: unless-stopped

    environment:
      MYSQL_ROOT_PASSWORD: root123

      MYSQL_PASSWORD: devpass

    # Porta no SEU PC: 3307 (a 3306 já é do MySQL da Tab 5 — os dois podem ficar ligados).

    ports:
      - "3307:3306"

      - ./init-sql-contextos:/docker-entrypoint-initdb.d

-- ══════════════════════════════════════════════════════════════
-- INIT SQL: 4 databases + tabelas + seed admin
-- ══════════════════════════════════════════════════════════════
-- Este script roda UMA vez no primeiro boot do MySQL (volume vazio).
-- Para re-executar: docker compose down -v && docker compose up -d
-- ══════════════════════════════════════════════════════════════

-- ──────────────────────────────────────────────────────────────
-- 1) CRIAR OS 4 DATABASES (fronteira de dados por contexto)
-- ──────────────────────────────────────────────────────────────
CREATE DATABASE IF NOT EXISTS auth_db CHARACTER SET utf8mb4;
CREATE DATABASE IF NOT EXISTS catalogo_db CHARACTER SET utf8mb4;
CREATE DATABASE IF NOT EXISTS pedidos_db CHARACTER SET utf8mb4;
CREATE DATABASE IF NOT EXISTS clientes_db CHARACTER SET utf8mb4;

-- O entrypoint do MySQL cria o devuser (MYSQL_USER) ANTES deste script,
-- mas só dá privilégios no MYSQL_DATABASE (que não definimos).
-- Sem estes GRANTs, o appsettings.json (User=devuser) recebe "Access denied".
GRANT ALL PRIVILEGES ON auth_db.*     TO 'devuser'@'%';
GRANT ALL PRIVILEGES ON catalogo_db.* TO 'devuser'@'%';
GRANT ALL PRIVILEGES ON pedidos_db.*  TO 'devuser'@'%';
GRANT ALL PRIVILEGES ON clientes_db.* TO 'devuser'@'%';
FLUSH PRIVILEGES;

-- ──────────────────────────────────────────────────────────────
-- 2) AUTH: tabela usuarios + seed admin
-- ──────────────────────────────────────────────────────────────
USE auth_db;

-- Tabela de usuários (senha em texto puro — didático)
CREATE TABLE IF NOT EXISTS usuarios (
  -- GUID como chave primária (CHAR(36) no MySQL)
  id CHAR(36) NOT NULL PRIMARY KEY,

  -- Login único (usado na autenticação)
  login VARCHAR(100) NOT NULL,

  -- Nome exibido no token e nas respostas
  nome VARCHAR(200) NOT NULL,

  -- Senha em texto puro (DIDÁTICO — nunca em produção!)
  senha VARCHAR(255) NOT NULL,

  -- Data de criação do usuário
	CriadoEm DATETIME(6) NOT NULL DEFAULT CURRENT_TIMESTAMP(6),
	-- Índice único no login para evitar duplicados
  UNIQUE INDEX ix_usuarios_login (login)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

-- Seed: usuário admin inicial
-- Login: admin / Senha: admin123
INSERT INTO usuarios (id, login, nome, senha, CriadoEm)
VALUES (UUID(), 'admin', 'Administrador', 'admin123', UTC_TIMESTAMP());

-- ──────────────────────────────────────────────────────────────
-- 3) CATÁLOGO: tabela produtos
-- ──────────────────────────────────────────────────────────────
USE catalogo_db;

CREATE TABLE IF NOT EXISTS produtos (
  -- Id auto-incremento
  id INT NOT NULL AUTO_INCREMENT PRIMARY KEY,

  -- Nome do produto (obrigatório)
  nome VARCHAR(100) NOT NULL,

  -- Preço com precisão decimal
  preco DECIMAL(10,2) NOT NULL,

  -- Estoque total
  estoque INT NOT NULL DEFAULT 0,

  -- Quantidade reservada (reserva em duas fases)
  reservado INT NOT NULL DEFAULT 0
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

-- Seed: os ids são os MESMOS dos exemplos do contrato da Tab 8 (produto 101).
-- Assim o testes-contextos.http da Tab 8 roda aqui quase sem mudança.

👉 O Value Object de dinheiro, usado por Catálogo e Pedidos: nunca negativo, sempre com 2 casas, comparado pelo valor e com os operadores + e ×.

LojaApi.Shared.Kernel/Dinheiro.cs (Value Object) 
using System.Globalization;

namespace LojaApi.Shared.Kernel;

/// <summary>
/// 💰 VALUE OBJECT "Dinheiro" (DDD): sem identidade, imutável e comparado pelo VALOR —
/// dois "R$ 10,00" são iguais. Fica no Shared Kernel porque Catálogo (preço) e
/// Pedidos (preço do item, total) falam a MESMA língua de dinheiro.
///
/// Por que não um "decimal" solto? Porque a regra "nunca negativo, sempre 2 casas"
/// passa a morar num lugar só, e o compilador não deixa somar preço com estoque.
/// </summary>
public sealed record Dinheiro
{
    public decimal Valor { get; }

    public Dinheiro(decimal valor)
    {
        if (valor < 0)
            throw new DomainException("Valor em dinheiro não pode ser negativo");
        Valor = decimal.Round(valor, 2, MidpointRounding.AwayFromZero);   // centavos, como o DECIMAL(10,2)
    }

    public static Dinheiro Zero { get; } = new(0);

    public static Dinheiro operator +(Dinheiro a, Dinheiro b) => new(a.Valor + b.Valor);
    public static Dinheiro operator *(Dinheiro a, int quantidade) => new(a.Valor * quantidade);

    public override string ToString() => Valor.ToString("F2", CultureInfo.InvariantCulture);
}

using LojaApi.Shared.Kernel;

namespace LojaApi.Modules.Auth.Domain;

/// <summary>
/// Entidade Usuario do contexto Auth.
/// Didático: senha em texto puro. Não usar em produção real.
/// </summary>
public class Usuario
{
    /// <summary>Identificador do usuário. Vira o claim "sub" do JWT.</summary>
    public Guid Id { get; private set; }

    /// <summary>Login usado na autenticação. Deve ser único.</summary>
    public string Login { get; private set; } = string.Empty;

    /// <summary>Nome exibido no token e nas respostas.</summary>
    public string Nome { get; private set; } = string.Empty;

    /// <summary>
    /// Senha em texto puro (didático).
    /// Em produção real: hash forte, nunca texto puro.
    /// </summary>
    public string Senha { get; private set; } = string.Empty;

    /// <summary>Data de criação do usuário.</summary>
    public DateTime CriadoEm { get; private set; }

    /// <summary>
    /// Construtor protegido para o EF Core materializar a entidade.
    /// </summary>
    protected Usuario() { }

    /// <summary>
    /// Construtor principal com validações mínimas de domínio.
    /// </summary>
    public Usuario(Guid id, string login, string nome, string senha)
    {
        // Valida login: não pode ser vazio
        if (string.IsNullOrWhiteSpace(login))
            throw new DomainException("O login é obrigatório.");

        // Valida nome: não pode ser vazio
        if (string.IsNullOrWhiteSpace(nome))
            throw new DomainException("O nome é obrigatório.");

        // Valida senha: não pode ser vazia
        if (string.IsNullOrWhiteSpace(senha))
            throw new DomainException("A senha é obrigatória.");

        // Atribui os valores normalizando o login para minúsculas
        Id = id;
        Login = login.Trim().ToLower();
        Nome = nome.Trim();
        Senha = senha;
        CriadoEm = DateTime.UtcNow;
    }

    /// <summary>Usuário que JÁ existe (banco ou documento da Tab 9-B): sem validação, mantém a data original.</summary>
    public static Usuario Reconstituir(Guid id, string login, string nome, string senha, DateTime criadoEm)
        => new() { Id = id, Login = login, Nome = nome, Senha = senha, CriadoEm = criadoEm };

    /// <summary>
    /// Compara a senha recebida com a senha armazenada.
    /// Didático: comparação direta em texto puro.
    /// </summary>
    public bool SenhaConfere(string senha)
    {
        // Se a senha enviada for nula/vazia, falha imediatamente
        if (string.IsNullOrWhiteSpace(senha))
            return false;

        // Comparação direta (texto puro)
        return Senha == senha;
    }
}

LojaApi.Modules.Auth/Application/AuthService.cs (o caso de uso) 
using LojaApi.Modules.Auth.Domain;
using System.Threading.Tasks;

namespace LojaApi.Modules.Auth.Application;

/// <summary>
/// Caso de uso de login.
/// Depende da interface IUsuarioRepository, não da implementação MySQL.
/// Isso deixa o módulo pronto para futura troca por MongoDB.
/// </summary>
public class AuthService : IAuthService
{
    // Porta de acesso aos usuários
    private readonly IUsuarioRepository _usuarioRepository;

    // Serviço gerador de JWT
    private readonly IJwtService _jwtService;

    /// <summary>
    /// Injeção de dependência via construtor.
    /// </summary>
    public AuthService(IUsuarioRepository usuarioRepository, IJwtService jwtService)
    {
        _usuarioRepository = usuarioRepository;
        _jwtService = jwtService;
    }

    /// <summary>
    /// Valida credenciais e emite JWT.
    /// </summary>
    public async Task<LoginResult?> AutenticarAsync(string login, string senha)
    {
        // Se login ou senha estiverem vazios, falha imediatamente
        if (string.IsNullOrWhiteSpace(login) || string.IsNullOrWhiteSpace(senha))
            return null;

        // Busca o usuário pelo login
        var usuario = await _usuarioRepository.BuscarPorLoginAsync(login);

        // Se não encontrou o usuário, credenciais inválidas
        if (usuario is null)
            return null;

        // Compara senha em texto puro (didático)
        if (!usuario.SenhaConfere(senha))
            return null;

        // Gera o token JWT
        var token = _jwtService.GerarToken(usuario);

        // Retorna token + usuário autenticado
        return new LoginResult(
            token,
            new UsuarioAutenticado(usuario.Id, usuario.Nome, usuario.Login)
        );
    }
}

/// <summary>🔌 ADAPTER EF Core + MySQL da porta IUsuarioRepository (tabela usuarios).</summary>

    public Task<Usuario?> BuscarPorLoginAsync(string login, CancellationToken ct = default)
    {
        var normalizado = login.Trim().ToLower();   // mesma regra do construtor de Usuario
        return _db.Usuarios.AsNoTracking().FirstOrDefaultAsync(u => u.Login == normalizado, ct);
    }

    public async Task<Usuario> SalvarAsync(Usuario usuario, CancellationToken ct = default)
    {
        if (await _db.Usuarios.AnyAsync(u => u.Id == usuario.Id, ct))
            _db.Usuarios.Update(usuario);
        else
            _db.Usuarios.Add(usuario);
        await _db.SaveChangesAsync(ct);
        return usuario;
    }
}

👉 O adapter do token: monta as claims (sub, name, login, exp) e assina com a chave secreta.

LojaApi.Modules.Auth/Infrastructure/JwtService.cs (o adapter do token) 
using LojaApi.Modules.Auth.Application;
using LojaApi.Modules.Auth.Domain;
using Microsoft.IdentityModel.Tokens;
using System;
using System.IdentityModel.Tokens.Jwt;
using System.Security.Claims;
using System.Text;

namespace LojaApi.Modules.Auth.Infrastructure;

/// <summary>
/// Gera JWT real usando HMAC-SHA256.
/// O token contém:
/// - sub: id do usuário
/// - name: nome do usuário
/// - exp: expiração
/// - login: extra opcional, útil para diagnóstico (não é usado na autorização)
/// </summary>
public class JwtService : IJwtService
{
    // Segredo usado para assinar o token
    private readonly string _secret;

    // Tempo de vida do token em minutos
    private readonly int _expirationMinutes;

    /// <summary>
    /// Construtor recebe secret e expiração.
    /// </summary>
    public JwtService(string secret, int expirationMinutes)
    {
        // Valida se o secret foi informado
        if (string.IsNullOrWhiteSpace(secret))
            throw new ArgumentException("O JWT Secret não pode ser vazio.");

        // HMAC-SHA256 exige chave com pelo menos 32 caracteres
        if (secret.Length < 32)
            throw new ArgumentException("O JWT Secret deve ter pelo menos 32 caracteres.");

        // Valida expiração positiva
        if (expirationMinutes <= 0)
            throw new ArgumentException("A expiração do JWT deve ser maior que zero.");

        _secret = secret;
        _expirationMinutes = expirationMinutes;
    }

    /// <summary>
    /// Gera o token JWT para o usuário.
    /// </summary>
    public string GerarToken(Usuario usuario)
    {
        // Converte o secret em chave simétrica
        var key = new SymmetricSecurityKey(Encoding.UTF8.GetBytes(_secret));

        // Cria as credenciais de assinatura
        var credentials = new SigningCredentials(key, SecurityAlgorithms.HmacSha256);

        // Define as claims do token
        var claims = new[]
        {
            // sub: identificador do usuário
            new Claim(JwtRegisteredClaimNames.Sub, usuario.Id.ToString()),

            // name: nome do usuário
            new Claim("name", usuario.Nome),

            // login: útil para diagnóstico e testes
            new Claim("login", usuario.Login)
        };

        // Define a expiração do token
        var expiration = DateTime.UtcNow.AddMinutes(_expirationMinutes);

        // Monta o token JWT
        var token = new JwtSecurityToken(
            claims: claims,
            expires: expiration,
            signingCredentials: credentials
        );

        // Serializa o token para o formato string
        return new JwtSecurityTokenHandler().WriteToken(token);
    }
}

O Produto guarda estoque e reservado; o disponivel é a conta entre os dois, e o preço é um Dinheiro. Reservar é o "segura para mim"; liberar é o "pode devolver". O ProdutoService recebe um ProdutoRequest (sem id: quem cria o id é o banco), aplica as regras do domínio e grava pela porta. O controller só repassa.

🧠 Domain

👉 O Aggregate Root do Catálogo: estoque, reservado e preço (Dinheiro). Repare em Reservar e Liberar: as regras de estoque moram aqui, não no serviço.

LojaApi.Modules.Catalogo/Domain/Produto.cs (Aggregate Root) 
using LojaApi.Shared.Kernel;

namespace LojaApi.Modules.Catalogo.Domain;

/// <summary>
/// 🧠 AGGREGATE ROOT do Catálogo: o produto e o seu estoque, com reserva em duas fases
/// (reservar → confirmar, ou reservar → liberar).
/// Setters privados: nada muda sem passar pelas regras abaixo.
/// </summary>
public class Produto : AggregateRoot
{
    public int Id { get; private set; }
    public string Nome { get; private set; } = string.Empty;
    public Dinheiro Preco { get; private set; } = Dinheiro.Zero;   // Value Object do Shared Kernel
    public int Estoque { get; private set; }
    public int Reservado { get; private set; }

    /// <summary>Disponível = estoque total − reservado (calculado; não vai para o banco).</summary>
    public int Disponivel => Estoque - Reservado;

    /// <summary>Construtor vazio para o EF Core.</summary>
    protected Produto() { }

    /// <summary>Produto NOVO: as regras do contrato (nome 2–100, preço &gt; 0, estoque ≥ 0). O id vem do banco.</summary>
    public static Produto Criar(string nome, decimal preco, int estoque)
    {
        Validar(nome, preco, estoque);
        return new Produto { Nome = nome.Trim(), Preco = new Dinheiro(preco), Estoque = estoque };
    }

    /// <summary>Produto que JÁ existe (banco, documento da Tab 9-B ou teste): sem validação de criação.</summary>
    public static Produto Reconstituir(int id, string nome, decimal preco, int estoque, int reservado)
        => new() { Id = id, Nome = nome, Preco = new Dinheiro(preco), Estoque = estoque, Reservado = reservado };

    /// <summary>PUT: as mesmas regras do Criar, e o estoque não pode ficar abaixo do reservado.</summary>
    public void Atualizar(string nome, decimal preco, int estoque)
    {
        Validar(nome, preco, estoque);
        if (estoque < Reservado)
            throw new DomainException($"Estoque não pode ficar abaixo do reservado ({Reservado})", ProblemTypes.Conflito);
        Nome = nome.Trim();
        Preco = new Dinheiro(preco);
        Estoque = estoque;
    }

    /// <summary>
    /// Reserva unidades. Sem disponível suficiente → 409 estoque-insuficiente.
    /// (No banco, a MESMA regra roda como um UPDATE atômico: ver IProdutoRepository.)
    /// </summary>
    public void Reservar(int qtd)
    {
        ValidarQuantidade(qtd);
        if (Disponivel < qtd)
            throw new DomainException($"Produto {Id}: pedido {qtd}, disponível {Disponivel}", ProblemTypes.EstoqueInsuficiente);
        Reservado += qtd;
    }

    /// <summary>Devolve unidades reservadas (compensação). Nunca fica negativo.</summary>
    public void Liberar(int qtd)
    {
        ValidarQuantidade(qtd);
        Reservado = Math.Max(0, Reservado - qtd);
    }

    /// <summary>A venda se concretizou: sai do estoque e da reserva.</summary>
    public void ConfirmarReserva(int qtd)
    {
        Estoque -= qtd;
        Liberar(qtd);
    }

    public static void ValidarQuantidade(int qtd)
    {
        if (qtd <= 0) throw new DomainException("Quantidade deve ser maior que zero");
    }

    private static void Validar(string nome, decimal preco, int estoque)
    {
        if (string.IsNullOrWhiteSpace(nome) || nome.Trim().Length < 2)
            throw new DomainException("Nome deve ter pelo menos 2 caracteres");
        if (nome.Trim().Length > 100)
            throw new DomainException("Nome deve ter no máximo 100 caracteres");
        if (preco <= 0)
            throw new DomainException("Preço deve ser maior que zero");
        if (estoque < 0)
            throw new DomainException("Estoque não pode ser negativo");
    }
}

LojaApi.Modules.Catalogo/Application/ProdutoService.cs (os casos de uso) 
using LojaApi.Modules.Catalogo.Domain;
using LojaApi.Shared.Kernel;

namespace LojaApi.Modules.Catalogo.Application;

/// <summary>
/// ⚙️ CASOS DE USO do Catálogo. Orquestra: valida a entrada, chama o domínio (as regras)
/// e a porta IProdutoRepository (o banco). Não conhece HTTP nem EF Core.
/// </summary>
public class ProdutoService : IProdutoService
{
    private readonly IProdutoRepository _repo;

    public ProdutoService(IProdutoRepository repo) { _repo = repo; }

    public async Task<IReadOnlyList<ProdutoResponse>> ListarAsync(int page, int size, CancellationToken ct = default)
    {
        if (page < 0) throw new DomainException("page deve ser maior ou igual a 0");
        if (size is < 1 or > 100) throw new DomainException("size deve estar entre 1 e 100");
        return (await _repo.ListarAsync(page, size, ct)).Select(ProdutoResponse.De).ToList();
    }

    public async Task<ProdutoResponse> ObterAsync(int id, CancellationToken ct = default)
        => ProdutoResponse.De(await Buscar(id, ct));

    /// <summary>As regras estão em Produto.Criar; o retorno da porta traz o id gerado.</summary>
    public async Task<ProdutoResponse> CriarAsync(ProdutoRequest req, CancellationToken ct = default)
        => ProdutoResponse.De(await _repo.AdicionarAsync(Produto.Criar(req.Nome, req.Preco, req.Estoque), ct));

    /// <summary>As regras rodam no domínio (Atualizar) e só então o banco grava.</summary>
    public async Task<ProdutoResponse> AtualizarAsync(int id, ProdutoRequest req, CancellationToken ct = default)
    {
        var p = await Buscar(id, ct);
        p.Atualizar(req.Nome, req.Preco, req.Estoque);
        if (!await _repo.AtualizarDadosAsync(p, ct)) throw NaoExiste(id);   // apagado no meio do caminho
        return ProdutoResponse.De(p);
    }

    public async Task ExcluirAsync(int id, CancellationToken ct = default)
    {
        if (!await _repo.RemoverAsync(id, ct)) throw NaoExiste(id);
    }

    /// <summary>Rota interna (Pedidos): a regra é a de Produto.Reservar, executada pelo banco num passo só.</summary>
    public async Task<ReservaResponse> ReservarAsync(int id, ReservarRequest req, CancellationToken ct = default)
    {
        Produto.ValidarQuantidade(req.Quantidade);
        var r = await _repo.TentarReservarAsync(id, req.Quantidade, ct);
        return r.Status switch
        {
            StatusReserva.Reservado => new ReservaResponse(Guid.NewGuid().ToString("N")[..8], "RESERVADO", r.PrecoUnitario),
            StatusReserva.ProdutoInexistente => throw NaoExiste(id),
            _ => throw new DomainException($"Produto {id}: não há {req.Quantidade} unidade(s) disponível(is)",
                                           ProblemTypes.EstoqueInsuficiente)
        };
    }

    /// <summary>
    /// Compensação. Produto que não existe mais → nada a fazer: liberar é "devolver se houver"
    /// (idempotente), e o contrato não prevê 404 aqui.
    /// </summary>
    public async Task LiberarAsync(int id, ReservarRequest req, CancellationToken ct = default)
    {
        Produto.ValidarQuantidade(req.Quantidade);
        await _repo.LiberarAsync(id, req.Quantidade, ct);
    }

    private async Task<Produto> Buscar(int id, CancellationToken ct) => await _repo.ObterAsync(id, ct) ?? throw NaoExiste(id);
    private static NaoEncontradoException NaoExiste(int id) => new($"O produto {id} não existe.");
}

LojaApi.Modules.Catalogo/Infrastructure/EfProdutoRepository.cs (o adapter MySQL — reserva atômica) 
using LojaApi.Modules.Catalogo.Domain;
using Microsoft.EntityFrameworkCore;

namespace LojaApi.Modules.Catalogo.Infrastructure;

/// <summary>
/// 🔌 ADAPTER EF Core + MySQL da porta IProdutoRepository.
/// As escritas usam ExecuteUpdate/ExecuteDelete: viram UM comando SQL, sem
/// carregar a linha antes — é isso que torna a reserva atômica.
/// </summary>
public class EfProdutoRepository : IProdutoRepository
{
    private readonly CatalogoDbContext _db;

    public EfProdutoRepository(CatalogoDbContext db) { _db = db; }

    /// <summary>SELECT … ORDER BY id LIMIT size OFFSET page*size</summary>
    public async Task<IReadOnlyList<Produto>> ListarAsync(int page, int size, CancellationToken ct = default)
        => await _db.Produtos.AsNoTracking().OrderBy(p => p.Id).Skip(page * size).Take(size).ToListAsync(ct);

    public Task<Produto?> ObterAsync(int id, CancellationToken ct = default)
        => _db.Produtos.AsNoTracking().FirstOrDefaultAsync(p => p.Id == id, ct);

    /// <summary>INSERT; o AUTO_INCREMENT preenche o Id do próprio objeto.</summary>
    public async Task<Produto> AdicionarAsync(Produto produto, CancellationToken ct = default)
    {
        _db.Produtos.Add(produto);
        await _db.SaveChangesAsync(ct);
        return produto;
    }

    /// <summary>UPDATE produtos SET nome=…, preco=…, estoque=… WHERE id=… ("reservado" fica de fora)</summary>
    public async Task<bool> AtualizarDadosAsync(Produto produto, CancellationToken ct = default)
        => await _db.Produtos.Where(p => p.Id == produto.Id)
               .ExecuteUpdateAsync(s => s
                   .SetProperty(p => p.Nome, produto.Nome)
                   .SetProperty(p => p.Preco, produto.Preco)
                   .SetProperty(p => p.Estoque, produto.Estoque), ct) > 0;

    public async Task<bool> RemoverAsync(int id, CancellationToken ct = default)
        => await _db.Produtos.Where(p => p.Id == id).ExecuteDeleteAsync(ct) > 0;

    /// <summary>
    /// ⚛️ RESERVA ATÔMICA — um UPDATE condicional:
    ///   UPDATE produtos SET reservado = reservado + @q
    ///   WHERE id = @id AND estoque - reservado &gt;= @q
    /// Duas requisições disputando a última unidade: o banco executa uma de cada vez,
    /// e a 2ª não casa mais o WHERE (0 linhas) → estoque insuficiente.
    /// </summary>
    public async Task<ResultadoReserva> TentarReservarAsync(int id, int quantidade, CancellationToken ct = default)
    {
        var linhas = await _db.Produtos
            .Where(p => p.Id == id && p.Estoque - p.Reservado >= quantidade)
            .ExecuteUpdateAsync(s => s.SetProperty(p => p.Reservado, p => p.Reservado + quantidade), ct);

        // 2ª consulta: o preço (para o snapshot do pedido) — ou descobrir POR QUE não reservou
        var preco = await _db.Produtos.AsNoTracking().Where(p => p.Id == id).Select(p => p.Preco).FirstOrDefaultAsync(ct);

        if (linhas == 1) return new ResultadoReserva(StatusReserva.Reservado, preco!.Valor);
        return new ResultadoReserva(preco is null ? StatusReserva.ProdutoInexistente : StatusReserva.EstoqueInsuficiente);
    }

    /// <summary>UPDATE produtos SET reservado = GREATEST(reservado - @q, 0) WHERE id = @id</summary>
    public async Task<bool> LiberarAsync(int id, int quantidade, CancellationToken ct = default)
        => await _db.Produtos.Where(p => p.Id == id)
               .ExecuteUpdateAsync(s => s.SetProperty(
                   p => p.Reservado,
                   p => p.Reservado - quantidade < 0 ? 0 : p.Reservado - quantidade), ct) > 0;
}

/// <summary>Status do pedido (máquina de estados).</summary>
public enum PedidoStatus { CRIADO, RESERVADO, CONFIRMADO, ENVIADO, CANCELADO }

/// <summary>Item do pedido, com o preço COPIADO do Catálogo no momento da compra (snapshot).</summary>
public class ItemPedido
{
    public int ProdutoId { get; private set; }
    public int Quantidade { get; private set; }
    public Dinheiro PrecoUnitario { get; private set; } = Dinheiro.Zero;   // Value Object
    public Dinheiro Subtotal => PrecoUnitario * Quantidade;

    /// <summary>Construtor vazio para o EF Core.</summary>
    protected ItemPedido() { }

    public ItemPedido(int produtoId, int quantidade, decimal precoUnitario)
    {
        if (quantidade < 1) throw new DomainException("A quantidade de cada item deve ser maior que zero");
        ProdutoId = produtoId;
        Quantidade = quantidade;
        PrecoUnitario = new Dinheiro(precoUnitario);
    }
}

/// <summary>
/// 🧠 AGGREGATE ROOT de Pedidos, com máquina de estados:
///   CRIADO → RESERVADO → CONFIRMADO → ENVIADO
///        ↘ CANCELADO (só antes de CONFIRMADO)
/// </summary>
public class Pedido : AggregateRoot
{
    public int Id { get; private set; }

    /// <summary>Login de quem comprou (claim "login" do JWT) — o "usuario" do contrato.</summary>
    public string Usuario { get; private set; } = string.Empty;
    public int ClienteId { get; private set; }
    public int EnderecoId { get; private set; }
    public PedidoStatus Status { get; private set; } = PedidoStatus.CRIADO;
    public List<ItemPedido> Itens { get; private set; } = new();

    /// <summary>Ids das reservas no Catálogo (o MySQL não guarda; o MongoDB da Tab 9-B guarda).</summary>
    public List<string> ReservaIds { get; private set; } = new();

    /// <summary>Soma de preço × quantidade de cada item.</summary>
    public Dinheiro Total => Itens.Aggregate(Dinheiro.Zero, (soma, i) => soma + i.Subtotal);

    /// <summary>Construtor vazio para o EF Core.</summary>
    protected Pedido() { }

    /// <summary>Pedido NOVO. O id vem do banco ao salvar.</summary>
    public static Pedido Criar(string usuario, int clienteId, int enderecoId, IEnumerable<ItemPedido> itens)
    {
        var p = new Pedido { Usuario = usuario, ClienteId = clienteId, EnderecoId = enderecoId };
        p.Itens.AddRange(itens);
        if (p.Itens.Count == 0) throw new DomainException("O pedido precisa de pelo menos 1 item");
        return p;
    }

    /// <summary>Pedido que JÁ existe (banco, documento da Tab 9-B ou teste).</summary>
    public static Pedido Reconstituir(int id, string usuario, int clienteId, int enderecoId, PedidoStatus status,
                                      IEnumerable<ItemPedido> itens, IEnumerable<string>? reservaIds = null)
        => new()
        {
            Id = id, Usuario = usuario, ClienteId = clienteId, EnderecoId = enderecoId, Status = status,
            Itens = itens.ToList(), ReservaIds = reservaIds?.ToList() ?? new()
        };

    public void MarcarReservado(IEnumerable<string> reservaIds)
    {
        if (Status != PedidoStatus.CRIADO)
            throw new DomainException("Transição inválida para RESERVADO", ProblemTypes.Conflito);
        ReservaIds.AddRange(reservaIds);
        Status = PedidoStatus.RESERVADO;
    }

    /// <summary>
    /// Depois de salvo (agora o pedido TEM id): registra o evento de domínio.
    /// Registrar antes de salvar sairia com id 0.
    /// </summary>
    public void ConfirmarCriacao()
    {
        if (Id == 0) throw new InvalidOperationException("Salve o pedido antes de confirmar a criação");
        Registrar(new PedidoCriadoEvent(Id, Usuario, Total.Valor, DateTime.UtcNow));
    }

    /// <summary>Cancelar CONFIRMADO, ENVIADO ou já CANCELADO → 409 (cancelar 2x liberaria o estoque 2x).</summary>
    public void Cancelar()
    {
        if (Status is PedidoStatus.CONFIRMADO or PedidoStatus.ENVIADO or PedidoStatus.CANCELADO)
            throw new DomainException($"Pedido {Status} não pode ser cancelado", ProblemTypes.Conflito);
        Status = PedidoStatus.CANCELADO;
    }
}

LojaApi.Modules.Pedidos/Application/PedidoService.cs (orquestração + compensação) 
using LojaApi.Modules.Pedidos.Domain;
using LojaApi.Shared.Kernel;

namespace LojaApi.Modules.Pedidos.Application;

/// <summary>
/// ⚙️ Caso de uso "fazer pedido": orquestra DOIS outros contextos por portas.
///
///   1) valida o pedido (antes de reservar qualquer coisa);
///   2) Catálogo: reserva cada item e guarda o preço do momento (snapshot);
///   3) Clientes: confere se o endereço é do cliente;
///   4) salva o pedido como RESERVADO e registra o evento PedidoCriado.
///
/// Se QUALQUER passo falhar depois de reservar algo, as reservas feitas são
/// LIBERADAS (compensação, uma "saga" simples). Assim o estoque não fica preso.
/// Só conhece interfaces: nos testes, as três viram mocks.
/// </summary>
public class PedidoService : IPedidoService
{
    private readonly ICatalogoClient _catalogo;
    private readonly IClientesClient _clientes;
    private readonly IPedidoRepository _pedidos;

    public PedidoService(ICatalogoClient catalogo, IClientesClient clientes, IPedidoRepository pedidos)
    {
        _catalogo = catalogo;
        _clientes = clientes;
        _pedidos = pedidos;
    }

    public async Task<PedidoResponse> CriarAsync(PedidoRequest req, string usuario, CancellationToken ct = default)
    {
        // 1) Regras do contrato ANTES de chamar outro contexto (minItems 1, quantidade ≥ 1)
        if (req.Itens is null || req.Itens.Count == 0)
            throw new DomainException("O pedido precisa de pelo menos 1 item");
        if (req.Itens.Any(i => i.Quantidade < 1))
            throw new DomainException("A quantidade de cada item deve ser maior que zero");

        var reservas = new List<(int ProdutoId, ReservarDto Dto, string ReservaId)>();
        try
        {
            // 2) Catálogo: reserva item a item
            var itens = new List<ItemPedido>();
            foreach (var item in req.Itens)
            {
                var dto = new ReservarDto(item.Quantidade, $"PED-{usuario}-{DateTime.UtcNow:HHmmss}");
                var r = await _catalogo.ReservarAsync(item.ProdutoId, dto, ct);
                reservas.Add((item.ProdutoId, dto, r.ReservaId));
                itens.Add(new ItemPedido(item.ProdutoId, item.Quantidade, r.PrecoUnitario));   // snapshot do preço
            }

            // 3) Clientes: o endereço precisa ser deste cliente
            var enderecos = await _clientes.ObterEnderecosAsync(req.ClienteId, ct);
            if (!enderecos.Any(e => e.Id == req.EnderecoId))
                throw new DomainException($"O endereço {req.EnderecoId} não é do cliente {req.ClienteId}");

            // 4) Domínio + banco + evento
            var pedido = Pedido.Criar(usuario, req.ClienteId, req.EnderecoId, itens);
            pedido.MarcarReservado(reservas.Select(r => r.ReservaId));
            var salvo = await _pedidos.AdicionarAsync(pedido, ct);   // o retorno traz o id
            salvo.ConfirmarCriacao();                                // agora sim: PedidoCriado com o id certo
            return PedidoResponse.De(salvo);
        }
        catch
        {
            // Compensação: devolve TUDO o que já tinha sido reservado, e relança o erro original
            foreach (var (produtoId, dto, _) in reservas)
                await _catalogo.LiberarAsync(produtoId, dto, ct);
            throw;
        }
    }

    public async Task<IReadOnlyList<PedidoResponse>> MeusAsync(string usuario, CancellationToken ct = default)
        => (await _pedidos.ListarPorUsuarioAsync(usuario, ct)).Select(PedidoResponse.De).ToList();

    /// <summary>
    /// Cancela e devolve o estoque. Pedido inexistente OU de outra pessoa → 404
    /// (responder 403 confirmaria que o pedido existe). Já enviado/cancelado → 409.
    /// </summary>
    public async Task CancelarAsync(int pedidoId, string usuario, CancellationToken ct = default)
    {
        var p = await _pedidos.ObterAsync(pedidoId, ct);
        if (p is null || p.Usuario != usuario)
            throw new NaoEncontradoException($"O pedido {pedidoId} não existe.");

        p.Cancelar();                                    // regra de estado (409 se não pode)
        foreach (var i in p.Itens)
            await _catalogo.LiberarAsync(i.ProdutoId, new ReservarDto(i.Quantidade, $"PED-{pedidoId}"), ct);
        await _pedidos.AtualizarStatusAsync(pedidoId, p.Status, ct);
    }
}

👉 O adapter HTTP da porta ICatalogoClient: chama as rotas do Catálogo, espera no máximo 2 s e traduz a resposta para o erro do contrato: sem estoque → 409; produto que não existe → 400 (para quem faz o pedido, é um dado inválido); sem resposta → 503.

LojaApi.Modules.Pedidos/Infrastructure/CatalogoClient.cs (o adapter HTTP) 
using LojaApi.Modules.Pedidos.Application;
using LojaApi.Shared.Kernel;
using System.Net.Http.Json;

namespace LojaApi.Modules.Pedidos.Infrastructure;

/// <summary>
/// Adapter HTTP: timeout 2s, erros 409/503 mapeados
/// para DomainException tipada.
/// </summary>
public class CatalogoClient : ICatalogoClient
{
    // HttpClient injetado via AddHttpClient
    private readonly HttpClient _http;

    /// <summary>Construtor com configuração de timeout.</summary>
    public CatalogoClient(HttpClient http)
    {
        _http = http;

        // Timeout curto: 2 segundos
        _http.Timeout = TimeSpan.FromSeconds(2);
    }

    /// <summary>Reserva estoque no Catálogo.</summary>
    public async Task<ReservaDto> ReservarAsync(
        int produtoId,
        ReservarDto dto,
        CancellationToken ct = default)
    {
        // Faz POST para o endpoint de reserva
        // Timeout (2s) ou falha de rede → 503 tipado
        HttpResponseMessage resp;
        try
        {
            resp = await _http.PostAsJsonAsync(
                $"/api/catalogo/produtos/{produtoId}/reservar",
                dto,
                ct);
        }
        catch (Exception ex) when (ex is HttpRequestException or TaskCanceledException)
        {
            throw new DomainException(
                $"Catálogo indisponível ({ex.GetType().Name})",
                ProblemTypes.DependenciaIndisponivel);
        }

        // Traduz a resposta do Catálogo para o erro certo do contrato de PEDIDOS:
        //   409 → 409 estoque-insuficiente (repassa o detalhe: "pedido 999, disponível 8")
        //   404 → 400 validação (para quem faz o pedido, é um produtoId inválido)
        //   400 → 400 validação
        //   qualquer outro erro → 503 (o Catálogo não conseguiu responder)
        if (!resp.IsSuccessStatusCode)
        {
            var detalhe = await DetalheAsync(resp, ct);
            throw (int)resp.StatusCode switch
            {
                409 => new DomainException(detalhe ?? $"Estoque insuficiente p/ produto {produtoId}",
                                           ProblemTypes.EstoqueInsuficiente),
                404 => new DomainException($"O produto {produtoId} não existe"),
                400 => new DomainException(detalhe ?? "Item inválido"),
                _   => new DomainException($"Catálogo indisponível ({(int)resp.StatusCode})",
                                           ProblemTypes.DependenciaIndisponivel)
            };
        }

        // Desserializa resposta
        return (await resp.Content.ReadFromJsonAsync<ReservaDto>(ct))!;
    }

    /// <summary>Libera estoque reservado (compensação best-effort).</summary>
    public async Task LiberarAsync(
        int produtoId,
        ReservarDto dto,
        CancellationToken ct = default)
    {
        try
        {
            // Faz POST para o endpoint de liberação
            await _http.PostAsJsonAsync(
                $"/api/catalogo/produtos/{produtoId}/liberar",
                dto,
                ct);
        }
        catch
        {
            // Compensação best-effort:
            // em prod, log + fila de reconciliação
        }
    }

    /// <summary>Lê o "detail" do problem+json do Catálogo (null se não houver).</summary>
    private static async Task<string?> DetalheAsync(HttpResponseMessage resp, CancellationToken ct)
    {
        try
        {
            var corpo = await resp.Content.ReadFromJsonAsync<Dictionary<string, object>>(ct);
            return corpo is not null && corpo.TryGetValue("detail", out var d) ? d?.ToString() : null;
        }
        catch { return null; }
    }
}

/// <summary>
/// Repassa o header Authorization da request original para as chamadas
/// HTTP internas (Pedidos → Catálogo/Clientes).
/// Sem isso, /reservar e /enderecos (que exigem [Authorize]) respondem 401
/// e o checkout falha com 503 "dependência indisponível".
/// </summary>
public class BearerTokenForwardingHandler : DelegatingHandler
{
    // Acesso à request HTTP atual (a que chegou no PedidosController)
    private readonly IHttpContextAccessor _accessor;

    /// <summary>Injeção de dependência via construtor.</summary>
    public BearerTokenForwardingHandler(IHttpContextAccessor accessor)
    {
        _accessor = accessor;
    }

    /// <summary>Copia o "Authorization: Bearer ..." antes de enviar.</summary>
    protected override Task<HttpResponseMessage> SendAsync(
        HttpRequestMessage request,
        CancellationToken ct)
    {
        // Lê o header da request original (se houver)
        var auth = _accessor.HttpContext?.Request.Headers.Authorization.ToString();

        // Repassa apenas se ainda não foi definido
        if (!string.IsNullOrWhiteSpace(auth) && request.Headers.Authorization is null)
            request.Headers.TryAddWithoutValidation("Authorization", auth);

        return base.SendAsync(request, ct);
    }
}

using LojaApi.Shared.Kernel;
using System.Text.RegularExpressions;

namespace LojaApi.Modules.Clientes.Domain;

/// <summary>
/// 📧 VALUE OBJECT "Email": se existe, é válido. A regra (formato, sem espaços,
/// minúsculas) mora aqui, e não espalhada por controller, serviço e banco.
/// </summary>
public sealed record Email
{
    public string Valor { get; }

    public Email(string valor)
    {
        var v = (valor ?? "").Trim().ToLowerInvariant();
        if (!Regex.IsMatch(v, @"^[^@\s]+@[^@\s]+\.[^@\s]+$"))
            throw new DomainException($"E-mail inválido: {valor}");
        Valor = v;
    }

    public override string ToString() => Valor;
}

/// <summary>
/// 📮 VALUE OBJECT "Cep": aceita "01001000" ou "01001-000" e guarda SEMPRE "01001-000".
/// </summary>
public sealed record Cep
{
    public string Valor { get; }

    public Cep(string valor)
    {
        var digitos = Regex.Replace(valor ?? "", @"[^0-9]", "");
        if (valor is null || !Regex.IsMatch(valor.Trim(), @"^[0-9]{5}-?[0-9]{3}$"))
            throw new DomainException($"CEP inválido: {valor}");
        Valor = $"{digitos[..5]}-{digitos[5..]}";
    }

    public override string ToString() => Valor;
}

using LojaApi.Modules.Clientes.Domain;
using LojaApi.Shared.Kernel;

namespace LojaApi.Modules.Clientes.Application;

/// <summary>⚙️ CASOS DE USO de Clientes: domínio (regras) + porta IClienteRepository (banco).</summary>
public class ClienteService : IClienteService
{
    private readonly IClienteRepository _repo;

    public ClienteService(IClienteRepository repo) { _repo = repo; }

    /// <summary>Cliente + endereços numa tacada só. Cada endereço é validado ao ser criado.</summary>
    public async Task<ClienteResponse> CriarAsync(ClienteRequest req, CancellationToken ct = default)
    {
        var enderecos = (req.Enderecos ?? new())
            .Select(e => new Endereco(0, e.Logradouro, e.Cidade, e.Uf, e.Cep))
            .ToList();
        var c = await _repo.AdicionarAsync(Cliente.Criar(req.Nome, req.Email, enderecos), ct);   // o retorno traz os ids
        return ClienteResponse.De(c);
    }

    public async Task<ClienteResponse> ObterAsync(int id, CancellationToken ct = default)
        => ClienteResponse.De(await Buscar(id, ct));

    public async Task<ClienteResponse> AtualizarAsync(int id, AtualizarClienteRequest req, CancellationToken ct = default)
    {
        var c = await Buscar(id, ct);
        c.Atualizar(req.Nome, req.Email);                            // regras no domínio…
        if (!await _repo.AtualizarDadosAsync(c, ct)) throw NaoExiste(id);   // …e só então o banco grava
        return ClienteResponse.De(c);
    }

    public async Task<ClienteResponse> DesativarAsync(int id, CancellationToken ct = default)
    {
        var c = await Buscar(id, ct);
        c.Desativar();                                               // 409 se já estava desativado
        if (!await _repo.AtualizarDadosAsync(c, ct)) throw NaoExiste(id);
        return ClienteResponse.De(c);
    }

    /// <summary>Rota interna (chamada por Pedidos).</summary>
    public async Task<IReadOnlyList<EnderecoResponse>> EnderecosAsync(int id, CancellationToken ct = default)
    {
        if (!await _repo.ExisteAsync(id, ct)) throw NaoExiste(id);
        return (await _repo.ListarEnderecosAsync(id, ct)).Select(EnderecoResponse.De).ToList();
    }

    private async Task<Cliente> Buscar(int id, CancellationToken ct) => await _repo.ObterAsync(id, ct) ?? throw NaoExiste(id);
    private static NaoEncontradoException NaoExiste(int id) => new($"O cliente {id} não existe.");
}

using LojaApi.Modules.Clientes.Domain;

namespace LojaApi.Modules.Clientes.Infrastructure;

/// <summary>🔌 ADAPTER EF Core + MySQL da porta IClienteRepository.</summary>
public class EfClienteRepository : IClienteRepository
{
    private readonly ClientesDbContext _db;

    public EfClienteRepository(ClientesDbContext db) { _db = db; }

    /// <summary>INSERT do cliente e dos endereços numa transação só (o SaveChanges faz as duas).</summary>
    public async Task<Cliente> AdicionarAsync(Cliente cliente, CancellationToken ct = default)
    {
        _db.Clientes.Add(cliente);
        await _db.SaveChangesAsync(ct);
        return cliente;
    }

    /// <summary>SELECT … JOIN enderecos (o Include traz os endereços junto)</summary>
    public Task<Cliente?> ObterAsync(int id, CancellationToken ct = default)
        => _db.Clientes.AsNoTracking().Include(c => c.Enderecos).FirstOrDefaultAsync(c => c.Id == id, ct);

    /// <summary>UPDATE clientes SET nome=…, email=…, ativo=… WHERE id=…</summary>
    public async Task<bool> AtualizarDadosAsync(Cliente cliente, CancellationToken ct = default)
        => await _db.Clientes.Where(c => c.Id == cliente.Id)
               .ExecuteUpdateAsync(s => s
                   .SetProperty(c => c.Nome, cliente.Nome)
                   .SetProperty(c => c.Email, cliente.Email)
                   .SetProperty(c => c.Ativo, cliente.Ativo), ct) > 0;

    public Task<bool> ExisteAsync(int id, CancellationToken ct = default)
        => _db.Clientes.AnyAsync(c => c.Id == id, ct);

    public async Task<IReadOnlyList<Endereco>> ListarEnderecosAsync(int clienteId, CancellationToken ct = default)
        => await _db.Clientes.AsNoTracking()
               .Where(c => c.Id == clienteId)
               .SelectMany(c => c.Enderecos)
               .OrderBy(e => e.Id)
               .ToListAsync(ct);
}

👉 Pega qualquer erro de qualquer módulo e responde problem+json com o type e o status do contrato.

LojaApi.Api/Middleware/ExceptionMiddleware.cs (RFC 7807) 
using LojaApi.Shared.Kernel;
using System.Text.Json;

namespace LojaApi.Api.Middleware;

/// <summary>
/// Tratamento CENTRALIZADO de erros: toda exceção vira RFC 7807 (application/problem+json)
/// com os "type" do contrato da Tab 8. O status vem do type (ProblemTypes.StatusDe):
///   validacao 400 · nao-encontrado 404 · conflito / estoque-insuficiente 409 ·
///   dependencia-indisponivel 503 · qualquer outra exceção → 500 (detalhe só no log).
/// </summary>
public class ExceptionMiddleware
{
    private readonly RequestDelegate _next;
    private readonly ILogger<ExceptionMiddleware> _log;

    public ExceptionMiddleware(RequestDelegate next, ILogger<ExceptionMiddleware> log)
    { _next = next; _log = log; }

    public async Task Invoke(HttpContext ctx)
    {
        try { await _next(ctx); }
        catch (DomainException ex)
        {
            await Escrever(ctx, ProblemTypes.StatusDe(ex.Type), ex.Type, ProblemTypes.TituloDe(ex.Type), ex.Message);
        }
        catch (Exception ex)
        {
            _log.LogError(ex, "Erro inesperado");   // o detalhe vai para o log, nunca para o cliente
            await Escrever(ctx, 500, "https://example.com/erros/interno", "Erro interno",
                           "Algo deu errado. Tente novamente.");
        }
    }

    private static Task Escrever(HttpContext ctx, int status, string type, string title, string detail)
    {
        ctx.Response.StatusCode = status;
        ctx.Response.ContentType = "application/problem+json";
        return ctx.Response.WriteAsync(JsonSerializer.Serialize(new { type, title, status, detail }));
    }
}
