⓪ ☕ Conhecendo o Java (5 minutos de leitura)

Em uma frase: Java é uma linguagem de programação criada em 1995 pela Sun Microsystems (hoje da Oracle), feita para que o mesmo programa rode em qualquer computador. O lema dela era "escreva uma vez, rode em qualquer lugar".

Como o seu código vira programa

O computador não entende Java direto. O código passa por duas etapas: o compilador traduz o seu texto para bytecode, e a JVM (a "máquina virtual do Java") executa esse bytecode em qualquer sistema — Windows, Mac ou Linux. No IntelliJ, as duas etapas acontecem com um clique no ▶.

② 👋 Laboratório 1: seu primeiro programa em Java (Hello World)

Objetivo: criar, rodar e entender seu primeiro programa em Java. Ele escreve uma mensagem, pergunta seu nome e responde — tudo na janela de baixo do IntelliJ. Tempo: ~30 minutos.

📦 E o ZIP? O botão acima baixa os dois laboratórios prontos, para você conferir o seu com o gabarito. Mas, para aprender, faça os passos: é digitando e errando que a coisa entra na cabeça.

3🖱️ Escrever e rodar o Hello World

O exemplo que o IntelliJ criou traz mais coisa do que precisamos agora. Clique no editor, apague tudo (Ctrl+A seleciona tudo, Delete apaga) e digite (de preferência digitando, não colando):

    }

  1. Repare que, ao lado da linha public static void main, na margem esquerda do editor, aparece um ▶ verde. Clique nele → Run 'Main.main()' ("rodar"). Atalho: Shift+F10 (no Mac, Ctrl+R).
  2. Espere alguns segundos. O painel Run abre embaixo e mostra:

🎉 Parabéns: você rodou seu primeiro programa em Java! Por trás do clique, o Java compilou (traduziu o seu texto para bytecode, uma linguagem que a máquina do Java entende) e executou. O "exit code 0" ("código de saída 0") quer dizer que o programa terminou sem erro.

Lendo o código, pedaço por pedaço:

PedaçoO que significa

🧪 Experimente agora: troque "Hello World!" por "Olá! Meu nome é ..." com o seu nome e rode de novo (▶ ou Shift+F10). O IntelliJ salva sozinho — não precisa de Ctrl+S (diferente do VS Code da Tab 3).

✋Errou? Ótimo: veja como o IntelliJ avisa

Errar faz parte — e a IDE ajuda a achar o erro. Faça de propósito: apague o ; do final da linha do println e clique no ▶.

  1. Leia a mensagem do painel Build: ela diz o que falta e em que linha.
  2. Dê dois cliques na mensagem: o cursor vai direto para a linha do erro.
  3. Pare o mouse sobre o risquinho vermelho, ou aperte Alt+Enter: o IntelliJ sugere a correção.
  4. Devolva o ; e rode de novo.
✅ Resultado esperado: o vermelho some, o ❗ vira ✓ e o programa volta a mostrar Hello World!.
⚠️ Erro comum: "Unsupported JDK" / "Cannot compile module … configured for JVM target 21". Quer dizer que o projeto pede o Java 21, mas o IntelliJ está usando outro (por exemplo, o 17). Acontece muito ao abrir projetos baixados (como os ZIPs do guia). Correção com o mouse: File → Project Structure… (Ctrl+Alt+Shift+S) → Project → SDK → escolha um 21 (ou Download JDK… → 21) → OK.

4Fazer o programa conversar com você — em 4 etapas

Agora você vai construir um programa que pergunta seu nome e responde. Por partes: a cada etapa você acrescenta poucas linhas, roda e vê o que mudou. As linhas novas estão marcadas com // ← NOVO.

Etapa A — escrever duas linhas

hello-java/src/Main.java — etapa A 
public class Main {
    public static void main(String[] args) {
        System.out.println("Hello World!");
        System.out.println("Estou aprendendo Java.");   // ← NOVO
    }
}

Rode. Aparecem duas linhas, na ordem em que você escreveu: o programa lê o código de cima para baixo, uma instrução de cada vez.

💡 Enquanto você digita: o IntelliJ sugere o resto da palavra numa listinha (é o autocompletar) — aperte Enter para aceitar. Atalho de ouro: digite sout e aperte Tab: vira System.out.println(); sozinho. E se algo estiver errado, aparece um sublinhado vermelho — pare o mouse em cima para ler o erro.

Etapa B — perguntar o nome e guardar a resposta

hello-java/src/Main.java — etapa B 
import java.util.Scanner;                                   // ← NOVO

    public static void main(String[] args) {
        System.out.println("Hello World!");
        System.out.println("Estou aprendendo Java.");

        Scanner teclado = new Scanner(System.in);           // ← NOVO

Gabarito: o programa completo, comentado

Compare com o seu. Este é o arquivo que vem no ZIP — com comentários explicando cada linha e 3 desafios no final.

hello-java/src/Main.java (gabarito comentado) 
// ════════════════════════════════════════════════════════════════════════════
//  Main.java — seu primeiro programa em Java (aplicativo de console, Java 21)
//
//  Como ler: o programa começa no método 'main' e roda de CIMA para BAIXO,
//  uma linha de cada vez. Tudo o que começa com // é COMENTÁRIO: o
//  computador ignora, é só para você.
// ════════════════════════════════════════════════════════════════════════════

// 'import' traz uma ferramenta pronta do Java para este arquivo.
// Scanner é a ferramenta que LÊ o que você digita no teclado.
import java.util.Scanner;

// Em Java, todo código mora dentro de uma CLASSE. O nome da classe precisa
// ser IGUAL ao nome do arquivo: classe Main → arquivo Main.java.
public class Main {

    // 'main' é a PORTA DE ENTRADA: é por aqui que o Java começa a rodar.
    // Essa linha é sempre igual — por enquanto, aceite-a como uma fórmula:
    //   public  = pode ser chamado de fora (pelo próprio Java)
    //   static  = não precisa criar nada antes para chamar
    //   void    = não devolve resultado nenhum
    //   String[] args = argumentos da linha de comando (não usamos aqui)
    public static void main(String[] args) {

        // ── 1) ESCREVER NA TELA ─────────────────────────────────────────────
        // System.out = a saída do programa (a janela de baixo do IntelliJ)
        // println    = "imprima esta linha e pule para a próxima"
        // "..."      = um TEXTO (uma "String"), sempre entre aspas duplas
        // ;          = o ponto final do Java: toda instrução termina com ele
        System.out.println("Hello World!");

        // ── 2) PERGUNTAR E GUARDAR A RESPOSTA ──────────────────────────────
        // Cria o "leitor de teclado". System.in = a ENTRADA (o teclado).
        Scanner teclado = new Scanner(System.in);

        // print (sem "ln") escreve SEM pular linha: o cursor fica esperando
        // logo depois da pergunta.
        System.out.print("Qual é o seu nome? ");

        // nextLine() espera você digitar e apertar Enter. O texto digitado
        // vai para dentro de uma VARIÁVEL chamada 'nome', do tipo String.
        String nome = teclado.nextLine();

        // ── 3) TOMAR UMA DECISÃO ───────────────────────────────────────────
        // if = "se". isBlank() pergunta: "o texto está vazio ou só tem espaços?"
        // Se sim, trocamos por "visitante" para a frase não sair estranha.
        if (nome.isBlank()) {
            nome = "visitante";
        }

        // ── 4) USAR NÚMEROS ─────────────────────────────────────────────────
        // int = número inteiro. Year.now() é o ano atual do seu computador.
        int ano = java.time.Year.now().getValue();

        // ── 5) MONTAR UMA FRASE COM VARIÁVEIS ──────────────────────────────
        // O + JUNTA textos (e números) numa frase só.
        System.out.println("Olá, " + nome + "! Bem-vindo ao Java em " + ano + ".");

        // .length() = quantos caracteres o texto tem (espaços contam).
        System.out.println("Seu nome tem " + nome.length() + " caracteres.");
    }
}

// ════════════════════════════════════════════════════════════════════════════
//  DESAFIOS (tente sozinho e rode de novo com o ▶ verde):
//   1. Pergunte também a cidade e mostre: "Ana, de Recife".
//   2. Pergunte o ano em que a pessoa nasceu e calcule a idade.
//      Dica: int nascimento = Integer.parseInt(teclado.nextLine());
//   3. Se o nome tiver mais de 10 letras, escreva "Que nome comprido!".
// ════════════════════════════════════════════════════════════════════════════
⚠️ Erros comuns (e o que fazer):
  • ';' expected → faltou o ; no fim de uma linha. O IntelliJ sublinha de vermelho o lugar exato; o painel mostra o número da linha.
  • cannot find symbol → um nome escrito diferente. Java diferencia maiúsculas de minúsculas: nome ≠ Nome, system ≠ System.
  • class Main is public, should be declared in a file named Main.java → o nome da classe e o do arquivo estão diferentes. Os dois precisam ser iguais.
  • unclosed string literal → abriu aspas e esqueceu de fechar.
  • "O programa travou depois da pergunta" → não travou: está esperando você digitar no painel Run e apertar Enter.
  • O ▶ verde não aparece / "Project JDK is not defined" → falta o Java no projeto: clique no aviso amarelo no topo do editor → Setup SDK → escolha o 21 (ou Download JDK…, como no passo 2).

    // controle ao Spring, que liga o servidor e fica esperando pedidos.

        SpringApplication.run(HelloSpringApplication.class, args);
    }
}

3🖱️ Criar o controller (as rotas da API)

  1. Na coluna Project, clique com o botão direito no pacote com.example.hello → New → Package ("pacote") → digite controller → Enter. Um pacote é uma pasta de código para organizar as classes.
  2. Botão direito no novo pacote controller → New → Java Class → digite HelloController → Enter. O IntelliJ cria o arquivo já com a linha package e a classe vazia.
  3. Apague tudo, copie o código abaixo (botão 📋 Copiar) e cole (Ctrl+V). Desta vez pode colar: o importante é ler os comentários — eles explicam cada linha.
hello-spring/src/main/java/com/example/hello/controller/HelloController.java 
package com.example.hello.controller;   // ← "filho" de com.example.hello: o Spring encontra

import org.springframework.http.ResponseEntity;
import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.PathVariable;
import org.springframework.web.bind.annotation.RestController;

import java.time.Instant;
import java.util.List;
import java.util.Map;

// ════════════════════════════════════════════════════════════════════════════
//  HelloController.java — as ROTAS da API (o arquivo que você cria).
//
//  As palavras com @ na frente são ANOTAÇÕES: etiquetas que avisam o Spring
//  "trate esta classe/método de um jeito especial". Você não chama esses
//  métodos: quem chama é o Spring, quando chega um pedido no endereço certo.
// ════════════════════════════════════════════════════════════════════════════

// @RestController = "esta classe atende pedidos HTTP e responde em JSON".
// Tudo o que um método devolver é convertido para JSON automaticamente.
@RestController
public class HelloController {

    // @GetMapping("/") = "quando alguém pedir GET /, chame este método".
    // Map.of(...) monta pares "nome" → valor, que viram um JSON.
    @GetMapping("/")
    public Map<String, Object> raiz() {
        return Map.of(
            "status", "API Spring Boot no ar",
            "rotas", List.of("GET /hello", "GET /hello/{nome}")
        );
    }

    // GET /hello — o "smoke test": se isto responde, o ambiente está pronto.
    @GetMapping("/hello")
    public Map<String, Object> hello() {
        return Map.of(
            "mensagem", "Hello World com Spring Boot 4 + Java 21!",
            // Qual "trabalhador" (thread) atendeu este pedido. Repare no valor:
            // na parte ④ você liga as Virtual Threads e ele muda.
            "thread", Thread.currentThread().toString(),
            // Instant.now() = agora, em UTC (sem fuso: o fuso é de quem exibe).
            "horarioUtc", Instant.now().toString()
        );
    }

    // {nome} é um PARÂMETRO DE ROTA: em GET /hello/Ana, o Spring entrega "Ana"
    // no parâmetro 'nome' — é o que a anotação @PathVariable faz.
    @GetMapping("/hello/{nome}")
    public ResponseEntity<Map<String, String>> helloNome(@PathVariable String nome) {
        // Igual ao Lab 1: uma decisão com if. Nome gigante é recusado com
        // 400 Bad Request ("pedido inválido"). ResponseEntity deixa escolher
        // o código HTTP da resposta — sem ele, seria sempre 200 OK.
        if (nome.length() > 30) {
            return ResponseEntity.badRequest()
                    .body(Map.of("erro", "Nome deve ter no máximo 30 caracteres"));
        }
        return ResponseEntity.ok(
                Map.of("mensagem", "Olá, " + nome + "! Sua API Spring Boot está funcionando."));
    }
}
🔗 Repare na ligação com o Lab 1: a rota /hello/{nome} faz o mesmo que o seu "qual é o seu nome?" — só que o nome vem no endereço (/hello/Ana) em vez de ser digitado. E as mesmas peças aparecem: if, .length(), "Olá, " + nome.

JVM, JDK e JRE

O Java não roda direto no Windows ou no Mac: ele roda dentro de uma máquina virtual, a JVM. Quando você clica no ▶, o seu .java é traduzido para bytecode (arquivos .class), que a JVM executa. É por isso que o mesmo programa Java roda em qualquer sistema: cada sistema tem a sua JVM.

SiglaNomeO que éQuem precisa

O Eclipse Temurin que você escolheu é uma das "marcas" do JDK — todas seguem a mesma especificação. Usamos o Java 21 porque é LTS (suporte de longo prazo) e é o mesmo das Tabs 6 e 6-B. Já existe o Java 25, LTS mais novo; o 21 continua com correções por vários anos.

🧵 Virtual Threads — veja com os próprios olhos

Uma thread é um "trabalhador" que atende um pedido. As threads tradicionais são caras (cerca de 1 MB de memória cada), então um servidor tem poucas — e, se todas ficarem esperando o banco de dados responder, os pedidos novos fazem fila. As Virtual Threads (Java 21) são levíssimas (poucos KB): dá para ter milhões. Quando uma delas fica esperando, a JVM a "estaciona" e libera o trabalhador de verdade para outro pedido.

  1. Abra o application.yml (pasta src/main/resources). Se ele estiver vazio ou só com o nome da aplicação, cole o conteúdo abaixo.
  2. Troque enabled: false por enabled: true. Cuidado com o recuo: são 2 espaços por nível, nunca Tab.
  3. Desligue (⏹) e ligue (▶) a API, e abra http://localhost:8080/hello de novo.
hello-spring/src/main/resources/application.yml (troque false por true) 
# ─────────────────────────────────────────────────────────────
#  application.yml — as configurações da API (formato YAML).
#  O RECUO importa: são 2 espaços por nível, nunca Tab.
# ─────────────────────────────────────────────────────────────
spring:
  application:
    name: hello-spring

  # Parte ④ da aba — Virtual Threads (Java 21):
  # troque false por true, salve, reinicie a API e chame /hello de novo.
  # O campo "thread" passa de "Thread[#..,http-nio-8080-exec-1,...]"
  # para "VirtualThread[#..]/runnable@ForkJoinPool-1-worker-1".
  threads:
    virtual:
      enabled: false

server:
  port: 8080      # a porta da API. Se a 8080 estiver ocupada, troque (ex.: 8081)
enabledO campo "thread" mostraQuem atendeu o pedido
falseThread[#45,http-nio-8080-exec-1,5,main]Uma thread tradicional, de um grupo fixo do Tomcat
trueVirtualThread[#52]/runnable@ForkJoinPool-1-worker-1Uma virtual thread, criada só para este pedido

Numa API pequena como esta não há diferença de velocidade. O ganho aparece com muitos pedidos ao mesmo tempo que esperam algo lento (banco de dados, outra API) — exatamente o caso das Tabs 6 e 9.

⑤ 🔀 Guardar seu código no GitHub (pelo IntelliJ)

🔀 O que é Git? E o GitHub?

Git é um programa que guarda o histórico do seu código: cada vez que você "salva uma versão" (um commit), ele tira uma foto do projeto. Dá para ver o que mudou, quando e por quê — e voltar a qualquer foto antiga. Analogia: é o "salvar jogo" do código, com uma legenda em cada ponto de salvamento.

O GitHub é um site que guarda uma cópia desse histórico na nuvem: seu código fica seguro mesmo se o computador quebrar, e outras pessoas podem ver e colaborar. O GitLab é um site parecido, muito usado em empresas.

  • Repositório (repo): o projeto + todo o histórico.
  • Commit: uma "foto" das mudanças, com uma mensagem explicando o que foi feito.
  • Push: enviar seus commits para o site. Pull: trazer de lá o que mudou.
  • Branch: uma linha paralela de trabalho (ex.: feat/novo-endpoint); main é a principal.
  • Pull Request (PR): pedido para alguém revisar seu branch antes de juntá-lo ao main.

1🖱️ Criar a conta no GitHub (e o Git, se faltar)

  1. Conta: entre em github.com → Sign up ("cadastrar") → e-mail, senha e nome de usuário → confirme o código que chega no e-mail. É gratuito.
  2. Git: o IntelliJ avisa se ele não estiver instalado. No Windows, quando aparecer "Git is not installed", clique em Download and Install e o IntelliJ instala para você. (Ou baixe em git-scm.com e clique Next em todas as telas. Se você fez a Tab 3, já tem.)

2🖱️ Publicar a API no GitHub

  1. Com o projeto hello-spring aberto, no menu do topo: Git → GitHub → Share Project on GitHub ("compartilhar projeto no GitHub"). (Se o menu Git não aparecer, procure VCS no mesmo lugar, ou aperte Shift duas vezes e digite Share Project on GitHub.)
  2. Na primeira vez, ele pede para entrar na conta: Log In via GitHub… → o navegador abre o GitHub → faça login → Authorize JetBrains ("autorizar") → volte ao IntelliJ.
  3. Na janela Share Project On GitHub: Repository name = hello-spring · marque Private ("privado", só você vê) se quiser · Share ("compartilhar").
  4. Se pedir nome e e-mail do Git ("Git User Name Is Not Defined"), preencha com os seus dados — use o mesmo e-mail da conta do GitHub. Isso aparece uma vez só.
  5. Janela Add Files For Initial Commit ("arquivos para o primeiro commit"): confira que as pastas target e .idea estão desmarcadas (veja o aviso abaixo) → Add.
  6. No canto de baixo aparece "Successfully shared project on GitHub" com o link: clique e veja seu código na nuvem. 🎉
⚠️ Por que não enviar target/ e .idea/? A target é gerada pelo Maven toda vez que o programa roda; a .idea guarda as preferências do seu IntelliJ. Enviá-las só deixa o repositório pesado e causa conflito entre colegas. O Initializr já gera um .gitignore (a lista do que o Git ignora) que barra as duas; o do ZIP é uma versão curta e comentada:
hello-spring/.gitignore (o que o Git deve ignorar) 
# ─────────────────────────────────────────────────────────────
#  O que o Git deve IGNORAR (versão curta e comentada).
# ─────────────────────────────────────────────────────────────

# Saída do build do Maven: é gerada de novo a cada execução.
target/

# Configurações pessoais do IntelliJ (cada dev tem as suas)
.idea/
*.iml

# Logs e segredos locais NUNCA vão para o Git
*.log
.env

3🖱️ O dia a dia: mudar, fazer commit, enviar

  1. Altere algum arquivo (ex.: mude a mensagem do /hello). Na coluna Project, o nome do arquivo fica azul = modificado.
  2. Abra a janela Commit: ícone na barra da esquerda, ou Ctrl+K (no Mac, Cmd+K). O arquivo aparece em Changes ("alterações"); dê dois cliques nele para ver antes e depois lado a lado.
  3. Deixe o arquivo marcado ☑ e escreva a mensagem na caixa de baixo, ex.: feat: muda a mensagem do hello.
  4. Clique em Commit and Push… ("fazer commit e enviar") → na janela seguinte, Push. Pronto: está no GitHub.
✍️ Mensagem de commit: o prefixo diz o tipo da mudança — feat: coisa nova, fix: correção, docs: documentação. É o padrão Conventional Commits, usado em todo o guia.
👥 Em equipe: ninguém faz commit direto no main. Cada tarefa ganha um branch: clique no nome do branch no topo da janela (ao lado do nome do projeto, mostra main) → New Branch… → nome, ex.: feat/novo-endpoint → Create. Faça os commits nele, envie com Push e, no site do GitHub, abra um Pull Request para alguém revisar antes de juntar ao main.
⌨️ Prefere o terminal? O mesmo fluxo com comandos git

Crie antes, no site, um repositório vazio chamado hello-spring (sem README). No terminal do IntelliJ (Alt+F12):

terminal — primeiro envio 
git config --global user.name "Seu Nome"      # uma vez por computador
git config --global user.email "seu@email.com"

git init -b main                  # cria o repositório já com o branch 'main'
git add .                         # inclui os arquivos (o .gitignore barra target/ e .idea/)
git commit -m "feat: hello spring boot"
git remote add origin https://github.com/SEU-USUARIO/hello-spring.git
git push -u origin main           # envia; nos próximos, basta 'git push'
terminal — dia a dia com branch e PR 
git switch main && git pull                  # começa do main atualizado
git switch -c feat/novo-endpoint             # cria o branch da tarefa
git status                                   # quais arquivos mudaram
git diff                                     # o que mudou dentro deles
git add src/main/java/com/example/hello/controller/HelloController.java
git commit -m "feat: adiciona endpoint /hello/{nome}"
git push -u origin feat/novo-endpoint        # depois, abra o PR no site

⚠️ src refspec main does not match any? O branch se chama master: rode git branch -M main e repita o push. No primeiro push por HTTPS, o Git abre o navegador para você entrar no GitHub. A configuração com chave SSH está na Tab 3, no mesmo bloco "⌨️".
