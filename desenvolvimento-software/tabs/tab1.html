① 🍽️ Front-end × Back-end: a analogia do restaurante

Todo site ou aplicativo tem duas metades. Pense num restaurante:

No restauranteNo softwareO que fazExemplos
🪑 Salão, cardápio, mesasFront-endO que a pessoa vê e toca: telas, botões, coresO site da loja no navegador, o app no celular
🧾 A comanda que o garçom levaAPIO jeito combinado de fazer um pedido e receber a resposta"Me dê os produtos em promoção"
👨‍🍳 CozinhaBack-endOnde o pedido é preparado: regras, cálculos, segurançaCalcular o frete, conferir a senha, aplicar o desconto
🥫 DespensaBanco de dadosOnde tudo fica guardado, organizado e sem perder nadaClientes, produtos, pedidos, estoque
👨‍🍳
O cliente nunca entra na cozinha. Ele vê o salão e recebe o prato pronto. Do mesmo jeito, quem usa um app nunca vê o back-end — mas é lá que acontece quase todo o trabalho. Este guia ensina a construir a cozinha.

📐 O caminho de um pedido

O front-end fica na sua mão (no navegador ou no celular). O back-end e o banco ficam num servidor — um computador ligado 24 horas, geralmente na "nuvem" (num data center de empresas como Amazon, Microsoft ou Google).

② 🛒 O que acontece quando você clica em "Finalizar compra"

Leva menos de um segundo — mas, por trás, o back-end faz tudo isto:

  1. O app envia um pedido para a API da loja: "o cliente 42 quer comprar 1 fone, código 7, e pagar com cartão".
  2. O back-end confere quem é você: você está logado de verdade? (Isso é autenticação — a Tab 4 mostra como.)
  3. Consulta o banco de dados: o fone 7 existe? Quanto custa hoje? Tem no estoque?
  4. Aplica as regras do negócio: tem cupom? O frete para o seu CEP é quanto? O cartão foi aprovado?
  5. Grava no banco: cria o pedido nº 1001 e tira 1 fone do estoque — as duas coisas juntas, para nunca vender um fone que não existe.
  6. Avisa outros sistemas: o estoque, a nota fiscal, o e-mail de confirmação. (A Tab 7-B mostra como fazer isso sem perder nenhum aviso.)
  7. Responde ao app: "pedido 1001 confirmado". O app mostra a tela de sucesso. 🎉

📐 A mesma compra, em sequência

💡 Repare: o front-end só pediu e mostrou. Quem decidiu o preço, conferiu o estoque, guardou o pedido e garantiu que nada saísse errado foi o back-end. É por isso que regra importante (preço, permissão, estoque) sempre fica no back-end: o front-end está na mão do usuário, e qualquer um pode mexer nele.

O mesmo Hello World nas três

"Hello World" ("Olá, mundo") é o primeiro programa de quase todo mundo: só escreve uma frase na tela. Compare:

☕ Java 
public class Main {
    public static void main(String[] args) {
        System.out.println("Hello World!");
    }
}
🔷 C# 
Console.WriteLine("Hello World!");
🐍 Python 
print("Hello World!")

Java pede mais "embalagem" (a classe e o main); C# moderno e Python vão direto ao ponto. Mas a ideia é idêntica: "mostre este texto". Quem aprende uma, aprende as outras muito mais rápido.

A mesma API nas três

Agora o mais importante para o back-end: uma API que responde "Olá!" quando alguém acessa o endereço /hello. Mesma ideia, três jeitos de escrever:

☕ Java + Spring Boot (você faz isso na Tab 2) 
@RestController                        // "esta classe atende pedidos da web"
public class HelloController {

    @GetMapping("/hello")              // "quando pedirem /hello..."
    public String hello() {
        return "Olá!";                 // "...responda isto"
    }
}
🔷 C# + ASP.NET Core (você faz isso na Tab 3) 
var app = WebApplication.CreateBuilder(args).Build();

app.MapGet("/hello", () => "Olá!");    // "quando pedirem /hello, responda isto"

app.Run();                             // "fique ligado esperando pedidos"
🐍 Python + FastAPI (só para comparar) 
from fastapi import FastAPI

app = FastAPI()

@app.get("/hello")                     # "quando pedirem /hello..."
def hello():
    return "Olá!"                      # "...responda isto"

"…responda isto"return "Olá!";() => "Olá!"return "Olá!"

🤔 "Qual é a melhor?" Nenhuma. Todas fazem APIs excelentes e têm muitas vagas. O que muda é onde cada uma é mais usada. Este guia usa Java e C# porque são as mais pedidas em vagas de back-end em empresas grandes, e porque, aprendendo uma delas, a outra fica fácil — elas são "primas". Escolha uma para começar e vá até o fim nela.

⑤ 🥫 Banco de dados: onde as informações moram

Um programa, sozinho, esquece tudo quando é desligado. O banco de dados é o programa especializado em guardar informação com segurança: não perde nada se a luz cair, deixa milhares de pessoas lerem e gravarem ao mesmo tempo sem bagunçar, e acha qualquer dado em milissegundos. Pense numa planilha superpoderosa.

Os dois grandes tipos

Como guardaEm tabelas: linhas e colunas, como uma planilhaEm documentos: fichas no formato JSON, cada uma pode ter campos diferentes
AnalogiaUm fichário de gavetas com formulários iguaisUma pasta de fichas livres
Ponto forteRegras rígidas, relações entre os dados, nunca deixa os números baterem erradoFlexível, rápido para dados que mudam de formato
ExemplosMySQL, PostgreSQL, SQL Server, OracleMongoDB, Redis, DynamoDB
Bom paraPedidos, pagamentos, estoque, cadastrosCatálogos, logs, perfis com campos variados

Um produto nos dois jeitos

Relacional: a tabela produtos. Cada linha é um produto; cada coluna, uma informação. O id é a chave: o número único que identifica cada linha.

idnomeprecoestoque
1Teclado349.9050
2Mouse89.9030
7Fone199.003

Para conversar com um banco relacional, usa-se a linguagem SQL. Ela é quase uma frase em inglês:

SQL — "quais produtos custam menos de 100 reais?" 
SELECT nome, preco          -- "mostre o nome e o preço"
FROM produtos               -- "da tabela produtos"
WHERE preco < 100;          -- "só dos que custam menos de 100"

-- Resultado:
-- nome  | preco
-- Mouse | 89.90

NoSQL (MongoDB): o mesmo fone como documento JSON. Repare que ele pode trazer coisas a mais, como a lista de cores, sem precisar de outra tabela:

Documento no MongoDB 
{
  "_id": 7,
  "nome": "Fone",
  "preco": 199.00,
  "estoque": 3,
  "cores": ["preto", "branco"]
}

⑥ 📖 As palavras que você vai ouvir

Não precisa decorar: volte aqui sempre que uma palavra aparecer nas próximas abas. (A Tab 10 tem o glossário completo.)

PalavraO que é, em uma frase
ClienteQuem faz o pedido: o navegador, o app de celular, outro programa.
ServidorQuem responde o pedido: o computador (e o programa) onde o back-end roda.
HTTPO "idioma" que cliente e servidor usam para conversar na web.
APIA porta de entrada do back-end: a lista de pedidos que ele aceita e o formato das respostas.
Endpoint / rotaUm endereço específico da API, como /produtos ou /hello.
JSONO formato de texto mais usado nas respostas: {"nome": "Fone", "preco": 199}.
Código de statusO número que resume a resposta: 200 deu certo, 404 não achei, 500 deu erro no servidor.
FrameworkUm "kit" pronto que faz o trabalho pesado (Spring Boot, ASP.NET Core): você só preenche o que é seu.
Biblioteca / pacoteCódigo pronto, escrito por outras pessoas, que você acrescenta ao seu projeto.
CompilarTraduzir o código que você escreveu para uma forma que o computador executa.
IDEO programa onde você escreve e roda o código: IntelliJ (Java), VS Code (C#).
Git / GitHubGit guarda o histórico do seu código; o GitHub guarda uma cópia na nuvem.
DockerUma "caixa" que leva o programa com tudo de que ele precisa, para rodar igual em qualquer computador.
Nuvem (cloud)Computadores de outra empresa (Amazon, Microsoft, Google) que você aluga para rodar o seu back-end.
Deploy"Colocar no ar": publicar uma versão nova do programa no servidor.
