🏛️ Clean Architecture (Robert C. Martin, 2012)

Origem: consolidou ideias de Hexagonal (Alistair Cockburn, 2005) e Onion Architecture (Jeffrey Palermo, 2008). O princípio central: o que é negócio fica no centro; o que é tecnologia fica na borda.

As 4 camadas (de dentro para fora)

  1. Entities (Domain): regras de negócio puras (nosso Produto POJO — sem anotações de framework).
  2. Use Cases (Application): orquestram as regras (nosso ProdutoServiceImpl).
  3. Interface Adapters: controllers, gateways/repositórios (convertem mundo externo ↔ interno).
  4. Frameworks & Drivers: banco, web, UI, mensageria (Spring, JPA, MySQL).

🔑 A Regra de Dependência

Setas de dependência só apontam para dentro. Camadas internas não conhecem camadas externas. É por isso que ProdutoServiceImpl depende da interface ProdutoRepository, nunca do JPA diretamente.

Aprofundar: Uncle Bob — The Clean Architecture (2012) · Hexagonal (Cockburn) · Onion (Palermo).

import java.math.BigDecimal;

/**
 * Entidade de domínio Produto (POJO puro, anêmico — sem anotações ORM).
 * A lógica de negócio fica no Use Case (ProdutoServiceImpl) — ver ADR-J1.
 *
 * Nenhuma anotação de banco aqui (@Entity, @Id...): o mapeamento MySQL fica
 * em ProdutoJpaEntity. Trocar de banco = trocar o adapter, nunca esta classe.
 *
 * @since 1.0.0
 */
public class Produto {
    private Long id;
    private String nome;
    private BigDecimal preco;
    private Integer estoque;

    public Produto() {}

    /**
     * Construtor completo. Também serve para RECONSTITUIR um produto lido do
     * banco (por isso não valida nada: no modelo anêmico, as regras de criação
     * ficam no ProdutoServiceImpl, e um dado já salvo não é "criado" de novo).
     *
     * @param id null = produto novo (o banco/adapter gera o id)
     */
    public Produto(Long id, String nome, BigDecimal preco, Integer estoque) {
        this.id = id;
        this.nome = nome;
        this.preco = preco;
        this.estoque = estoque;
    }

    public Long getId() { return id; }
    public void setId(Long id) { this.id = id; }
    public String getNome() { return nome; }
    public void setNome(String nome) { this.nome = nome; }
    public BigDecimal getPreco() { return preco; }
    public void setPreco(BigDecimal preco) { this.preco = preco; }
    public Integer getEstoque() { return estoque; }
    public void setEstoque(Integer estoque) { this.estoque = estoque; }
}

package com.loja.domain;

import java.util.List;
import java.util.Optional;

/**
 * 🚪 PORTA DE SAÍDA do domínio (Dependency Inversion Principle).
 * O domínio define O QUE precisa; a infraestrutura decide COMO fazer.
 *
 *   ProdutoRepositoryAdapter → MySQL via JPA (esta Tab 6)
 *
 * ✅ Nenhum tipo de framework na assinatura (nada de Page, Pageable,
 *    Specification do Spring Data): a porta fala a língua do domínio.
 */
public interface ProdutoRepository {

    /**
     * Insere (id == null) ou atualiza (id != null) e DEVOLVE o produto salvo.
     * Use sempre o retorno: é ele que traz o id gerado (AUTO_INCREMENT do MySQL).
     */
    Produto salvar(Produto produto);

    Optional<Produto> buscarPorId(Long id);

    /**
     * Página de produtos ordenada por id (page começa em 0).
     * A paginação acontece NO BANCO (LIMIT/OFFSET no MySQL).
     * Antes, a API carregava TODOS os produtos e cortava a lista em memória:
     * com 1 milhão de produtos, cada GET traria 1 milhão de linhas.
     */
    List<Produto> listarPagina(int page, int size);

    /** Todos os produtos, ordenados por id — uso administrativo (relatórios, cópias). */
    List<Produto> listarTodos();

    boolean existePorId(Long id);

    void deletarPorId(Long id);
}

application/ProdutoServiceImpl.java 
package com.loja.application;

import com.loja.domain.Produto;
import com.loja.domain.ProdutoRepository;
import com.loja.domain.ProdutoService;
import com.loja.domain.exception.DomainException;
import com.loja.domain.exception.RecursoNaoEncontradoException;
import java.math.BigDecimal;
import java.util.List;

/**
 * Implementa os casos de uso. Recebe a INTERFACE ProdutoRepository (DIP).
 * Registrado como bean via CoreBeansConfig (não tem @Service — é classe pura).
 * Ela só conhece a porta ProdutoRepository, nunca o JPA.
 */
public class ProdutoServiceImpl implements ProdutoService {

    /** Limite de itens por página: protege o banco de "size=1000000". */
    static final int TAMANHO_MAXIMO_PAGINA = 100;

    /** Mesmo limite do contrato (maxLength: 100) e da coluna VARCHAR(100). */
    static final int TAMANHO_MAXIMO_NOME = 100;

    private final ProdutoRepository repository;

    public ProdutoServiceImpl(ProdutoRepository repository) {
        this.repository = repository;
    }

    @Override
    public Produto criarProduto(Produto p) {
        validar(p);
        p.setNome(p.getNome().trim());
        p.setId(null);                 // criação: quem gera o id é o banco/adapter
        return repository.salvar(p);   // usa o RETORNO (traz o id gerado)
    }

    @Override
    public List<Produto> listarProdutos(int page, int size) {
        // Validação de entrada: antes, page negativo derrubava a API com erro 500
        if (page < 0)
            throw new DomainException("page deve ser >= 0");
        if (size < 1 || size > TAMANHO_MAXIMO_PAGINA)
            throw new DomainException("size deve estar entre 1 e " + TAMANHO_MAXIMO_PAGINA);

        // Paginação feita NO BANCO, pela porta (não mais em memória)
        return repository.listarPagina(page, size);
    }

    @Override
    public Produto obterPorId(Long id) {
        return repository.buscarPorId(id)
                .orElseThrow(() -> new RecursoNaoEncontradoException("Produto não encontrado: " + id));
    }

    @Override
    public Produto atualizarProduto(Long id, Produto p) {
        Produto existente = obterPorId(id);   // 404 se não existir
        validar(p);
        existente.setNome(p.getNome().trim());
        existente.setPreco(p.getPreco());
        existente.setEstoque(p.getEstoque());
        return repository.salvar(existente);
    }

    @Override
    public void excluirProduto(Long id) {
        if (!repository.existePorId(id))
            throw new RecursoNaoEncontradoException("Produto não encontrado: " + id);
        repository.deletarPorId(id);
    }

    /** Regras de negócio comuns a criar e atualizar (um lugar só = sem duplicação). */
    private static void validar(Produto p) {
        if (p.getNome() == null || p.getNome().trim().isEmpty())
            throw new DomainException("O nome do produto é obrigatório");
        if (p.getNome().trim().length() < 2)
            throw new DomainException("O nome deve ter pelo menos 2 caracteres");
        if (p.getNome().trim().length() > TAMANHO_MAXIMO_NOME)
            throw new DomainException("O nome deve ter no máximo " + TAMANHO_MAXIMO_NOME + " caracteres");
        if (p.getPreco() == null || p.getPreco().compareTo(BigDecimal.ZERO) <= 0)
            throw new DomainException("O preço deve ser maior que zero");
        if (p.getEstoque() == null || p.getEstoque() < 0)
            throw new DomainException("O estoque não pode ser negativo");
    }
}

/**
 * 🔌 ADAPTER JPA/MySQL — implementa a porta do domínio (Hexagonal).
 *
 * Repare: SEM @Repository. É uma classe simples; quem a registra como
 * bean é o PersistenceConfig.

public class ProdutoRepositoryAdapter implements ProdutoRepository {

    private final SpringDataProdutoRepository jpaRepo;

    public ProdutoRepositoryAdapter(SpringDataProdutoRepository jpaRepo) {
        this.jpaRepo = jpaRepo;
    }

    @Override
    public Produto salvar(Produto p) {
        // id null → INSERT (AUTO_INCREMENT gera o id); id preenchido → UPDATE
        return toDomain(jpaRepo.save(toJpa(p)));
    }

    @Override
    public Optional<Produto> buscarPorId(Long id) {
        return jpaRepo.findById(id).map(this::toDomain);
    }

    @Override
    public List<Produto> listarPagina(int page, int size) {
        // SELECT ... ORDER BY id LIMIT :size OFFSET :page*size  (paginação NO BANCO)
        // Ordenar por id: sem ORDER BY, o banco pode devolver as páginas em qualquer ordem.
        return jpaRepo.findAll(PageRequest.of(page, size, Sort.by("id")))
                .getContent().stream().map(this::toDomain).toList();
    }

    @Override
    public List<Produto> listarTodos() {
        return jpaRepo.findAll(Sort.by("id")).stream().map(this::toDomain).toList();
    }

    @Override
    public boolean existePorId(Long id) { return jpaRepo.existsById(id); }

    @Override
    public void deletarPorId(Long id) { jpaRepo.deleteById(id); }

    // ── Conversões domínio ↔ entidade JPA (o domínio nunca vê a @Entity) ──
    private ProdutoJpaEntity toJpa(Produto d) {
        ProdutoJpaEntity e = new ProdutoJpaEntity();
        e.setId(d.getId()); e.setNome(d.getNome()); e.setPreco(d.getPreco()); e.setEstoque(d.getEstoque());
        return e;
    }

    private Produto toDomain(ProdutoJpaEntity e) {
        return new Produto(e.getId(), e.getNome(), e.getPreco(), e.getEstoque());
    }

package com.loja.presentation.security;

import io.jsonwebtoken.Claims;
import io.jsonwebtoken.JwtException;
import io.jsonwebtoken.Jwts;
import io.jsonwebtoken.security.Keys;
import java.nio.charset.StandardCharsets;
import java.util.Date;
import java.util.Optional;
import javax.crypto.SecretKey;
import org.springframework.beans.factory.annotation.Value;
import org.springframework.stereotype.Service;

/**
 * Gera e valida JWT (HMAC-SHA256) com a API do jjwt 0.12.x.
 * (0.11 usava setSubject/parserBuilder/parseClaimsJws — hoje depreciados.)
 */
@Service
public class JwtService {

    private final SecretKey key;
    private final long expirationMs;

    public JwtService(@Value("${jwt.secret}") String secret,
                      @Value("${jwt.expiration}") long expirationMs) {
        // UTF-8 explícito: getBytes() sem charset depende do sistema operacional
        // (a mesma chave poderia gerar bytes diferentes em Windows e Linux).
        // HS256 exige chave de no mínimo 256 bits (32 bytes).
        this.key = Keys.hmacShaKeyFor(secret.getBytes(StandardCharsets.UTF_8));
        this.expirationMs = expirationMs;
    }

    /** O token diz só QUEM é o usuário (sub). Sem papéis/roles nesta aula. */
    public String gerarToken(String email) {
        Date agora = new Date();
        return Jwts.builder()
                .subject(email)                                         // sub
                .issuedAt(agora)                                        // iat
                .expiration(new Date(agora.getTime() + expirationMs))   // exp
                .signWith(key, Jwts.SIG.HS256)
                .compact();
    }

    /**
     * Valida assinatura + expiração e devolve as claims, num ÚNICO parse.
     * (Antes: isTokenValido() + extrairClaims() = o token era verificado 2x.)
     * Token inválido, expirado ou malformado → Optional.empty().
     */
    public Optional<Claims> validar(String token) {
        try {
            return Optional.of(Jwts.parser()
                    .verifyWith(key)
                    .build()
                    .parseSignedClaims(token)
                    .getPayload());
        } catch (JwtException | IllegalArgumentException e) {
            return Optional.empty();
        }
    }

    public long getExpiracaoSegundos() { return expirationMs / 1000; }
}

package com.loja.presentation.security;

import jakarta.servlet.FilterChain;
import jakarta.servlet.ServletException;
import jakarta.servlet.http.HttpServletRequest;
import jakarta.servlet.http.HttpServletResponse;
import java.io.IOException;
import java.util.List;
import org.springframework.security.authentication.UsernamePasswordAuthenticationToken;
import org.springframework.security.core.context.SecurityContextHolder;
import org.springframework.web.filter.OncePerRequestFilter;

/**
 * Lê "Authorization: Bearer ...", valida o token e popula o SecurityContext.
 *
 * NÃO é @Component de propósito: o Spring Boot registra todo Filter que é bean
 * como filtro de servlet GLOBAL — ele rodaria fora da cadeia do Spring Security
 * também. Criado à mão no SecurityConfig, ele existe só dentro da cadeia.
 *
 * Se o token faltar ou for inválido, este filtro NÃO responde nada: ele só
 * deixa a requisição sem autenticação, e o Spring Security decide — endpoint
 * público passa; protegido cai no authenticationEntryPoint (401).
 */
public class JwtTokenFilter extends OncePerRequestFilter {

    private final JwtService jwtService;

    public JwtTokenFilter(JwtService jwtService) { this.jwtService = jwtService; }

    @Override
    protected void doFilterInternal(HttpServletRequest req, HttpServletResponse res, FilterChain chain)
            throws ServletException, IOException {
        String header = req.getHeader("Authorization");
        if (header != null && header.startsWith("Bearer ")) {
            jwtService.validar(header.substring(7)).ifPresent(claims -> {
                // Token válido = usuário autenticado. Lista de permissões vazia:
                // nesta aula não há papéis (roles), só "logado ou não".
                var auth = new UsernamePasswordAuthenticationToken(
                    claims.getSubject(), null, List.of());
                SecurityContextHolder.getContext().setAuthentication(auth);
            });
        }
        chain.doFilter(req, res);
    }
}

package com.loja.presentation.security;

import jakarta.servlet.http.HttpServletResponse;
import java.io.IOException;
import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;
import org.springframework.http.HttpMethod;
import org.springframework.security.config.annotation.web.builders.HttpSecurity;
import org.springframework.security.config.annotation.web.configuration.EnableWebSecurity;
import org.springframework.security.config.http.SessionCreationPolicy;
import org.springframework.security.web.SecurityFilterChain;
import org.springframework.security.web.authentication.UsernamePasswordAuthenticationFilter;

/**
 * Regras de acesso:
 *   /api/auth/**           → público (é o login)
 *   GET /api/produtos/**   → público (leitura do catálogo)
 *   /error                 → público (senão, todo erro viraria 401)
 *   qualquer outra         → exige JWT válido
 */
@Configuration
@EnableWebSecurity   // explícito: garante a cadeia de segurança também nos testes HTTP
public class SecurityConfig {

    @Bean
    public SecurityFilterChain filterChain(HttpSecurity http, JwtService jwtService) throws Exception {
        // Criado aqui (não é bean) → roda só dentro da cadeia do Spring Security
        JwtTokenFilter jwtFilter = new JwtTokenFilter(jwtService);

        return http
            .csrf(c -> c.disable())                       // API stateless com token (sem cookie de sessão)
            .sessionManagement(s -> s.sessionCreationPolicy(SessionCreationPolicy.STATELESS))
            .exceptionHandling(e -> e
                // Sem token / token inválido → 401 (o padrão do Spring seria 403!)
                // type e title iguais ao NaoAutenticado do contrato da Tab 4
                .authenticationEntryPoint((req, res, ex) -> problema(res, 401,
                    "Não autenticado", "Envie o header Authorization: Bearer <token>.",
                    "https://example.com/erros/naoautenticado")))
            .authorizeHttpRequests(a -> a
                .requestMatchers("/api/auth/**", "/error").permitAll()
                .requestMatchers(HttpMethod.GET, "/api/produtos/**").permitAll()
                .anyRequest().authenticated())
            .addFilterBefore(jwtFilter, UsernamePasswordAuthenticationFilter.class)
            .build();
    }

    /** Escreve um application/problem+json (RFC 7807) direto na resposta. */
    private static void problema(HttpServletResponse res, int status, String title,
                                 String detail, String type) throws IOException {
        res.setStatus(status);
        res.setContentType("application/problem+json");
        res.setCharacterEncoding("UTF-8");
        res.getWriter().write(
            "{\"type\":\"" + type + "\",\"title\":\"" + title + "\",\"status\":" + status
            + ",\"detail\":\"" + detail + "\"}");
    }
}

package com.loja.presentation.exception;

import com.loja.domain.exception.DomainException;

import java.net.URI;
import java.util.stream.Collectors;
import org.springframework.http.*;
import org.springframework.http.converter.HttpMessageNotReadableException;
import org.springframework.web.bind.MethodArgumentNotValidException;
import org.springframework.web.bind.annotation.*;
import org.springframework.web.method.annotation.MethodArgumentTypeMismatchException;

/**
 * Captura exceções e retorna RFC 7807 (application/problem+json).
 * O Spring escolhe o handler MAIS ESPECÍFICO: RecursoNaoEncontradoException
 * (subclasse) vai para o 404, as demais DomainException para o 400.
 * Os "type" e "title" são os MESMOS do contrato da Tab 4:
 *   400 → erros/validacao · 401 → erros/naoautenticado · 404 → erros/naoencontrado
 */
@RestControllerAdvice
public class GlobalExceptionHandler {

    /** 404 — recurso inexistente (GET/PUT/DELETE de id que não existe). */
    @ExceptionHandler(RecursoNaoEncontradoException.class)
    public ResponseEntity<ProblemDetail> handleNotFound(RecursoNaoEncontradoException ex) {
        return problema(HttpStatus.NOT_FOUND, "https://example.com/erros/naoencontrado",
                "Não encontrado", ex.getMessage());
    }

    /** 400 — regra de negócio violada (para o cliente, é dado inválido do mesmo jeito). */
    @ExceptionHandler(DomainException.class)
    public ResponseEntity<ProblemDetail> handleDomain(DomainException ex) {
        return problema(HttpStatus.BAD_REQUEST, "https://example.com/erros/validacao",
                "Requisição inválida", ex.getMessage());
    }

    /** 400 — Bean Validation (@Valid no DTO). */
    @ExceptionHandler(MethodArgumentNotValidException.class)
    public ResponseEntity<ProblemDetail> handleValidation(MethodArgumentNotValidException ex) {
        String detail = ex.getBindingResult().getFieldErrors().stream()
                .map(fe -> fe.getField() + ": " + fe.getDefaultMessage())
                .collect(Collectors.joining("; "));
        return problema(HttpStatus.BAD_REQUEST, "https://example.com/erros/validacao",
                "Requisição inválida", detail);
    }

    /** 400 — JSON malformado no corpo. */
    @ExceptionHandler(HttpMessageNotReadableException.class)
    public ResponseEntity<ProblemDetail> handleJsonInvalido(HttpMessageNotReadableException ex) {
        return problema(HttpStatus.BAD_REQUEST, "https://example.com/erros/validacao",
                "Requisição inválida", "Corpo JSON malformado");
    }

    /** 400 — parâmetro com tipo errado (ex.: /api/produtos/abc). */
    @ExceptionHandler(MethodArgumentTypeMismatchException.class)
    public ResponseEntity<ProblemDetail> handleTipo(MethodArgumentTypeMismatchException ex) {
        return problema(HttpStatus.BAD_REQUEST, "https://example.com/erros/validacao",
                "Requisição inválida", "Parâmetro '" + ex.getName() + "' com formato inválido");

        pd.setTitle(title);
        return ResponseEntity.status(status)
                .contentType(MediaType.APPLICATION_PROBLEM_JSON)
                .body(pd);
    }

🔑 JWT na prática (Java): quem faz o quê

  1. Emissão — JwtService.gerarToken(): monta as claims (sub = e-mail, iat, exp) — sem papéis (roles): nesta aula basta saber se a pessoa está logada — e assina com HS256 usando o secret vindo de ${jwt.secret}.
  2. Verificação — JwtTokenFilter: em toda request, lê Authorization: Bearer …, valida assinatura/expiração num único parse e popula o SecurityContext. Se o token faltar ou for inválido, o filtro não responde: a request segue sem autenticação e, se o endpoint for protegido, o authenticationEntryPoint responde 401 problem+json (sem ele, o Spring responderia 403).
  3. Fio condutor — SecurityConfig: cria o filtro (ele não é @Component, para não ser registrado também como filtro global do servlet), sessão STATELESS, libera /api/auth/**, /error e GETs de produtos, exige auth no resto.
  4. Secret: vem de ${jwt.secret} no application.yml em dev; em produção use variável de ambiente (export JWT_SECRET=…) ou secret manager — nunca commitado.

📄 Os arquivos do Maven Wrapper (mvnw, mvnw.cmd, maven-wrapper.properties) — gerados, não precisa ler

O Maven Wrapper é um script que baixa a versão certa do Maven na 1ª execução (fica em ~/.m2/wrapper). Assim todo mundo — você, o colega e o CI — usa o mesmo Maven, sem instalar nada. São os arquivos oficiais do Apache Maven Wrapper 3.3.2 (tipo only-script).

# Optional ENV vars
# -----------------
#   JAVA_HOME - location of a JDK home dir, required when download maven via java source
#   MVNW_REPOURL - repo url base for downloading maven distribution
#   MVNW_USERNAME/MVNW_PASSWORD - user and password for downloading maven

set -euf
[ "${MVNW_VERBOSE-}" != debug ] || set -x

# OS specific support.
native_path() { printf %s\\n "$1"; }
case "$(uname)" in
CYGWIN* | MINGW*)
  [ -z "${JAVA_HOME-}" ] || JAVA_HOME="$(cygpath --unix "$JAVA_HOME")"
  native_path() { cygpath --path --windows "$1"; }
  ;;
esac

# set JAVACMD and JAVACCMD
set_java_home() {
  # For Cygwin and MinGW, ensure paths are in Unix format before anything is touched
  if [ -n "${JAVA_HOME-}" ]; then
    if [ -x "$JAVA_HOME/jre/sh/java" ]; then
      # IBM's JDK on AIX uses strange locations for the executables
      JAVACMD="$JAVA_HOME/jre/sh/java"
      JAVACCMD="$JAVA_HOME/jre/sh/javac"
    else
      JAVACMD="$JAVA_HOME/bin/java"
      JAVACCMD="$JAVA_HOME/bin/javac"

      if [ ! -x "$JAVACMD" ] || [ ! -x "$JAVACCMD" ]; then
        echo "The JAVA_HOME environment variable is not defined correctly, so mvnw cannot run." >&2
        echo "JAVA_HOME is set to \"$JAVA_HOME\", but \"\$JAVA_HOME/bin/java\" or \"\$JAVA_HOME/bin/javac\" does not exist." >&2
        return 1
      fi
    fi
  else
    JAVACMD="$(
      'set' +e
      'unset' -f command 2>/dev/null
      'command' -v java
    )" || :
    JAVACCMD="$(
      'set' +e
      'unset' -f command 2>/dev/null
      'command' -v javac
    )" || :

    if [ ! -x "${JAVACMD-}" ] || [ ! -x "${JAVACCMD-}" ]; then
      echo "The java/javac command does not exist in PATH nor is JAVA_HOME set, so mvnw cannot run." >&2
      return 1
    fi
  fi
}

# hash string like Java String::hashCode
hash_string() {
  str="${1:-}" h=0
  while [ -n "$str" ]; do
    char="${str%"${str#?}"}"
    h=$(((h * 31 + $(LC_CTYPE=C printf %d "'$char")) % 4294967296))
    str="${str#?}"
  done
  printf %x\\n $h
}

verbose() { :; }
[ "${MVNW_VERBOSE-}" != true ] || verbose() { printf %s\\n "${1-}"; }

die() {
  printf %s\\n "$1" >&2
  exit 1
}

trim() {
  # MWRAPPER-139:
  #   Trims trailing and leading whitespace, carriage returns, tabs, and linefeeds.
  #   Needed for removing poorly interpreted newline sequences when running in more
  #   exotic environments such as mingw bash on Windows.
  printf "%s" "${1}" | tr -d '[:space:]'
}

# parse distributionUrl and optional distributionSha256Sum, requires .mvn/wrapper/maven-wrapper.properties
while IFS="=" read -r key value; do
  case "${key-}" in
  distributionUrl) distributionUrl=$(trim "${value-}") ;;
  distributionSha256Sum) distributionSha256Sum=$(trim "${value-}") ;;
  esac
done <"${0%/*}/.mvn/wrapper/maven-wrapper.properties"
[ -n "${distributionUrl-}" ] || die "cannot read distributionUrl property in ${0%/*}/.mvn/wrapper/maven-wrapper.properties"

case "${distributionUrl##*/}" in
maven-mvnd-*bin.*)
  MVN_CMD=mvnd.sh _MVNW_REPO_PATTERN=/maven/mvnd/
  case "${PROCESSOR_ARCHITECTURE-}${PROCESSOR_ARCHITEW6432-}:$(uname -a)" in
  *AMD64:CYGWIN* | *AMD64:MINGW*) distributionPlatform=windows-amd64 ;;
  :Darwin*x86_64) distributionPlatform=darwin-amd64 ;;
  :Darwin*arm64) distributionPlatform=darwin-aarch64 ;;
  :Linux*x86_64*) distributionPlatform=linux-amd64 ;;
  *)
    echo "Cannot detect native platform for mvnd on $(uname)-$(uname -m), use pure java version" >&2
    distributionPlatform=linux-amd64
    ;;
  esac
  distributionUrl="${distributionUrl%-bin.*}-$distributionPlatform.zip"
  ;;
maven-mvnd-*) MVN_CMD=mvnd.sh _MVNW_REPO_PATTERN=/maven/mvnd/ ;;
*) MVN_CMD="mvn${0##*/mvnw}" _MVNW_REPO_PATTERN=/org/apache/maven/ ;;
esac

# apply MVNW_REPOURL and calculate MAVEN_HOME
# maven home pattern: ~/.m2/wrapper/dists/{apache-maven-<version>,maven-mvnd-<version>-<platform>}/<hash>
[ -z "${MVNW_REPOURL-}" ] || distributionUrl="$MVNW_REPOURL$_MVNW_REPO_PATTERN${distributionUrl#*"$_MVNW_REPO_PATTERN"}"
distributionUrlName="${distributionUrl##*/}"
distributionUrlNameMain="${distributionUrlName%.*}"
distributionUrlNameMain="${distributionUrlNameMain%-bin}"
MAVEN_USER_HOME="${MAVEN_USER_HOME:-${HOME}/.m2}"
MAVEN_HOME="${MAVEN_USER_HOME}/wrapper/dists/${distributionUrlNameMain-}/$(hash_string "$distributionUrl")"

exec_maven() {
  unset MVNW_VERBOSE MVNW_USERNAME MVNW_PASSWORD MVNW_REPOURL || :
  exec "$MAVEN_HOME/bin/$MVN_CMD" "$@" || die "cannot exec $MAVEN_HOME/bin/$MVN_CMD"
}

  verbose "found existing MAVEN_HOME at $MAVEN_HOME"
  exec_maven "$@"
fi

*?-bin.zip | *?maven-mvnd-?*-?*.zip) ;;
*) die "distributionUrl is not valid, must match *-bin.zip or maven-mvnd-*.zip, but found '${distributionUrl-}'" ;;
esac

  clean() { rm -rf -- "$TMP_DOWNLOAD_DIR"; }
  trap clean HUP INT TERM EXIT
else
  die "cannot create temp dir"
fi

mkdir -p -- "${MAVEN_HOME%/*}"

verbose "Downloading from: $distributionUrl"
verbose "Downloading to: $TMP_DOWNLOAD_DIR/$distributionUrlName"

# select .zip or .tar.gz
if ! command -v unzip >/dev/null; then
  distributionUrl="${distributionUrl%.zip}.tar.gz"
  distributionUrlName="${distributionUrl##*/}"
fi

# verbose opt
__MVNW_QUIET_WGET=--quiet __MVNW_QUIET_CURL=--silent __MVNW_QUIET_UNZIP=-q __MVNW_QUIET_TAR=''
[ "${MVNW_VERBOSE-}" != true ] || __MVNW_QUIET_WGET='' __MVNW_QUIET_CURL='' __MVNW_QUIET_UNZIP='' __MVNW_QUIET_TAR=v

# normalize http auth
case "${MVNW_PASSWORD:+has-password}" in
'') MVNW_USERNAME='' MVNW_PASSWORD='' ;;
has-password) [ -n "${MVNW_USERNAME-}" ] || MVNW_USERNAME='' MVNW_PASSWORD='' ;;
esac

if [ -z "${MVNW_USERNAME-}" ] && command -v wget >/dev/null; then
  verbose "Found wget ... using wget"
  wget ${__MVNW_QUIET_WGET:+"$__MVNW_QUIET_WGET"} "$distributionUrl" -O "$TMP_DOWNLOAD_DIR/$distributionUrlName" || die "wget: Failed to fetch $distributionUrl"
elif [ -z "${MVNW_USERNAME-}" ] && command -v curl >/dev/null; then
  verbose "Found curl ... using curl"
  curl ${__MVNW_QUIET_CURL:+"$__MVNW_QUIET_CURL"} -f -L -o "$TMP_DOWNLOAD_DIR/$distributionUrlName" "$distributionUrl" || die "curl: Failed to fetch $distributionUrl"
elif set_java_home; then
  verbose "Falling back to use Java to download"
  javaSource="$TMP_DOWNLOAD_DIR/Downloader.java"
  targetZip="$TMP_DOWNLOAD_DIR/$distributionUrlName"
  cat >"$javaSource" <<-END
	public class Downloader extends java.net.Authenticator
	{
	  protected java.net.PasswordAuthentication getPasswordAuthentication()
	  {
	    return new java.net.PasswordAuthentication( System.getenv( "MVNW_USERNAME" ), System.getenv( "MVNW_PASSWORD" ).toCharArray() );
	  }
	  public static void main( String[] args ) throws Exception
	  {
	    setDefault( new Downloader() );
	    java.nio.file.Files.copy( java.net.URI.create( args[0] ).toURL().openStream(), java.nio.file.Paths.get( args[1] ).toAbsolutePath().normalize() );
	  }
	}
	END
  # For Cygwin/MinGW, switch paths to Windows format before running javac and java
  verbose " - Compiling Downloader.java ..."
  "$(native_path "$JAVACCMD")" "$(native_path "$javaSource")" || die "Failed to compile Downloader.java"
  verbose " - Running Downloader.java ..."
  "$(native_path "$JAVACMD")" -cp "$(native_path "$TMP_DOWNLOAD_DIR")" Downloader "$distributionUrl" "$(native_path "$targetZip")"
fi

# If specified, validate the SHA-256 sum of the Maven distribution zip file
if [ -n "${distributionSha256Sum-}" ]; then
  distributionSha256Result=false
  if [ "$MVN_CMD" = mvnd.sh ]; then
    echo "Checksum validation is not supported for maven-mvnd." >&2
    echo "Please disable validation by removing 'distributionSha256Sum' from your maven-wrapper.properties." >&2
    exit 1
  elif command -v sha256sum >/dev/null; then
    if echo "$distributionSha256Sum  $TMP_DOWNLOAD_DIR/$distributionUrlName" | sha256sum -c >/dev/null 2>&1; then
      distributionSha256Result=true
    fi
  elif command -v shasum >/dev/null; then
    if echo "$distributionSha256Sum  $TMP_DOWNLOAD_DIR/$distributionUrlName" | shasum -a 256 -c >/dev/null 2>&1; then
      distributionSha256Result=true
    fi
  else
    echo "Checksum validation was requested but neither 'sha256sum' or 'shasum' are available." >&2
    echo "Please install either command, or disable validation by removing 'distributionSha256Sum' from your maven-wrapper.properties." >&2
    exit 1
  fi
  if [ $distributionSha256Result = false ]; then
    echo "Error: Failed to validate Maven distribution SHA-256, your Maven distribution might be compromised." >&2
    echo "If you updated your Maven version, you need to update the specified distributionSha256Sum property." >&2
    exit 1
  fi
fi

# unzip and move
if command -v unzip >/dev/null; then
  unzip ${__MVNW_QUIET_UNZIP:+"$__MVNW_QUIET_UNZIP"} "$TMP_DOWNLOAD_DIR/$distributionUrlName" -d "$TMP_DOWNLOAD_DIR" || die "failed to unzip"
else
  tar xzf${__MVNW_QUIET_TAR:+"$__MVNW_QUIET_TAR"} "$TMP_DOWNLOAD_DIR/$distributionUrlName" -C "$TMP_DOWNLOAD_DIR" || die "failed to untar"
fi
printf %s\\n "$distributionUrl" >"$TMP_DOWNLOAD_DIR/$distributionUrlNameMain/mvnw.url"
mv -- "$TMP_DOWNLOAD_DIR/$distributionUrlNameMain" "$MAVEN_HOME" || [ -d "$MAVEN_HOME" ] || die "fail to move MAVEN_HOME"

clean || :
exec_maven "$@"

ADR-002 · Clean Architecture em 4 módulos ☕ JavaAceita

Contexto: acoplamento domínio↔infra dificultava troca de banco.

Decisão: módulos domain/application/infrastructure/presentation com regra de dependência para dentro.

Alternativas consideradas: camadas por tecnologia (rejeitada); monolito sem módulos (rejeitada).

Consequências: (+) testabilidade ↑, trocar banco é trocar adapter; (−) custo inicial de scaffolding ↑.

Status: Aceita · Stakeholders: Backend Java, Arquitetura.

ADR-J1 · Domínio anêmico + Service Interface ☕ JavaAceita

Contexto: equipe Java familiarizada com padrão Spring tradicional.

Decisão: Entidade anêmica (POJO puro); lógica no ProdutoServiceImpl; contrato via ProdutoService (interface).

Alternativas consideradas: domínio rico/DDD (adiado p/ stack C#); CQRS (fora de escopo).

Consequências: (+) curva de aprendizado menor; (−) lógica fora da entidade pode levar a duplicação.

Status: Aceita · Stakeholders: Backend Java.

ADR-J2 · JPA/Hibernate como ORM padrão ☕ JavaAceita

Contexto: persistência relacional com MySQL.

Decisão: JPA via Spring Data JPA (Hibernate); ddl-auto: validate (DDL controlada por scripts).

Alternativas consideradas: JDBC puro (rejeitada: boilerplate); jOOQ (rejeitada: curva).

Consequências: (+) produtividade alta; (−) abstração pode gerar queries ineficientes (monitorar).

Status: Aceita · Stakeholders: Backend Java, DBA.

ADR-J3 · Só autenticação, sem papéis (roles) ☕ JavaAceita

Contexto: o contrato da Tab 4 só distingue "logado" de "não logado": leitura pública, escrita com token.

Decisão: o JWT carrega só sub/iat/exp; o filtro autentica sem autoridades; sem 403. Igual à API C# (Tab 7).

Alternativas consideradas: roles ADMIN/USER com hasRole (adiada: o contrato não pede e aumentaria a aula).

Consequências: (+) menos código e o mesmo comportamento nas duas stacks; (−) qualquer usuário logado pode escrever.

Status: Aceita · Stakeholders: Backend Java, Segurança.
