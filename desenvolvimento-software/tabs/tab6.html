🏛️ Clean Architecture (Robert C. Martin, 2012)

Origem: consolidou ideias de Hexagonal (Alistair Cockburn, 2005) e Onion Architecture (Jeffrey Palermo, 2008). O princípio central: o que é negócio fica no centro; o que é tecnologia fica na borda.

As 4 camadas (de dentro para fora)

  1. Entities (Domain): regras de negócio puras (nosso Produto POJO — sem anotações de framework).
  2. Use Cases (Application): orquestram as regras (nosso ProdutoServiceImpl).
  3. Interface Adapters: controllers, gateways/repositórios (convertem mundo externo ↔ interno).
  4. Frameworks & Drivers: banco, web, UI, mensageria (Spring, JPA, MySQL, Mongo).

🔑 A Regra de Dependência

Setas de dependência só apontam para dentro. Camadas internas não conhecem camadas externas. É por isso que ProdutoServiceImpl depende da interface ProdutoRepository, nunca do JPA/Mongo diretamente.

Aprofundar: Uncle Bob — The Clean Architecture (2012) · Hexagonal (Cockburn) · Onion (Palermo).

📐 SOLID — Os 5 princípios aplicados neste projeto Java

SOLID foi cunhado por Michael Feathers (acrônimo) a partir dos princípios de Robert C. Martin. Cada letra mapeia diretamente a uma decisão de design neste projeto:

🧰 Framework, Container DI, ORM e JPA (conceitos Java)

package com.loja.application;

import com.loja.domain.Produto;
import com.loja.domain.ProdutoRepository;
import com.loja.domain.ProdutoService;
import com.loja.domain.exception.DomainException;
import java.math.BigDecimal;
import java.util.List;

/**
 * Implementa os casos de uso. Recebe a INTERFACE ProdutoRepository (DIP).
 * Registrado como bean via CoreBeansConfig (não tem @Service — é classe pura).
 */
public class ProdutoServiceImpl implements ProdutoService {

    private final ProdutoRepository repository;

    public ProdutoServiceImpl(ProdutoRepository repository) {
        this.repository = repository;
    }

    @Override
    public Produto criarProduto(Produto p) {
        if (p.getNome() == null || p.getNome().trim().isEmpty())
            throw new DomainException("O nome do produto é obrigatório");
        if (p.getNome().trim().length() < 2)
            throw new DomainException("O nome deve ter pelo menos 2 caracteres");
        if (p.getPreco() == null || p.getPreco().compareTo(BigDecimal.ZERO) <= 0)
            throw new DomainException("O preço deve ser maior que zero");
        if (p.getEstoque() == null || p.getEstoque() < 0)
            throw new DomainException("O estoque não pode ser negativo");
        return repository.salvar(p);
    }

    @Override
    public List<Produto> listarProdutos() {
        return repository.listarTodos();
    }
    @Override
    public List<Produto> listarProdutos(int page, int size) {
        var all = repository.listarTodos();
        int from = Math.min(page * size, todos.size());
        int to = Math.min(from + size, todos.size());
        return todos.subList(from, to);
    @Override
    public Produto atualizarProduto(Long id, Produto p) {
    Produto existente = repository.buscarPorId(id)
    .orElseThrow(() -> new DomainException("Produto não encontrado: " + id));
    if (p.getNome() == null || p.getNome().trim().length() < 2)
    throw new DomainException("O nome deve ter pelo menos 2 caracteres");
    if (p.getPreco() == null || p.getPreco().compareTo(BigDecimal.ZERO) <= 0)
    throw new DomainException("O preço deve ser maior que zero");
    if (p.getEstoque() == null || p.getEstoque() < 0)
    throw new DomainException("O estoque não pode ser negativo");
    existente.setNome(p.getNome());
    existente.setPreco(p.getPreco());
    existente.setEstoque(p.getEstoque());
    return repository.salvar(existente);
    }
    @Override
    public Produto obterPorId(Long id) {
        return repository.buscarPorId(id)
                .orElseThrow(() -> new DomainException("Produto não encontrado: " + id));
    }

    @Override
    public void excluirProduto(Long id) {
        if (!repository.existePorId(id))
            throw new DomainException("Produto inexistente: " + id);
        repository.deletarPorId(id);
    }
}

package com.loja.infrastructure.persistence;

import com.loja.domain.Produto;
import com.loja.domain.ProdutoRepository;
import org.springframework.boot.autoconfigure.condition.ConditionalOnProperty;
import org.springframework.stereotype.Repository;
import java.util.List;
import java.util.Optional;

/** Adapter JPA — implementa a porta do domínio (Hexagonal). */
@Repository
@ConditionalOnProperty(name = "persistence.provider", havingValue = "relational", matchIfMissing = true)
public class ProdutoRepositoryAdapter implements ProdutoRepository {

    private final SpringDataProdutoRepository jpaRepo;

    public ProdutoRepositoryAdapter(SpringDataProdutoRepository jpaRepo) {
        this.jpaRepo = jpaRepo;
    }

    @Override public Produto salvar(Produto p) { return toDomain(jpaRepo.save(toJpa(p))); }
    @Override public Optional<Produto> buscarPorId(Long id) { return jpaRepo.findById(id).map(this::toDomain); }
    @Override public List<Produto> listarTodos() { return jpaRepo.findAll().stream().map(this::toDomain).toList(); }
    @Override public boolean existePorId(Long id) { return jpaRepo.existsById(id); }
    @Override public void deletarPorId(Long id) { jpaRepo.deleteById(id); }

    private ProdutoJpaEntity toJpa(Produto d) {
        ProdutoJpaEntity e = new ProdutoJpaEntity();
        e.setId(d.getId()); e.setNome(d.getNome()); e.setPreco(d.getPreco()); e.setEstoque(d.getEstoque());
        return e;
    }
    private Produto toDomain(ProdutoJpaEntity e) {
        return new Produto(e.getId(), e.getNome(), e.getPreco(), e.getEstoque());
    }
}

package com.loja.infrastructure.mongo;

import com.loja.domain.Produto;
import com.loja.domain.ProdutoRepository;
import org.springframework.boot.autoconfigure.condition.ConditionalOnProperty;
import org.springframework.data.mongodb.core.MongoTemplate;
import org.springframework.data.mongodb.core.query.Criteria;
import org.springframework.data.mongodb.core.query.Query;
import org.springframework.stereotype.Repository;
import java.util.List;
import java.util.Optional;

/** Adapter Mongo — mesma porta, tecnologia diferente (Liskov/Open-Closed). */
@Repository
@ConditionalOnProperty(name = "persistence.provider", havingValue = "nosql")
public class MongoProdutoRepository implements ProdutoRepository {

    private final MongoTemplate mongo;

    public MongoProdutoRepository(MongoTemplate mongo) { this.mongo = mongo; }

    @Override public Produto salvar(Produto p) {
        ProdutoMongoDocument doc = toDoc(p);
        doc = mongo.save(doc);
        return toDomain(doc);
    }
    @Override public Optional<Produto> buscarPorId(Long id) {
        Query q = new Query(Criteria.where("idLegado").is(id));
        return Optional.ofNullable(mongo.findOne(q, ProdutoMongoDocument.class)).map(this::toDomain);
    }
    @Override public List<Produto> listarTodos() {
        return mongo.findAll(ProdutoMongoDocument.class).stream().map(this::toDomain).toList();
    }
    @Override public boolean existePorId(Long id) { return buscarPorId(id).isPresent(); }
    @Override public void deletarPorId(Long id) {
        mongo.remove(new Query(Criteria.where("idLegado").is(id)), ProdutoMongoDocument.class);
    }

    private ProdutoMongoDocument toDoc(Produto d) {
        ProdutoMongoDocument doc = new ProdutoMongoDocument();
        doc.setIdLegado(d.getId()); doc.setNome(d.getNome());
        doc.setPreco(d.getPreco()); doc.setEstoque(d.getEstoque());
        return doc;
    }
    private Produto toDomain(ProdutoMongoDocument doc) {
        return new Produto(doc.getIdLegado(), doc.getNome(), doc.getPreco(), doc.getEstoque());
    }
}

presentation/security/JwtService.java 
package com.loja.presentation.security;

import io.jsonwebtoken.*;
import io.jsonwebtoken.security.Keys;
import org.springframework.beans.factory.annotation.Value;
import org.springframework.stereotype.Service;
import java.security.Key;
import java.util.Date;

/** Gera e valida JWT (HMAC-SHA256). */
@Service
public class JwtService {

    private final Key key;
    private final long expiration;

    public JwtService(@Value("${jwt.secret}") String secret,
                      @Value("${jwt.expiration}") long expiration) {
        this.key = Keys.hmacShaKeyFor(secret.getBytes());
        this.expiration = expiration;
    }

    public String gerarToken(String username, String role) {
        return Jwts.builder()
                .setSubject(username)
                .claim("role", role)
                .setIssuedAt(new Date())
                .setExpiration(new Date(System.currentTimeMillis() + expiration))
                .signWith(key, SignatureAlgorithm.HS256)
                .compact();
    }

    public Claims extrairClaims(String token) {
        return Jwts.parserBuilder().setSigningKey(key).build().parseClaimsJws(token).getBody();
    }

    public boolean isTokenValido(String token) {
        try { extrairClaims(token); return true; }
        catch (JwtException e) { return false; }
    }
}
presentation/security/JwtTokenFilter.java 
package com.loja.presentation.security;

import io.jsonwebtoken.Claims;
import jakarta.servlet.FilterChain;
import jakarta.servlet.ServletException;
import jakarta.servlet.http.HttpServletRequest;
import jakarta.servlet.http.HttpServletResponse;
import org.springframework.security.authentication.UsernamePasswordAuthenticationToken;
import org.springframework.security.core.authority.SimpleGrantedAuthority;
import org.springframework.security.core.context.SecurityContextHolder;
import org.springframework.stereotype.Component;
import org.springframework.web.filter.OncePerRequestFilter;
import java.io.IOException;
import java.util.List;

/** Filtra requisições, valida "Bearer ...", popula SecurityContext. */
@Component
public class JwtTokenFilter extends OncePerRequestFilter {

    private final JwtService jwtService;

    public JwtTokenFilter(JwtService jwtService) { this.jwtService = jwtService; }

    @Override
    protected void doFilterInternal(HttpServletRequest req, HttpServletResponse res, FilterChain chain)
            throws ServletException, IOException {
        String header = req.getHeader("Authorization");
        if (header != null && header.startsWith("Bearer ")) {
            String token = header.substring(7);
            if (jwtService.isTokenValido(token)) {
                Claims claims = jwtService.extrairClaims(token);
                var auth = new UsernamePasswordAuthenticationToken(
                    claims.getSubject(), null,
                    List.of(new SimpleGrantedAuthority("ROLE_" + claims.get("role", String.class))));
                SecurityContextHolder.getContext().setAuthentication(auth);
            }
        }
        chain.doFilter(req, res);
    }
}

package com.loja.presentation.security;

import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;
import org.springframework.http.HttpMethod;
import org.springframework.security.config.annotation.web.builders.HttpSecurity;
import org.springframework.security.config.http.SessionCreationPolicy;
import org.springframework.security.web.SecurityFilterChain;
import org.springframework.security.web.authentication.UsernamePasswordAuthenticationFilter;

@Configuration
public class SecurityConfig {

    private final JwtTokenFilter jwtFilter;

    public SecurityConfig(JwtTokenFilter jwtFilter) { this.jwtFilter = jwtFilter; }

    @Bean
    public SecurityFilterChain filterChain(HttpSecurity http) throws Exception {
        return http.csrf(c -> c.disable())
            .sessionManagement(s -> s.sessionCreationPolicy(SessionCreationPolicy.STATELESS))
            .authorizeHttpRequests(a -> a
                .requestMatchers("/api/auth/**", "/hello", "/").permitAll()
                .requestMatchers(HttpMethod.GET, "/api/produtos/**").permitAll()
                .anyRequest().authenticated())
            .addFilterBefore(jwtFilter, UsernamePasswordAuthenticationFilter.class)
            .build();
    }
}

package com.loja.presentation.exception;

import com.loja.domain.exception.DomainException;
import org.springframework.http.*;
import org.springframework.web.bind.MethodArgumentNotValidException;
import org.springframework.web.bind.annotation.*;
import java.net.URI;
import java.util.stream.Collectors;

/** Captura exceções e retorna RFC 7807 (application/problem+json). */
@RestControllerAdvice
public class GlobalExceptionHandler {

    @ExceptionHandler(DomainException.class)
    public ResponseEntity<ProblemDetail> handleDomain(DomainException ex) {
        ProblemDetail pd = ProblemDetail.forStatusAndDetail(HttpStatus.BAD_REQUEST, ex.getMessage());
        pd.setType(URI.create("https://example.com/erros/dominio"));
        pd.setTitle("Regra de negócio violada");
        return ResponseEntity.status(HttpStatus.BAD_REQUEST)
                .contentType(MediaType.APPLICATION_PROBLEM_JSON).body(pd);
    }

    @ExceptionHandler(MethodArgumentNotValidException.class)
    public ResponseEntity<ProblemDetail> handleValidation(MethodArgumentNotValidException ex) {
        String detail = ex.getBindingResult().getFieldErrors().stream()
                .map(fe -> fe.getField() + ": " + fe.getDefaultMessage())
                .collect(Collectors.joining("; "));
        ProblemDetail pd = ProblemDetail.forStatusAndDetail(HttpStatus.BAD_REQUEST, detail);
        pd.setType(URI.create("https://example.com/erros/validacao"));
        pd.setTitle("Requisição inválida");
        return ResponseEntity.status(HttpStatus.BAD_REQUEST)
                .contentType(MediaType.APPLICATION_PROBLEM_JSON).body(pd);
    }
}

🔑 JWT na prática (Java): quem faz o quê

  1. Emissão — JwtService.gerarToken(): monta claims (sub, role, iat, exp) e assina com HS256 usando o secret vindo de ${jwt.secret}.
  2. Verificação — JwtTokenFilter: em toda request, lê Authorization: Bearer …, valida assinatura/expiração e popula o SecurityContext; se inválido → 401 problem+json.
  3. Fio condutor — SecurityConfig: registra o filtro antes do UsernamePasswordAuthenticationFilter, sessão STATELESS, libera /api/auth/** e GETs públicos, exige auth no resto.
  4. Secret: vem de ${jwt.secret} no application.yml em dev; em produção use variável de ambiente (export JWT_SECRET=…) ou secret manager — nunca commitado.

🔄 Migração relacional → NoSQL (Strangler Fig — Java)

Motivações: escala horizontal, schema flexível. Riscos: perda de ACID, consistência eventual. A migração acontece DENTRO da API, via toggle persistence.provider no application.yml, trocando qual adapter é injetado.

Aprofundar: Polyglot Persistence · Strangler Fig.

ADR-004 · Migração Strangler Fig com toggle ☕ JavaAceita

Contexto: catálogo com atributos variáveis cresce; o relacional limita o schema; necessidade de escala horizontal sem downtime.

Decisão: migrar em 4 fases (dual-write → backfill → cut-over → desligamento) controladas por toggle (persistence.provider / Persistence:Provider), com a API escrevendo/lendo via porta ProdutoRepository/IProdutoRepository.

Alternativas consideradas: big-bang (rejeitada: downtime e risco); manter só relacional (rejeitada: limite de schema); CDC + ETL externo (rejeitada: complexidade de infra).

Consequências: (+) rollback trivial (1 chave), sem downtime, validação progressiva; (−) complexidade temporária de 2 adapters e necessidade de reconciliação.

Status: Aceita · Stakeholders: Backend, QA, SRE.

🔁 CI/CD: conceitos + GitHub Actions + GitLab CI (Java)

🔁 CI vs CD (o que é cada um)

  • CI (Integração Contínua): a cada push/PR o pipeline compila + testa automaticamente, pegando erros cedo.
  • CD (Entrega Contínua): após CI verde, o artefato é empacotado e deixado pronto p/ deploy.
  • Pipeline / Stage / Job: pipeline = sequência; stage = fase (build, test); job = tarefa.
  • Runner: máquina/agente que executa os jobs.
  • Artifact / Cache: artifact = saída (jar); cache = reaproveita deps.

Aprofundar: Martin Fowler (CI) · Atlassian CI/CD.

🖱️ Onde configurar (menus)

  1. GitLab: repo → Settings → CI/CD → habilitar Runners / Variables; o arquivo .gitlab-ci.yml na raiz ativa o pipeline automaticamente.
  2. GitHub: repo → aba Actions → set up a workflow → criar .github/workflows/ci.yml.
  3. Proteger a main: GitHub → Settings → Branches → Add rule → exigir checks; GitLab → Settings → Repository → Protected branches.
  4. Testar: abrir um PR/MR de um branch feature/x → os checks rodam; ao mergear na main, rodam de novo.

ADR-002 · Clean Architecture em 4 módulos ☕ JavaAceita

Contexto: acoplamento domínio↔infra dificultava troca de banco.

Decisão: módulos domain/application/infrastructure/presentation com regra de dependência para dentro.

Alternativas consideradas: camadas por tecnologia (rejeitada); monolito sem módulos (rejeitada).

Consequências: (+) testabilidade ↑, trocar banco é trocar adapter; (−) custo inicial de scaffolding ↑.

Status: Aceita · Stakeholders: Backend Java, Arquitetura.

ADR-J1 · Domínio anêmico + Service Interface ☕ JavaAceita

Contexto: equipe Java familiarizada com padrão Spring tradicional.

Decisão: Entidade anêmica (POJO puro); lógica no ProdutoServiceImpl; contrato via ProdutoService (interface).

Alternativas consideradas: domínio rico/DDD (adiado p/ stack C#); CQRS (fora de escopo).

Consequências: (+) curva de aprendizado menor; (−) lógica fora da entidade pode levar a duplicação.

Status: Aceita · Stakeholders: Backend Java.

ADR-J2 · JPA/Hibernate como ORM padrão ☕ JavaAceita

Contexto: persistência relacional com MySQL.

Decisão: JPA via Spring Data JPA (Hibernate); ddl-auto: validate (DDL controlada por scripts).

Alternativas consideradas: JDBC puro (rejeitada: boilerplate); jOOQ (rejeitada: curva).

Consequências: (+) produtividade alta; (−) abstração pode gerar queries ineficientes (monitorar).

Status: Aceita · Stakeholders: Backend Java, DBA.

ADR-004 · Migração Strangler Fig com toggle ☕ JavaAceita

Contexto: catálogo com atributos variáveis cresce; relacional limita schema.

Decisão: migrar em 4 fases controladas por persistence.provider no application.yml.

Alternativas consideradas: big-bang (rejeitada: risco); manter só relacional (rejeitada: limite).

Consequências: (+) rollback trivial (1 chave), sem downtime; (−) complexidade temporária de 2 adapters.

Status: Aceita · Stakeholders: Backend Java, QA, SRE.

ADR-006 · Persistência poliglota MySQL+Mongo ☕ JavaAceita

Contexto: dados relacionais transacionais + catálogo flexível.

Decisão: MySQL p/ transações, Mongo p/ catálogo, ambos no dev via compose.

Alternativas consideradas: só relacional (rejeitada); só NoSQL (rejeitada: transações).

Consequências: (+) flexibilidade; (−) disciplina de consistência entre bases.
