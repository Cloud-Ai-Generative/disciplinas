🐬🍃 Orquestração de Bancos: MySQL 8.4 + MongoDB 7.0 + Playground

Sobe os bancos, conecta, e um playground CRUD completo (INSERT/SELECT/UPDATE/DELETE + agregações + JOIN) com diagramas de dados nomeados.

🐳 Imagem vs Container vs Volume vs Porta

  • Imagem: o "molde" leitura-only (camadas de filesystem + metadados). Feita por docker build ou baixada de um registry.
  • Container: uma instância em execução da imagem (processo isolado). Pode haver vários containers da mesma imagem.
  • Volume: armazenamento persistente gerenciado pelo Docker (sobrevive ao remover o container). Usado p/ dados dos bancos.
  • Porta (ports:): mapeamento host:container (ex.: 3306:3306) que expõe o serviço ao host. Sem ports:, só outros containers na mesma rede acessam.

1. Rede Bridge

DNS interno pelo nome: mysql-db:3306, mongo-db:27017; só ports: expõe ao host.

2. Volumes vs Bind Mounts

  • Volumes: persistem (dados).
  • Bind Mounts: pasta do host mapeada (scripts/configs).

3. Healthcheck

Teste periódico (ex.: mysqladmin ping) marca o container como healthy.

Aprofundar: Docker Get Started · Volumes.

🗄️ SQL, DDL e DML (o básico p/ entender os scripts)

  • SQL: linguagem de consulta/manipulação de bancos relacionais.
  • DDL (Data Definition Language): define estruturas — CREATE TABLE, ALTER, DROP, CREATE INDEX.
  • DML (Data Manipulation Language): manipula dados — INSERT, SELECT, UPDATE, DELETE.

No compose, a pasta /docker-entrypoint-initdb.d roda scripts .sql/.js uma vez no primeiro boot com volume vazio, em ordem alfanumérica. DDL cria estruturas; DML insere seed.

📄 docker-compose.yml (completo)

docker-compose.yml 
# COMPOSE DE INFRAESTRUTURA - SOMENTE BANCOS
# =====================================================================
# COMPOSE DE INFRAESTRUTURA - SOMENTE BANCOS
# ---------------------------------------------------------------------
# Este arquivo sobe APENAS os serviços de banco de dados (MySQL e MongoDB)
# para desenvolvimento local. Aplicações (APIs, workers, etc.) devem
# rodar em outro compose ou diretamente na máquina host.
#
# Uso:
#   docker compose up -d          -> sobe os bancos em background
#   docker compose ps             -> verifica status
#   docker compose logs -f mysql-db
#   docker compose down           -> derruba (mantém volumes)
#   docker compose down -v        -> derruba e APAGA os volumes (perde dados)
# =====================================================================

services:

  # -------------------------------------------------------------------
  # MYSQL 8.4 - Banco relacional principal
  # -------------------------------------------------------------------
  mysql-db:
    # Imagem oficial do MySQL. 8.4 = LTS (Long Term Support).
    image: mysql:8.4

    # Nome fixo do container (facilita 'docker exec -it dev_mysql_server ...').
    # Útil em dev, mas evita usar em produção (nome global conflita).
    container_name: dev_mysql_server

    # Reinicia automaticamente o container se cair, exceto se for parado manualmente.
    restart: unless-stopped

    # Variáveis lidas pela imagem na PRIMEIRA inicialização do volume.
    # Atenção: se o volume já existir, alterar aqui NÃO muda senhas/DB.
    environment:
      MYSQL_ROOT_PASSWORD: root123          # senha do usuário root
      MYSQL_DATABASE: loja_db               # DB criado automaticamente
      MYSQL_USER: devuser                   # usuário comum criado
      MYSQL_PASSWORD: devpass               # senha do usuário comum
      TZ: America/Sao_Paulo                 # fuso horário do container

    # Mapeia porta do host -> container. Formato "host:container".
    # Exposto no host para permitir conexão via DBeaver/Workbench/etc.
    ports:
      - "3306:3306"

    # Volumes: persistência de dados + scripts de inicialização.
    volumes:
      # Volume nomeado: dados do MySQL persistem entre 'down/up'.
      - mysql_dev_data:/var/lib/mysql
      # Pasta local com .sql/.sh executados UMA vez na criação do DB.
      # Coloque aqui seus scripts em ./init-sql/*.sql
      - ./init-sql:/docker-entrypoint-initdb.d

    # Anexa o container à rede customizada (permite DNS interno 'mysql-db').
    networks:
      - dev_network

    # Healthcheck: permite que outras stacks esperem o MySQL estar pronto.
    # 'mysqladmin ping' retorna OK quando o servidor aceita conexões.
    healthcheck:
      test: ["CMD", "mysqladmin", "ping", "-h", "localhost", "-proot123"]
      interval: 10s      # intervalo entre checagens
      timeout: 5s        # tempo máximo de cada checagem
      retries: 5         # tentativas antes de marcar como unhealthy
      start_period: 30s  # (extra) carência inicial p/ o MySQL subir

  # -------------------------------------------------------------------
  # MONGODB 7.0 - Banco NoSQL (documentos)
  # -------------------------------------------------------------------
  mongo-db:
    image: mongo:7.0
    container_name: dev_mongo_server
    restart: unless-stopped

    # Credenciais do usuário root do Mongo (admin).
    # MONGO_INITDB_DATABASE cria o DB na primeira inicialização.
    environment:
      MONGO_INITDB_ROOT_USERNAME: root
      MONGO_INITDB_ROOT_PASSWORD: root123
      MONGO_INITDB_DATABASE: loja_nosql
      TZ: America/Sao_Paulo

    ports:
      - "27017:27017"    # exposto p/ Mongo Compass / mongosh no host

    volumes:
      # Persistência dos dados do Mongo.
      - mongo_dev_data:/data/db
      # Scripts .js/.sh rodados na criação inicial do DB.
      - ./init-mongo:/docker-entrypoint-initdb.d

    networks:
      - dev_network

    # 'mongosh' é o shell oficial moderno (substitui 'mongo' legado).
    # db.adminCommand('ping') retorna { ok: 1 } se o servidor responde.
    healthcheck:
      test: ["CMD", "mongosh", "--eval", "db.adminCommand('ping')"]
      interval: 10s
      timeout: 5s
      retries: 5
      start_period: 20s

# =====================================================================
# VOLUMES NOMEADOS
# ---------------------------------------------------------------------
# Gerenciados pelo Docker. Persistem mesmo após 'docker compose down'.
# Só são removidos com 'docker compose down -v' ou 'docker volume rm'.
# =====================================================================
volumes:
  mysql_dev_data:
    driver: local
  mongo_dev_data:
    driver: local

# =====================================================================
# REDE
# ---------------------------------------------------------------------
# Rede bridge isolada. Containers nela se enxergam pelo nome do serviço
# (ex: 'mysql-db:3306' e 'mongo-db:27017' funcionam como hostname).
# O 'name' fixa o nome real da rede (default seria algo como 'pasta_dev_network').
# =====================================================================
networks:
  dev_network:
    driver: bridge
    name: loja_dev_network

📦 Passo 2: De onde vieram os dados? (DDL/DML)

🚪 /docker-entrypoint-initdb.d

Arquivos .sql/.js montados aí rodam uma vez, no primeiro boot com volume vazio, em ordem alfanumérica. DDL cria estruturas; DML insere seed. Tabela categorias + FK habilita JOINs e um ER mais rico.

🐬 init-sql/01-init.sql (com categorias p/ JOIN)

init-sql/01-init.sql 
USE loja_db;
-- DDL: tabela de categorias (lado "1")
CREATE TABLE IF NOT EXISTS categorias (
  id INT AUTO_INCREMENT PRIMARY KEY,
  nome VARCHAR(60) NOT NULL UNIQUE
);
-- DDL: tabela de produtos (lado "N"), com FK
CREATE TABLE IF NOT EXISTS produtos (
  id BIGINT AUTO_INCREMENT PRIMARY KEY,
  nome VARCHAR(100) NOT NULL,
  preco DECIMAL(10,2) NOT NULL,
  estoque INT NOT NULL DEFAULT 0,
  categoria_id INT,
  CONSTRAINT fk_cat FOREIGN KEY (categoria_id) REFERENCES categorias(id),
  CONSTRAINT chk_preco CHECK (preco > 0),
  CONSTRAINT chk_estoque CHECK (estoque >= 0)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
-- DML: seed de categorias
INSERT INTO categorias (nome) VALUES ('Perifericos'),('Audio');
-- DML: seed de produtos
INSERT INTO produtos (nome,preco,estoque,categoria_id) VALUES
 ('Teclado Mecanico RGB',349.90,15,1),
 ('Mouse Gamer 16000 DPI',189.50,20,1),
 ('Headset 7.1 Surround',420.00,10,2);
CREATE INDEX idx_nome ON produtos(nome);

🐬 MySQL: INSERT/SELECT/UPDATE/DELETE

shell MySQL (docker exec) 
# CREATE: insere mais um produto
INSERT INTO produtos (nome,preco,estoque,categoria_id)
VALUES ('Monitor 27 144Hz',1899.00,5,1);
# READ: filtros + ordenação + limite
SELECT nome, preco FROM produtos WHERE preco > 200 ORDER BY preco DESC LIMIT 2;
# READ com JOIN + agregação por categoria
SELECT c.nome AS categoria, COUNT(*) AS qtd, AVG(p.preco) AS preco_medio
FROM produtos p JOIN categorias c ON c.id = p.categoria_id
GROUP BY c.nome;
# UPDATE: reajuste com WHERE (sem WHERE atualiza TUDO!)
UPDATE produtos SET preco = preco * 1.10 WHERE categoria_id = 1;
# DELETE: remove com WHERE
DELETE FROM produtos WHERE nome LIKE 'Monitor%';

🍃 Mongo: insert/find/update/delete

mongosh (docker exec) 
use loja_nosql
// CREATE
db.produtos.insertOne({ nome:"Monitor 27 144Hz", preco:1899.00, estoque:5, tags:["video"] })
// READ com filtro + projeção + sort
db.produtos.find({ preco: { $gt: 200 } }, { nome:1, preco:1 }).sort({ preco:-1 })
// UPDATE: $set muda campo, $inc incrementa
db.produtos.updateOne({ nome:"Teclado Mecanico RGB" }, { $set:{ preco:379.90 }, $inc:{ estoque:3 } })
// DELETE
db.produtos.deleteOne({ nome:"Monitor 27 144Hz" })
db.produtos.countDocuments()
