🐬🍃 Docker + Bancos de Dados: MySQL e MongoDB na sua máquina

Passo a passo, com o mouse e com o terminal sempre ao lado: instale o Docker, ligue um MySQL e um MongoDB com um comando só, abra os dois em programas visuais e faça o CRUD (criar, ler, atualizar, apagar) em etapas, vendo o resultado de cada uma. Os bancos daqui são os que as APIs das Tabs 6, 7 e 9 vão usar.

🗺️ O caminho desta aba: ① O que é Docker → ② Instalar o Docker Desktop → ③ Ligar os bancos → ④ MySQL na prática → ⑤ MongoDB na prática → ⑥ De onde vieram os dados → ⑦ Os dois lado a lado → ⑧ Desligar, recomeçar e erros comuns. Tempo total: ~1h30.
🧭 Como ler esta aba: os passos com 🖱️ são feitos com o mouse. Os blocos ⌨️ Prefere o terminal? mostram o mesmo passo por comandos — o jeito que você vai usar no dia a dia de trabalho. Faça pelo mouse primeiro e, depois, repita pelo terminal: as duas formas fazem exatamente a mesma coisa.

① 🐳 O que é Docker (e por que usar)

Para ter um MySQL, você poderia instalar o MySQL no Windows, configurar, torcer para não dar conflito… e repetir tudo para o MongoDB. Com o Docker, cada banco vem numa "caixa" pronta, já configurada, que liga com um comando e some sem deixar rastro quando você não precisa mais. E roda igual no seu computador, no do colega e no servidor.

🎂
Analogia da confeitaria: a imagem é a forma do bolo (o molde, que nunca muda); o container é o bolo feito com a forma (dá para fazer vários iguais); o volume é o pote na geladeira onde você guarda o recheio (se jogar o bolo fora, o recheio continua lá); a porta é a janela do balcão por onde o cliente pega o pedido.

② 🧰 Instalar o Docker Desktop

⬇️ Site do Docker Desktop ↗

O Docker Desktop é o programa que roda os containers no Windows e no Mac, com uma janela para você ver tudo. É gratuito para uso pessoal, estudo e empresas pequenas. O passo a passo abaixo é para Windows 10/11; macOS e Linux estão no fim desta parte.

1🖱️ Baixar e instalar (Windows)

  1. Entre em docker.com/products/docker-desktop → clique em Download Docker Desktop → Download for Windows – AMD64 (quase todo PC; só escolha ARM64 se o seu notebook tiver processador Snapdragon). O arquivo se chama Docker Desktop Installer.exe (~500 MB).
  2. Dois cliques no arquivo → Sim na pergunta de permissão do Windows.
  3. Tela Configuration: deixe marcado ☑ Use WSL 2 instead of Hyper-V (recommended) ("use o WSL 2", recomendado) e ☑ Add shortcut to desktop → Ok.
    ❓ O que é WSL 2? Os bancos de dados das imagens Docker são programas de Linux. O WSL 2 (Windows Subsystem for Linux) é um Linux de verdade, da própria Microsoft, que roda escondido dentro do Windows. O Docker Desktop usa ele — você não precisa mexer nele.
  4. Espere a instalação (2 a 5 minutos) → Close and restart ("fechar e reiniciar"). O computador reinicia: salve o que estiver aberto antes.

2🖱️ Abrir o Docker Desktop pela primeira vez

  1. Depois de reiniciar, ele costuma abrir sozinho. Se não: tecla Windows → digite Docker Desktop → Enter.
  2. Docker Subscription Service Agreement (termos de uso) → Accept ("aceitar").
  3. Pedido de login ou de criar conta: pode clicar em Skip / Continue without signing in ("continuar sem entrar"). Pesquisa sobre o seu trabalho: Skip.
  4. Abre a janela principal. Olhe o canto inferior esquerdo: quando aparecer Engine running ("motor ligado") com uma bolinha verde 🟢, o Docker está pronto.
Menu da esquerdaO que mostra
ContainersOs containers que existem: ligados (🟢) ou parados (⚪). Botões ▶ ligar, ⏹ parar, 🗑 apagar — e, clicando no nome, os Logs (o que o programa está escrevendo) e o Exec (um terminal dentro do container)
ImagesOs "moldes" já baixados
VolumesOs "potes" com os dados guardados
⚠️ Erros comuns na instalação:
  • "Virtualization support not detected" ("virtualização não detectada") → a virtualização está desligada na BIOS do computador. Reinicie, entre na BIOS (geralmente F2, F10 ou Del ao ligar) e ative Intel VT-x ou AMD-V / SVM. Na dúvida, procure no YouTube "ativar virtualização BIOS" + a marca do seu PC.
  • "WSL needs updating" / "WSL 2 installation is incomplete" → abra o PowerShell (tecla Windows → powershell) e rode wsl --update. Depois, abra o Docker Desktop de novo.
  • Fica parado em "Starting the Docker Engine…" → espere uns 2 minutos na primeira vez; se não sair, reinicie o computador.

3Primeiro teste: o "Hello World" do Docker

O Docker é usado principalmente pelo terminal — por isso o primeiro teste é um comando. Abra o terminal da sua IDE (IntelliJ: View → Tool Windows → Terminal, Alt+F12 · VS Code: Terminal → New Terminal, Ctrl+`) ou o PowerShell, e digite:

terminal 
docker run hello-world

Na primeira vez, ele baixa a imagem hello-world (aparece "Unable to find image… Pulling from library/hello-world" — é normal) e depois mostra:

resultado esperado (o começo) 
Hello from Docker!
This message shows that your installation appears to be working correctly.
✅ Deu certo se aparecer "Hello from Docker!". Abra o Docker Desktop → Containers: o container que acabou de rodar aparece lá, parado (ele só escreve a mensagem e termina). Pode apagá-lo no 🗑.
⚠️ docker: command not found / "não é reconhecido como comando"? O terminal estava aberto antes da instalação: feche-o (no VS Code e no IntelliJ, feche a IDE inteira) e abra de novo. "Cannot connect to the Docker daemon"? O Docker Desktop não está aberto: abra e espere o Engine running 🟢.
🍎 macOS e 🐧 Linux: como instalar o Docker
  1. macOS: no mesmo site, Download for Mac – Apple Silicon (chips M1, M2, M3, M4) ou Intel. Abra o .dmg, arraste o Docker para Aplicativos, abra pelo Launchpad e siga os passos 2 e 3 acima.
  2. Linux (Ubuntu): o mais simples é o Docker Engine (sem janela), pelo script oficial:
Linux (Ubuntu) — terminal

sudo usermod -aG docker $USER                    # permite usar docker sem sudo

2Entender a receita (o docker-compose.yml)

Abra o arquivo no VS Code ou no IntelliJ para ler. Você não precisa mudar nada — os comentários (linhas com #) explicam cada parte. O resumo:

TrechoEm português
services:"Os programas que eu quero ligar": mysql-db e mongo-db
image: mysql:8.4"Use este molde" (baixado da internet na primeira vez)
container_name:"Dê este nome ao container" — é o nome que aparece no Docker Desktop

docker-compose.yml (comentado linha a linha) 
# =====================================================================
#  docker-compose.yml — a "receita" que sobe os 2 bancos do guia
# ---------------------------------------------------------------------
#  Sobe APENAS os bancos de dados (MySQL e MongoDB) para estudar e para
#  as APIs das próximas abas. As APIs rodam na sua máquina (IntelliJ /
#  VS Code) e se conectam aqui pelas portas 3306 e 27017.
#
#  Comandos (no terminal, na pasta deste arquivo):
#    docker compose up -d        -> liga os bancos (em segundo plano)
#    docker compose ps           -> mostra se estão ligados e saudáveis
#    docker compose stop         -> desliga (os dados ficam guardados)
#    docker compose down -v      -> desliga e APAGA os dados (recomeça do zero)
# =====================================================================

services:

  # -------------------------------------------------------------------
  # MYSQL 8.4 — banco RELACIONAL (tabelas)
  # -------------------------------------------------------------------
  mysql-db:
    # A IMAGEM: o "molde" oficial do MySQL, baixado da internet (Docker Hub).
    # 8.4 é a versão LTS (suporte de longo prazo).
    image: mysql:8.4

    # O nome do CONTAINER (o "bolo" feito com o molde). Nome fixo para
    # os comandos ficarem iguais em todo computador. As Tabs 6, 7 e 9
    # usam este nome — não mude.
    container_name: dev_mysql_server

    # Se o container cair, o Docker liga de novo (exceto se VOCÊ o parar).
    restart: unless-stopped

    # Configuração lida SÓ NA PRIMEIRA VEZ que o banco é criado.
    # ⚠️ Mudar aqui depois não muda nada: use 'docker compose down -v'.
    environment:
      MYSQL_ROOT_PASSWORD: root123          # senha do administrador (root)
      MYSQL_DATABASE: loja_db               # banco criado automaticamente
      MYSQL_USER: devuser                   # usuário comum, para as APIs e o DBeaver
      MYSQL_PASSWORD: devpass               # senha do devuser
      TZ: America/Sao_Paulo                 # fuso horário

    # A PORTA: "janela" entre o seu computador e o container.
    # Formato "porta-no-seu-PC:porta-no-container".
    # Se o seu PC já tem um MySQL instalado usando a 3306, troque para "3307:3306".
    ports:
      - "3306:3306"

    volumes:
      # O VOLUME: o "pote" onde os dados ficam guardados. Sobrevive mesmo
      # se o container for apagado — só some com 'down -v'.
      - mysql_dev_data:/var/lib/mysql
      # Pasta do seu PC com os scripts .sql que criam as tabelas e os
      # dados de exemplo. Rodam UMA vez, quando o banco é criado.
      - ./init-sql:/docker-entrypoint-initdb.d

    networks:
      - dev_network

    # HEALTHCHECK: um teste automático, a cada 10s, que pergunta
    # "o MySQL já está aceitando conexões?". Quando responde que sim,
    # o container fica "healthy" (saudável) — a bolinha verde.
    healthcheck:
      test: ["CMD", "mysqladmin", "ping", "-h", "localhost", "-proot123"]
      interval: 10s
      timeout: 5s
      retries: 5
      start_period: 30s   # carência: o MySQL leva ~20s para ligar na 1ª vez

  # -------------------------------------------------------------------
  # MONGODB 7.0 — banco NÃO RELACIONAL (documentos)
  # -------------------------------------------------------------------
  mongo-db:
    image: mongo:7.0
    container_name: dev_mongo_server
    restart: unless-stopped

    environment:
      MONGO_INITDB_ROOT_USERNAME: root      # administrador do Mongo
      MONGO_INITDB_ROOT_PASSWORD: root123
      MONGO_INITDB_DATABASE: loja_nosql     # banco onde o script de carga roda
      TZ: America/Sao_Paulo

    ports:
      - "27017:27017"     # a porta padrão do MongoDB (usada pelo Compass)

    volumes:
      - mongo_dev_data:/data/db                   # o "pote" dos dados
      - ./init-mongo:/docker-entrypoint-initdb.d  # scripts .js de carga inicial

    networks:
      - dev_network

    # 'mongosh' é o terminal oficial do MongoDB. O comando 'ping'
    # responde { ok: 1 } quando o banco está pronto.
    healthcheck:
      test: ["CMD", "mongosh", "--quiet", "--eval", "db.adminCommand('ping')"]
      interval: 10s
      timeout: 5s
      retries: 5
      start_period: 20s

# =====================================================================
#  VOLUMES — os "potes" com nome. Guardados pelo Docker no seu PC.
#  Só são apagados com 'docker compose down -v'.
# =====================================================================
volumes:
  mysql_dev_data:
  mongo_dev_data:

# =====================================================================
#  REDE — uma rede privada só para estes containers. Dentro dela, um
#  container acha o outro pelo NOME do serviço (mysql-db, mongo-db),
#  como se fosse um endereço de site.
# =====================================================================
networks:
  dev_network:
    driver: bridge
    name: loja_dev_network
🔐 Usuários e senhas (são de estudo — nunca use senhas assim num sistema de verdade):
• MySQL: usuário devuser / senha devpass · banco loja_db · administrador root / root123
• MongoDB: usuário root / senha root123 · banco loja_nosql

④ 🐬 MySQL na prática (DBeaver)

⬇️ Site do DBeaver ↗

O DBeaver Community é um programa gratuito para ver e mexer em bancos relacionais: mostra as tabelas como planilhas e tem um editor para escrever SQL.

1🖱️ Instalar o DBeaver

  1. Entre em dbeaver.io/download → em Community Edition, clique em Windows (installer).
  2. Abra o arquivo → escolha o idioma → Next → I Agree → For me (só para o seu usuário) → Next nas telas seguintes (pode deixar tudo como está) → Install → Finish.
  3. Abra o DBeaver. Se perguntar sobre criar um banco de exemplo (sample database), responda No.

2🖱️ Conectar no MySQL do Docker

  1. Clique no ícone de tomada com + no canto superior esquerdo (New Database Connection, "nova conexão"). Atalho: Ctrl+Shift+N.
  2. Escolha MySQL (o golfinho) → Next.
  3. Preencha:
    CampoValor
    Server Hostlocalhost ("este computador")
    Port3306
    Databaseloja_db
    Usernamedevuser
    Passworddevpass (marque Save password)
  4. Importante: clique na aba Driver properties (no topo da mesma janela). Na lista, ache allowPublicKeyRetrieval e mude para true. (Sem isso, o MySQL 8 recusa a conexão — veja os erros comuns abaixo.)
  5. Clique em Test Connection… ("testar conexão"). Na primeira vez, ele pede para baixar o driver (o "tradutor" entre o DBeaver e o MySQL): Download. Deve aparecer Connected ✅ → OK → Finish.
  6. A conexão aparece na coluna da esquerda (Database Navigator). Abra as setinhas ▸: loja_db → Tables → lá estão categorias e produtos.
  7. Dê dois cliques em produtos → aba Data ("dados"): os 3 produtos de exemplo aparecem como uma planilha. A aba Properties mostra as colunas e os tipos.
⚠️ Erros comuns ao conectar:
  • "Public Key Retrieval is not allowed" → faltou o allowPublicKeyRetrieval = true do item 4. Botão direito na conexão → Edit Connection → Driver properties.
  • "Communications link failure" / "Connection refused" → o container não está ligado: confira a bolinha verde no Docker Desktop.
  • "Access denied for user 'devuser'" → usuário ou senha digitados errado. Ou: você já tinha um MySQL instalado no Windows usando a porta 3306, e o DBeaver está falando com ele em vez do Docker — troque a porta no compose para "3307:3306", rode docker compose up -d e use 3307 no DBeaver.

3O CRUD em SQL, uma etapa de cada vez

Abra o editor de SQL: botão direito na conexão → SQL Editor → Open SQL script (atalho Ctrl+]). Abre um espaço em branco. Em cada etapa: apague o que estiver no editor, cole o comando, clique nele e aperte Ctrl+Enter (executa o comando onde está o cursor). O resultado aparece embaixo, como planilha.

Etapa 1 — READ (ler): ver tudo

SQL — etapa 1 
SELECT * FROM produtos;

SELECT = "mostre" · * = "todas as colunas" · FROM produtos = "da tabela produtos" · ; = fim do comando. Resultado:

idnomeprecoestoquecategoria_id
1Teclado Mecânico RGB349.90151
2Mouse Gamer 16000 DPI189.50201
3Headset 7.1 Surround420.00102

Etapa 2 — READ com filtro e ordem

SQL — etapa 2 
SELECT nome, preco
  FROM produtos
 WHERE preco > 200
 ORDER BY preco DESC;

nome, preco = só essas colunas · WHERE preco > 200 = "só os que custam mais de 200" · ORDER BY preco DESC = "do mais caro para o mais barato" (DESC = decrescente; ASC = crescente). Resultado: Headset (420.00) e Teclado (349.90). O Mouse ficou de fora: custa menos de 200.

Etapa 3 — juntar duas tabelas (JOIN)

A tabela produtos só guarda o número da categoria (categoria_id). O nome está na tabela categorias. O JOIN junta as duas, linha com linha, onde os números batem:

SQL — etapa 3 
SELECT p.nome, p.preco, c.nome AS categoria
  FROM produtos p
  JOIN categorias c ON c.id = p.categoria_id;

produtos p = "chame a tabela produtos de p" (um apelido, para escrever menos) · JOIN categorias c = "junte com categorias, apelidada c" · ON c.id = p.categoria_id = "onde o id da categoria for igual ao categoria_id do produto" · AS categoria = o nome da coluna no resultado. Resultado: cada produto com o nome da categoria — Teclado/Periféricos, Mouse/Periféricos, Headset/Áudio.

Etapa 4 — CREATE (criar): um produto novo

SQL — etapa 4 (rode um comando de cada vez: clique no INSERT e Ctrl+Enter, depois no SELECT) 
INSERT INTO produtos (nome, preco, estoque, categoria_id)
VALUES ('Webcam Full HD', 259.90, 8, 1);

SELECT * FROM produtos WHERE nome = 'Webcam Full HD';

INSERT INTO produtos (...) = "coloque em produtos, nestas colunas" · VALUES (...) = "estes valores, na mesma ordem". Texto vai entre aspas simples '...'; número, sem aspas. O id não foi informado: o MySQL deu o 4 sozinho (é o AUTO_INCREMENT). Na aba Data de produtos, clique em 🔄 (Refresh) para ver a linha nova.

Etapa 5 — UPDATE (atualizar): mudar o preço

SQL — etapa 5 
UPDATE produtos
   SET preco = 239.90, estoque = estoque + 5
 WHERE nome = 'Webcam Full HD';

SELECT nome, preco, estoque FROM produtos WHERE nome = 'Webcam Full HD';

UPDATE produtos = "altere em produtos" · SET preco = 239.90 = "o preço passa a ser 239.90" · estoque = estoque + 5 = "o estoque passa a ser o que era, mais 5" · WHERE ... = "só na Webcam". Resultado: 239.90 e estoque 13.

⚠️ A regra mais importante do SQL: nunca rode UPDATE ou DELETE sem WHERE. UPDATE produtos SET preco = 1; muda o preço de todos os produtos de uma vez. O DBeaver até pergunta se você tem certeza — mas, no terminal, ninguém pergunta.

Etapa 6 — DELETE (apagar)

SQL — etapa 6 
DELETE FROM produtos WHERE nome = 'Webcam Full HD';

SELECT * FROM produtos WHERE nome = 'Webcam Full HD';

"Apague de produtos a linha da Webcam." O SELECT depois volta vazio (0 linhas): ela sumiu. Se você inserir outro produto agora, ele ganha o id 5, não o 4: o AUTO_INCREMENT nunca reaproveita números.

Etapa 7 — o banco se defende: erros de propósito

As tabelas têm regras (veja o 01-init.sql na parte ⑥). Tente quebrá-las — rode um de cada vez:

SQL — etapa 7 (os dois DEVEM dar erro) 
-- Preço negativo: barrado pela regra CHECK (preco > 0)
INSERT INTO produtos (nome, preco, estoque, categoria_id) VALUES ('Produto X', -10, 1, 1);

-- Categoria 999, que não existe: barrado pela chave estrangeira (FOREIGN KEY)
INSERT INTO produtos (nome, preco, estoque, categoria_id) VALUES ('Produto Y', 10, 1, 999);

Erros esperados: "Check constraint 'chk_preco' is violated" e "Cannot add or update a child row: a foreign key constraint fails". É uma boa notícia: o banco recusou dado errado, mesmo que a API tenha um bug. É a última linha de defesa.

Etapa 8 — contas com os dados (agregação)

SQL — etapa 8 
SELECT c.nome AS categoria,
       COUNT(*)     AS quantidade,
       AVG(p.preco) AS preco_medio,
       SUM(p.estoque) AS estoque_total
  FROM produtos p
  JOIN categorias c ON c.id = p.categoria_id
 GROUP BY c.nome;

GROUP BY c.nome = "faça um grupo por categoria" · COUNT(*) = quantos produtos · AVG = média · SUM = soma. Resultado: Periféricos — 2 produtos, preço médio 269.70, estoque 35 · Áudio — 1 produto, 420.00, estoque 10. É assim que se fazem relatórios.

Você usouPara que serve
SELECT … FROM … WHERE … ORDER BYLer: escolher colunas, filtrar linhas, ordenar
JOIN … ON …Juntar tabelas pelas chaves
INSERT INTO … VALUESCriar linhas
UPDATE … SET … WHEREAtualizar linhas (sempre com WHERE!)
DELETE FROM … WHEREApagar linhas (sempre com WHERE!)
COUNT · AVG · SUM + GROUP BYFazer contas por grupo (relatórios)
⌨️ Prefere o terminal? O mesmo CRUD pelo cliente mysql

1) No terminal, entre no MySQL que está dentro do container:

terminal 
docker exec -it dev_mysql_server mysql -u devuser -pdevpass loja_db

docker exec = "rode um comando dentro de um container" · -it = "no modo conversa" (você digita, ele responde) · dev_mysql_server = qual container · mysql -u devuser -pdevpass loja_db = o programa cliente do MySQL, com usuário, senha (colada no -p, sem espaço) e banco. O terminal muda para mysql>: a partir daqui você digita SQL, não comandos do sistema.

2) Rode as etapas 1 a 8 acima, um comando por vez (cada um termina em ; + Enter). Dois comandos úteis que só existem no terminal:

dentro do mysql> 
SHOW TABLES;            -- lista as tabelas do banco
DESCRIBE produtos;      -- mostra as colunas e os tipos da tabela
EXIT;                   -- sai do mysql e volta ao terminal normal

No Docker Desktop dá para chegar no mesmo lugar sem o docker exec: Containers → clique em dev_mysql_server → aba Exec → digite mysql -u devuser -pdevpass loja_db.

⑤ 🍃 MongoDB na prática (MongoDB Compass)

⬇️ Site do Compass ↗

O MongoDB Compass é o programa oficial e gratuito para ver e mexer no MongoDB. Lembre a diferença (Tab 1): no MongoDB não há tabelas com colunas fixas, e sim coleções de documentos — fichas em formato JSON.

1🖱️ Instalar e conectar

  1. Entre em mongodb.com/try/download/compass → Platform: Windows 64-bit, Package: exe → Download → abra o arquivo (ele instala e abre sozinho).
  2. Na tela inicial, clique em Add new connection ("nova conexão") — ou + ao lado de Connections.
  3. No campo URI, apague o que estiver lá e cole:
URI de conexão 
mongodb://root:root123@localhost:27017/?authSource=admin

Lendo o endereço: mongodb:// = o tipo de banco · root:root123 = usuário e senha · @localhost:27017 = "neste computador, na porta 27017" · ?authSource=admin = "a senha está cadastrada no banco admin" (é onde o usuário root mora).

  1. Em Name, escreva Docker local → Save & Connect ("salvar e conectar").
  2. Na coluna da esquerda, abra loja_nosql → clique em produtos. Os 3 documentos aparecem como fichas. No topo, os botões trocam a visualização: lista, JSON ou tabela.
👀 Compare com o MySQL: o documento traz a categoria escrita dentro ("categoria": "Periféricos") e uma lista de tags. No MySQL, a categoria fica noutra tabela (e precisa de JOIN) e uma lista pediria uma terceira tabela. O _id com letras e números (ObjectId) é o "id" que o MongoDB cria sozinho.
⚠️ "Authentication failed"? Faltou o ?authSource=admin no fim do endereço, ou a senha foi digitada errado. "connect ECONNREFUSED"? O container dev_mongo_server não está ligado (Docker Desktop).

2🖱️ O CRUD pelo Compass

  1. READ com filtro: na barra Filter ("filtro"), no topo da lista, cole { preco: { $gt: 200 } } → Find. Aparecem só o Teclado e o Headset. Lendo: "documentos em que preco é $gt (greater than, maior que) 200". Limpe o filtro (Reset) para ver todos de novo.
  2. CREATE: botão verde ADD DATA → Insert document ("inserir documento") → apague o conteúdo da janela e cole o documento abaixo → Insert.
documento para colar no Insert document do Compass 
{
  "nome": "Webcam Full HD",
  "preco": { "$numberDecimal": "259.90" },
  "estoque": 8,
  "categoria": "Periféricos",
  "tags": ["webcam", "video"]
}

O { "$numberDecimal": "259.90" } é o jeito de escrever um Decimal128 (número exato, para dinheiro) nesta janela. Não informamos _id: o MongoDB cria sozinho.

  1. UPDATE: passe o mouse sobre o documento da Webcam → ícone de lápis ✏️ (Edit document) → clique no valor de estoque, troque 8 por 13 → Update. Pelo mesmo lápis dá para acrescentar um campo (o + à esquerda de uma linha) — algo impossível no MySQL sem mudar a tabela inteira.
  2. DELETE: ícone de lixeira 🗑 no documento da Webcam → Delete para confirmar.

3O mesmo CRUD por comandos (dentro do Compass)

Embaixo da janela do Compass há uma faixa >_MONGOSH: clique nela para abrir um terminal do MongoDB, já conectado. Rode um comando por vez (Enter executa):

mongosh — um comando por vez 
use loja_nosql

// READ: todos os documentos
db.produtos.find()

// READ com filtro (preço > 200) e só os campos nome e preco (1 = mostrar)
db.produtos.find({ preco: { $gt: 200 } }, { nome: 1, preco: 1 })

// CREATE: um documento novo (NumberDecimal = número exato, para dinheiro)
db.produtos.insertOne({ nome: "Monitor 27 144Hz", preco: NumberDecimal("1899.00"), estoque: 5, categoria: "Vídeo", tags: ["monitor"] })

// UPDATE: $set troca o valor de um campo; $inc soma ao valor atual
db.produtos.updateOne({ nome: "Monitor 27 144Hz" }, { $set: { preco: NumberDecimal("1799.00") }, $inc: { estoque: 3 } })

// DELETE: apaga o primeiro documento que bater com o filtro
db.produtos.deleteOne({ nome: "Monitor 27 144Hz" })

// Quantos documentos existem?
db.produtos.countDocuments()
CRUD🐬 MySQL (SQL)🍃 MongoDB (mongosh)
CriarINSERT INTO produtos … VALUES …db.produtos.insertOne({ … })
LerSELECT … FROM produtos WHERE preco > 200db.produtos.find({ preco: { $gt: 200 } })
AtualizarUPDATE produtos SET … WHERE …db.produtos.updateOne({ filtro }, { $set: { … } })
ApagarDELETE FROM produtos WHERE …db.produtos.deleteOne({ filtro })

⑥ 📦 De onde vieram as tabelas e os dados?

Você ligou os bancos e eles já tinham tabelas e produtos. Quem fez isso foram os scripts das pastas init-sql e init-mongo. O compose liga essas pastas a uma pasta especial dos containers, a /docker-entrypoint-initdb.d: tudo o que estiver lá roda sozinho, uma única vez — quando o banco é criado pela primeira vez (com o volume vazio), em ordem alfabética (01-…, 02-…).

Tipo de comandoPara que serveExemplos

DML — Data Manipulation LanguageMexe nos dados dentro das tabelasINSERT, SELECT, UPDATE, DELETE — o CRUD da parte ④

🐬 MySQL: tabelas + dados

init-sql/01-init.sql 
-- =====================================================================
--  01-init.sql — cria as tabelas e os dados de exemplo do MySQL.
--  Roda sozinho UMA vez, quando o container é criado com o volume vazio.
--  Para rodar de novo: docker compose down -v  e depois  docker compose up -d
-- =====================================================================

USE loja_db;   -- "trabalhe dentro do banco loja_db"

-- ── Tabela CATEGORIAS ────────────────────────────────────────────────
-- Cada categoria tem um número (id) e um nome.
CREATE TABLE IF NOT EXISTS categorias (
  id   INT AUTO_INCREMENT PRIMARY KEY,   -- o MySQL numera sozinho: 1, 2, 3...
  nome VARCHAR(60) NOT NULL UNIQUE       -- texto de até 60 letras; obrigatório; sem repetir
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

-- ── Tabela PRODUTOS ──────────────────────────────────────────────────
-- Cada produto PERTENCE a uma categoria: a coluna categoria_id guarda
-- o id da categoria. Isso é uma CHAVE ESTRANGEIRA (FOREIGN KEY).
CREATE TABLE IF NOT EXISTS produtos (
  id           BIGINT AUTO_INCREMENT PRIMARY KEY,  -- BIGINT: as APIs Java/C# esperam este tipo
  nome         VARCHAR(100) NOT NULL,
  preco        DECIMAL(10,2) NOT NULL,             -- dinheiro: casas decimais EXATAS (nunca FLOAT)
  estoque      INT NOT NULL DEFAULT 0,
  categoria_id INT,
  -- A FK impede um produto de apontar para uma categoria que não existe:
  CONSTRAINT fk_cat      FOREIGN KEY (categoria_id) REFERENCES categorias(id),
  -- CHECK: regras que o banco confere em TODA gravação:
  CONSTRAINT chk_preco   CHECK (preco > 0),
  CONSTRAINT chk_estoque CHECK (estoque >= 0)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

-- ÍNDICE: um "sumário" para achar produtos pelo nome sem ler a tabela toda.
CREATE INDEX idx_nome ON produtos(nome);

-- ── Dados de exemplo (seed) ──────────────────────────────────────────
INSERT INTO categorias (nome) VALUES ('Periféricos'), ('Áudio');   -- viram id 1 e id 2

INSERT INTO produtos (nome, preco, estoque, categoria_id) VALUES
  ('Teclado Mecânico RGB',  349.90, 15, 1),
  ('Mouse Gamer 16000 DPI', 189.50, 20, 1),
  ('Headset 7.1 Surround',  420.00, 10, 2);

🍃 MongoDB: coleção + documentos

init-mongo/01-init.js 
// =====================================================================
//  01-init.js — cria a coleção e os documentos de exemplo do MongoDB.
//  Roda sozinho UMA vez, quando o container é criado com o volume vazio.
// =====================================================================

// "Trabalhe dentro do banco loja_nosql" (é criado se não existir).
db = db.getSiblingDB('loja_nosql');

// Uma COLEÇÃO é o equivalente a uma tabela: um grupo de documentos.
db.createCollection('produtos');

// ÍNDICE pelo nome — mesma ideia do idx_nome do MySQL.
db.produtos.createIndex({ nome: 1 });

// Os MESMOS 3 produtos do MySQL, agora como DOCUMENTOS (fichas em JSON).
// Repare nas diferenças:
//  • a categoria vem DENTRO do documento (não há tabela separada nem JOIN);
//  • 'tags' é uma LISTA — algo que, no MySQL, pediria outra tabela;
//  • o preço usa NumberDecimal (Decimal128): número EXATO, sem erro de
//    centavos. Um número comum (349.90) é guardado de forma aproximada.
//    É a regra que as Tabs 6-B e 9-B seguem ao migrar para o MongoDB.
db.produtos.insertMany([
  { nome: "Teclado Mecânico RGB",  preco: NumberDecimal("349.90"), estoque: 15,
    categoria: "Periféricos", tags: ["teclado", "rgb"],  criadoEm: new Date() },
  { nome: "Mouse Gamer 16000 DPI", preco: NumberDecimal("189.50"), estoque: 20,
    categoria: "Periféricos", tags: ["mouse", "gamer"], criadoEm: new Date() },
  { nome: "Headset 7.1 Surround",  preco: NumberDecimal("420.00"), estoque: 10,
    categoria: "Áudio",       tags: ["headset"],        criadoEm: new Date() }
]);

print("✅ loja_nosql.produtos: 3 documentos criados");
⚠️ Mudei o script e nada aconteceu? Normal: ele só roda quando o banco é criado. Para rodar de novo, é preciso apagar o volume e recriar — veja a parte ⑧. (Por isso as APIs das próximas abas criam as próprias tabelas, em vez de depender deste script.)

📐 D-04 ER — O modelo do MySQL: uma categoria tem muitos produtos

Como ler: cada caixa é uma tabela, com as colunas e os tipos. PK (primary key) = a chave que identifica cada linha. FK (foreign key) = a coluna que aponta para outra tabela. A linha entre as caixas diz: uma categoria (||) possui zero ou muitos produtos (o{).

⚠️ Erros comuns:
  • "port is already allocated" / "Bind for 0.0.0.0:3306 failed" ("porta já em uso") → outro programa usa a porta. Quase sempre é um MySQL instalado direto no Windows (ou o container de outra aba). Pare o outro, ou troque no compose: "3307:3306" e use 3307 no DBeaver. Para o Mongo: "27018:27017".
  • "no configuration file provided: not found" → o terminal não está na pasta do docker-compose.yml. Entre nela (cd) ou abra o terminal pela barra de endereço da pasta.
  • Container fica unhealthy / reiniciando sem parar → veja o motivo na aba Logs do container. Se você trocou senhas no compose depois da primeira vez, recomece do zero (down -v).
  • Os bancos não ligam ao abrir o computador → o Docker Desktop precisa estar aberto. Em Settings → General, marque Start Docker Desktop when you sign in ("abrir ao entrar no Windows").
