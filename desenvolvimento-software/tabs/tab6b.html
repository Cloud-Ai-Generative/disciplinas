📄 Passo 4 — O documento (ProdutoDocument)

Assim como o MySQL tem o ProdutoJpaEntity, o MongoDB ganha seu próprio modelo de persistência. O domínio Produto continua sem nenhuma anotação.

infrastructure/mongo/ProdutoDocument.java 
package com.loja.infrastructure.mongo;

import com.loja.domain.Produto;
import java.math.BigDecimal;
import org.springframework.data.annotation.Id;
import org.springframework.data.mongodb.core.mapping.Document;
import org.springframework.data.mongodb.core.mapping.Field;
import org.springframework.data.mongodb.core.mapping.FieldType;

/**
 * 📄 MODELO DE PERSISTÊNCIA do produto no MongoDB (coleção "produtos").
 *
 * Documento resultante:
 *   { _id: 1, nome: "Teclado", preco: NumberDecimal("349.90"), estoque: 15 }
 *
 * O QUE MUDOU em relação à versão antiga da Tab 6:
 * - Antes: @Id String mongoId (ObjectId) + campo "idLegado". Como mongoId ficava
 *   nulo, cada save() INSERIA um documento novo → updates e backfill duplicavam
 *   tudo, e produto novo ficava com id nulo.
 * - Agora: o próprio id Long do domínio É o _id. save() vira "substituir pelo
 *   _id ou inserir" (upsert) → idempotente por natureza, e as URLs da API
 *   (/api/produtos/1) continuam as mesmas.
 */
@Document(collection = "produtos")
public class ProdutoDocument {

    @Id
    private Long id;

    @Field("nome")
    private String nome;

    /**
     * 💰 DECIMAL128 explícito: decimal EXATO de 128 bits.
     * O Spring Data MongoDB 5 (Spring Boot 4) não define mais uma representação
     * padrão para BigDecimal — sem isto, o preço não seria gravado de forma
     * confiável (e somas/ordenações no banco ficariam erradas se virasse texto).
     */
    @Field(name = "preco", targetType = FieldType.DECIMAL128)
    private BigDecimal preco;

    @Field("estoque")
    private Integer estoque;

    public ProdutoDocument() {}

    /** Domínio → documento (o id já precisa estar definido). */
    public static ProdutoDocument de(Produto p, Long id) {
        ProdutoDocument d = new ProdutoDocument();
        d.id = id;
        d.nome = p.getNome();
        d.preco = p.getPreco();
        d.estoque = p.getEstoque();
        return d;
    }

    /** Documento → domínio. */
    public Produto paraDominio() {
        return new Produto(id, nome, preco, estoque);
    }

    public Long getId() { return id; }
    public String getNome() { return nome; }
    public BigDecimal getPreco() { return preco; }
    public Integer getEstoque() { return estoque; }
}
⚠️ Por que targetType = FieldType.DECIMAL128: o Spring Data MongoDB 5 (Spring Boot 4) não define mais uma representação padrão para BigDecimal. Sem declarar, o preço não é gravado de forma confiável. Decimal128 é exato: 349.90 continua 349.90 — essencial para "migrar com precisão".

🔢 Passo 5 — Ids sem AUTO_INCREMENT (SequenceGenerator)

No MongoDB não existe AUTO_INCREMENT. A coleção counters com $inc atômico gera ids Long — e o método garantirMinimo resolve um problema específico da migração online: durante o dual-write quem gera os ids é o MySQL; no cut-over, o Mongo precisa continuar a numeração depois do maior id existente.

infrastructure/mongo/SequenceGenerator.java 
package com.loja.infrastructure.mongo;

import org.springframework.data.annotation.Id;
import org.springframework.data.mongodb.core.FindAndModifyOptions;
import org.springframework.data.mongodb.core.MongoTemplate;
import org.springframework.data.mongodb.core.mapping.Document;
import org.springframework.data.mongodb.core.query.Criteria;
import org.springframework.data.mongodb.core.query.Query;
import org.springframework.data.mongodb.core.query.Update;
import org.springframework.stereotype.Component;

/**
 * 🔢 Gerador de ids Long para o MongoDB (substitui o AUTO_INCREMENT).
 *
 * Coleção "counters":  { _id: "produtos", seq: 42 }
 *
 * proximo():        findAndModify + $inc  → atômico: duas requests simultâneas
 *                   nunca recebem o mesmo número.
 * garantirMinimo(): update + $max         → o contador nunca fica ATRÁS de um id
 *                   que já existe. Essencial na migração: durante o dual-write
 *                   quem gera os ids é o MySQL; quando o Mongo assumir sozinho
 *                   (cut-over), ele precisa continuar DEPOIS do maior id.
 */
@Component
public class SequenceGenerator {

    /** Documento da coleção de contadores. */
    @Document(collection = "counters")
    public static class Sequencia {
        @Id private String id;
        private long seq;
        public String getId() { return id; }
        public long getSeq() { return seq; }
    }

    private final MongoTemplate mongo;

    public SequenceGenerator(MongoTemplate mongo) { this.mongo = mongo; }

    /** Reserva e devolve o próximo id da sequência (cria a sequência se não existir). */
    public long proximo(String nome) {
        Sequencia s = mongo.findAndModify(
            Query.query(Criteria.where("_id").is(nome)),
            new Update().inc("seq", 1L),
            FindAndModifyOptions.options().returnNew(true).upsert(true),
            Sequencia.class);
        return s.getSeq();
    }

    /** Garante seq >= valor ($max nunca diminui; rodar várias vezes é seguro). */
    public void garantirMinimo(String nome, long valor) {
        mongo.upsert(
            Query.query(Criteria.where("_id").is(nome)),
            new Update().max("seq", valor),
            Sequencia.class);
    }
}
⚠️ Erro clássico: E11000 duplicate key error ... _id: 5 depois do cut-over → o contador ficou atrás dos ids que vieram do MySQL. Aqui isso é evitado em dois lugares: todo salvar com id chama garantirMinimo, e o backfill ajusta o contador ao final. Conferência: use loja_nosql; db.counters.find().

🍃 Passo 6 — MongoProdutoRepository (mesma porta, outro banco)

Implementa os mesmos 6 métodos do adapter JPA, com a mesma semântica — inclusive a ordenação por id na paginação, para que a página 2 traga os mesmos produtos nos dois bancos.

infrastructure/mongo/MongoProdutoRepository.java (🔌 Adapter Mongo) 
package com.loja.infrastructure.mongo;

import com.loja.domain.Produto;
import com.loja.domain.ProdutoRepository;
import java.util.List;
import java.util.Optional;
import org.springframework.data.domain.Sort;
import org.springframework.data.mongodb.core.MongoTemplate;
import org.springframework.data.mongodb.core.query.Criteria;
import org.springframework.data.mongodb.core.query.Query;

/**
 * 🔌 ADAPTER MongoDB da porta ProdutoRepository.
 *
 * Mesma porta e MESMA semântica do ProdutoRepositoryAdapter (JPA):
 * | Operação     | JPA / MySQL                     | MongoDB                               |
 * |--------------|---------------------------------|---------------------------------------|
 * | salvar novo  | INSERT + AUTO_INCREMENT         | id da sequência + save (insert)       |
 * | salvar c/ id | UPDATE                          | save = replace pelo _id (upsert)      |
 * | listarPagina | ORDER BY id LIMIT/OFFSET        | sort({_id:1}).skip().limit()          |
 * | existePorId  | SELECT 1 ... WHERE id           | exists({_id})                         |
 * | deletarPorId | DELETE ... WHERE id             | deleteOne({_id})                      |
 *
 * Sem @Repository: quem decide se ele é usado é o PersistenceConfig.
 */
public class MongoProdutoRepository implements ProdutoRepository {

    static final String SEQUENCIA = "produtos";

    private final MongoTemplate mongo;
    private final SequenceGenerator sequencias;

    public MongoProdutoRepository(MongoTemplate mongo, SequenceGenerator sequencias) {
        this.mongo = mongo;
        this.sequencias = sequencias;
    }

    @Override
    public Produto salvar(Produto p) {
        Long id;
        if (p.getId() == null) {
            // Produto novo: o Mongo gera o id (não há AUTO_INCREMENT)
            id = sequencias.proximo(SEQUENCIA);
        } else {
            // Id veio de fora (update, dual-write ou backfill): mantém o id e
            // empurra o contador para nunca gerar um id que já existe
            id = p.getId();
            sequencias.garantirMinimo(SEQUENCIA, id);
        }
        // save() com _id definido = substitui o documento ou insere (upsert)
        mongo.save(ProdutoDocument.de(p, id));
        return new Produto(id, p.getNome(), p.getPreco(), p.getEstoque());
    }

    @Override
    public Optional<Produto> buscarPorId(Long id) {
        return Optional.ofNullable(mongo.findById(id, ProdutoDocument.class))
                .map(ProdutoDocument::paraDominio);
    }

    @Override
    public List<Produto> listarPagina(int page, int size) {
        // Paginação NO BANCO, na mesma ordem do adapter JPA (por id)
        Query q = new Query()
                .with(Sort.by("_id"))
                .skip((long) page * size)
                .limit(size);
        return mongo.find(q, ProdutoDocument.class).stream()
                .map(ProdutoDocument::paraDominio).toList();
    }

    @Override
    public List<Produto> listarTodos() {
        return mongo.find(new Query().with(Sort.by("_id")), ProdutoDocument.class).stream()
                .map(ProdutoDocument::paraDominio).toList();
    }

    @Override
    public boolean existePorId(Long id) {
        return mongo.exists(porId(id), ProdutoDocument.class);
    }

    @Override
    public void deletarPorId(Long id) {
        mongo.remove(porId(id), ProdutoDocument.class);
    }

    private static Query porId(Long id) {
        return Query.query(Criteria.where("_id").is(id));
    }
}

✍️ Passo 7 — Dual-write e o PersistenceConfig com 3 modos

O DualWriteProdutoRepository é um adapter que envolve os outros dois: escreve no MySQL (a verdade) e espelha no Mongo; lê sempre do MySQL. Repare que ele recebe duas portas — é o padrão Decorator/Composite aplicado ao Repository.

infrastructure/persistence/DualWriteProdutoRepository.java (✍️✍️ dual-write) 
package com.loja.infrastructure.persistence;

import com.loja.domain.Produto;
import com.loja.domain.ProdutoRepository;
import java.util.List;
import java.util.Optional;
import org.slf4j.Logger;
import org.slf4j.LoggerFactory;

/**
 * ✍️✍️ DUAL-WRITE — fases 1 e 2 da migração (persistence.provider = dual).
 *
 * Regra: o MySQL continua sendo a FONTE DA VERDADE.
 *   - ESCRITA: primeiro no MySQL (gera o id); depois a MESMA coisa, com o
 *     MESMO id, no MongoDB.
 *   - LEITURA: sempre do MySQL (o Mongo ainda está "pegando o bonde").
 *
 * E se o Mongo falhar depois do MySQL já ter gravado?
 * Não dá para desfazer o commit do MySQL de forma confiável (são dois bancos,
 * sem transação distribuída). A decisão aqui é: a API NÃO falha para o usuário
 * (o MySQL, que é a verdade, gravou), registramos um aviso no log, e a
 * divergência é corrigida pela RECONCILIAÇÃO (Passo 10), que compara os dois
 * bancos e recopia o que estiver diferente. Este é o "contrato" do dual-write:
 * consistência EVENTUAL no Mongo, garantida por reconciliação.
 * (Em produção: padrão Outbox / CDC para não depender só do log.)
 */
public class DualWriteProdutoRepository implements ProdutoRepository {

    private static final Logger log = LoggerFactory.getLogger(DualWriteProdutoRepository.class);

    private final ProdutoRepository mysql;   // fonte da verdade
    private final ProdutoRepository mongo;   // destino da migração

    public DualWriteProdutoRepository(ProdutoRepository mysql, ProdutoRepository mongo) {
        this.mysql = mysql;
        this.mongo = mongo;
    }

    @Override
    public Produto salvar(Produto p) {
        Produto salvo = mysql.salvar(p);          // 1) verdade: gera/mantém o id
        try {
            mongo.salvar(salvo);                  // 2) espelho: mesmo id
        } catch (RuntimeException e) {
            log.warn("DUAL-WRITE: falha ao gravar produto {} no MongoDB — será corrigido pela reconciliação",
                     salvo.getId(), e);
        }
        return salvo;
    }

    @Override
    public void deletarPorId(Long id) {
        mysql.deletarPorId(id);
        try {
            mongo.deletarPorId(id);
        } catch (RuntimeException e) {
            log.warn("DUAL-WRITE: falha ao remover produto {} do MongoDB — será corrigido pela reconciliação", id, e);
        }
    }

    // ── Leituras: sempre da fonte da verdade (MySQL) ──
    @Override public Optional<Produto> buscarPorId(Long id) { return mysql.buscarPorId(id); }
    @Override public List<Produto> listarPagina(int page, int size) { return mysql.listarPagina(page, size); }
    @Override public List<Produto> listarTodos() { return mysql.listarTodos(); }
    @Override public boolean existePorId(Long id) { return mysql.existePorId(id); }
}

    public ProdutoRepository produtoRepository(
            @Value("${persistence.provider:relational}") String provider,
            SpringDataProdutoRepository jpaRepo,
            MongoTemplate mongoTemplate,
            SequenceGenerator sequencias) {

            case "relational" -> new ProdutoRepositoryAdapter(jpaRepo);
            case "dual" -> new DualWriteProdutoRepository(
                    new ProdutoRepositoryAdapter(jpaRepo),
                    new MongoProdutoRepository(mongoTemplate, sequencias));
            case "nosql" -> new MongoProdutoRepository(mongoTemplate, sequencias);
            default -> throw new IllegalStateException(
                    "persistence.provider inválido: '" + provider
                    + "'. Valores aceitos: relational | dual | nosql");
        };
    }

package com.loja.infrastructure.migration;

import com.loja.domain.Produto;
import com.loja.infrastructure.mongo.ProdutoDocument;
import com.loja.infrastructure.mongo.SequenceGenerator;
import com.loja.infrastructure.persistence.ProdutoRepositoryAdapter;
import java.util.List;
import org.springframework.data.mongodb.core.BulkOperations;
import org.springframework.data.mongodb.core.FindAndReplaceOptions;
import org.springframework.data.mongodb.core.MongoTemplate;
import org.springframework.data.mongodb.core.query.Criteria;
import org.springframework.data.mongodb.core.query.Query;

/**
 * 🚚 BACKFILL (fase 2): copia o HISTÓRICO do MySQL para o MongoDB.
 *
 * O dual-write (fase 1) só espelha o que muda DEPOIS de ligado. Os produtos
 * antigos, que ninguém tocou, ainda não estão no Mongo — o backfill os copia.
 *
 * Propriedades:
 * - ONLINE: roda com a API no ar (em modo dual), sem janela de manutenção.
 * - IDEMPOTENTE: "substitui pelo _id ou insere" (upsert). Rodar 2x = mesmo resultado.
 * - EM LOTES: lê páginas do MySQL e grava cada página com um bulkWrite
 *   (1 ida ao Mongo por lote, não por produto).
 *
 * ⚠️ Corrida conhecida: se um produto for ATUALIZADO pela API entre o momento
 * em que o backfill o leu e o momento em que o gravou, o backfill pode gravar
 * a versão antiga por cima da nova. Por isso, depois do backfill SEMPRE vem a
 * RECONCILIAÇÃO, que compara os dois bancos e recopia o que divergir.
 */
public class BackfillService {

    private final ProdutoRepositoryAdapter mysql;
    private final MongoTemplate mongo;
    private final SequenceGenerator sequencias;
    private final int tamanhoLote;

    public BackfillService(ProdutoRepositoryAdapter mysql, MongoTemplate mongo,
                           SequenceGenerator sequencias, int tamanhoLote) {
        this.mysql = mysql;
        this.mongo = mongo;
        this.sequencias = sequencias;
        this.tamanhoLote = tamanhoLote;
    }

    /** Executa o backfill e devolve quantos produtos foram copiados. */
    public long executar() {
        long total = 0;
        long maiorId = 0;

        for (int pagina = 0; ; pagina++) {
            // Página do MySQL (ordenada por id). Para tabelas gigantes, prefira
            // paginação por chave (WHERE id > ultimoId) em vez de OFFSET.
            List<Produto> lote = mysql.listarPagina(pagina, tamanhoLote);
            if (lote.isEmpty()) break;

            // bulkWrite não ordenado: o Mongo processa o lote em paralelo
            BulkOperations bulk = mongo.bulkOps(BulkOperations.BulkMode.UNORDERED, ProdutoDocument.class);
            for (Produto p : lote) {
                bulk.replaceOne(
                    Query.query(Criteria.where("_id").is(p.getId())),
                    ProdutoDocument.de(p, p.getId()),
                    FindAndReplaceOptions.options().upsert());
                maiorId = Math.max(maiorId, p.getId());
            }
            bulk.execute();

            total += lote.size();
            System.out.printf("   ✔ backfill: lote %d gravado (%d produtos até agora)%n", pagina + 1, total);
        }

        // Contador ≥ maior id copiado: no cut-over, o Mongo continua a numeração
        if (maiorId > 0)
            sequencias.garantirMinimo("produtos", maiorId);

        return total;
    }
}

package com.loja.infrastructure.migration;

import com.loja.infrastructure.mongo.MongoProdutoRepository;
import com.loja.infrastructure.mongo.SequenceGenerator;
import com.loja.infrastructure.persistence.ProdutoRepositoryAdapter;
import com.loja.infrastructure.persistence.SpringDataProdutoRepository;
import org.springframework.beans.factory.annotation.Value;
import org.springframework.boot.ApplicationArguments;
import org.springframework.boot.ApplicationRunner;
import org.springframework.boot.SpringApplication;
import org.springframework.context.ApplicationContext;
import org.springframework.data.mongodb.core.MongoTemplate;
import org.springframework.stereotype.Component;

/**
 * 🎛️ Orquestra as tarefas de migração, ligadas por propriedades:
 *
 *   --migracao.backfill=true     copia o histórico MySQL → Mongo
 *   --migracao.reconciliar=true  compara os dois bancos e gera o relatório
 *   --migracao.corrigir=true     (com reconciliar) recopia o que divergir
 *   --migracao.encerrar=true     encerra o processo ao final (código 0/1)
 *
 * Uso típico: uma SEGUNDA instância do mesmo JAR, sem servidor web, rodando
 * as tarefas enquanto a API "de verdade" continua atendendo em modo dual:
 *   java -jar app.jar --spring.main.web-application-type=none \
 *        --migracao.backfill=true --migracao.reconciliar=true --migracao.encerrar=true
 *
 * Sem nenhuma dessas propriedades, este runner não faz nada.
 */
@Component
public class MigracaoRunner implements ApplicationRunner {

    private final SpringDataProdutoRepository jpaRepo;
    private final MongoTemplate mongo;
    private final SequenceGenerator sequencias;
    private final ApplicationContext contexto;

    @Value("${migracao.backfill:false}") private boolean backfill;
    @Value("${migracao.reconciliar:false}") private boolean reconciliar;
    @Value("${migracao.corrigir:false}") private boolean corrigir;
    @Value("${migracao.encerrar:false}") private boolean encerrar;
    @Value("${migracao.tamanho-lote:500}") private int tamanhoLote;

    public MigracaoRunner(SpringDataProdutoRepository jpaRepo, MongoTemplate mongo,
                          SequenceGenerator sequencias, ApplicationContext contexto) {
        this.jpaRepo = jpaRepo;
        this.mongo = mongo;
        this.sequencias = sequencias;
        this.contexto = contexto;
    }

    @Override
    public void run(ApplicationArguments args) {
        if (!backfill && !reconciliar) return;

        // Os adapters são usados DIRETAMENTE (não o bean do PersistenceConfig):
        // a migração precisa enxergar cada banco separadamente.
        var mysqlAdapter = new ProdutoRepositoryAdapter(jpaRepo);
        var mongoAdapter = new MongoProdutoRepository(mongo, sequencias);
        boolean ok = true;

        if (backfill) {
            System.out.println("\n🚚 BACKFILL MySQL → MongoDB (lotes de " + tamanhoLote + ")");
            long n = new BackfillService(mysqlAdapter, mongo, sequencias, tamanhoLote).executar();
            System.out.println("✅ Backfill concluído: " + n + " produto(s) copiado(s)\n");
        }

        if (reconciliar) {
            System.out.println("🔍 RECONCILIAÇÃO MySQL × MongoDB" + (corrigir ? " (com correção)" : ""));
            ok = new ReconciliacaoService(mysqlAdapter, mongoAdapter).executar(corrigir);
        }

        if (encerrar) {
            int codigo = ok ? 0 : 1;   // útil em scripts e CI
            System.exit(SpringApplication.exit(contexto, () -> codigo));
        }
    }
}

🔍 Passo 10 — Reconciliação: provar (e corrigir) a precisão

A reconciliação compara MySQL e MongoDB em três camadas — contagem, somas de controle (Σ estoque, Σ preço × estoque) e campo a campo — e gera relatorio-reconciliacao.md. Com --migracao.corrigir=true, recopia do MySQL (a verdade) tudo o que divergir.

infrastructure/migration/ReconciliacaoService.java 
package com.loja.infrastructure.migration;

import com.loja.domain.Produto;
import com.loja.infrastructure.mongo.MongoProdutoRepository;
import com.loja.infrastructure.persistence.ProdutoRepositoryAdapter;
import java.io.IOException;
import java.math.BigDecimal;
import java.nio.file.Files;
import java.nio.file.Path;
import java.time.Instant;
import java.util.*;
import java.util.function.Function;
import java.util.stream.Collectors;

/**
 * 🔍 RECONCILIAÇÃO: prova (e opcionalmente corrige) que o MongoDB é igual ao MySQL.
 *
 * "Migrar com precisão" precisa ser DEMONSTRADO, em três camadas:
 *   1) CONTAGEM            → pega registros perdidos ou duplicados;
 *   2) SOMAS DE CONTROLE   → Σ estoque e Σ preço×estoque: pega conversões erradas
 *                            (ex.: preço que perdeu centavos) mesmo com contagem certa;
 *   3) CAMPO A CAMPO       → "assinatura" de cada produto nos dois lados.
 *
 * Com corrigir = true (só faz sentido enquanto o MySQL é a verdade, fases 1–2):
 *   - faltando no Mongo  → copia do MySQL
 *   - diferente          → recopia do MySQL (resolve a corrida do backfill)
 *   - sobrando no Mongo  → remove (ex.: delete do dual-write que falhou)
 */
public class ReconciliacaoService {

    private final ProdutoRepositoryAdapter mysql;
    private final MongoProdutoRepository mongo;

    public ReconciliacaoService(ProdutoRepositoryAdapter mysql, MongoProdutoRepository mongo) {
        this.mysql = mysql;
        this.mongo = mongo;
    }

    /** Assinatura normalizada: 349.9 e 349.90 são o mesmo preço. */
    static String assinatura(Produto p) {
        BigDecimal preco = p.getPreco() == null ? null : p.getPreco().stripTrailingZeros();
        return p.getId() + "|" + p.getNome() + "|"
             + (preco == null ? "null" : preco.toPlainString()) + "|" + p.getEstoque();
    }

    /** @return true se, ao final, os dois bancos estiverem equivalentes */
    public boolean executar(boolean corrigir) {
        Map<Long, Produto> origem = indexar(mysql.listarTodos());
        Map<Long, Produto> destino = indexar(mongo.listarTodos());

        List<Long> faltando = origem.keySet().stream().filter(id -> !destino.containsKey(id)).sorted().toList();
        List<Long> sobrando = destino.keySet().stream().filter(id -> !origem.containsKey(id)).sorted().toList();
        List<Long> diferentes = origem.keySet().stream()
                .filter(destino::containsKey)
                .filter(id -> !assinatura(origem.get(id)).equals(assinatura(destino.get(id))))
                .sorted().toList();

        var r = new StringBuilder();
        r.append("# Relatório de reconciliação — MySQL × MongoDB\n\n")
         .append("Gerado em: ").append(Instant.now()).append("\n\n")
         .append("| Verificação | MySQL | MongoDB | OK |\n|---|---:|---:|:-:|\n");

        boolean ok = true;
        ok &= linha(r, "quantidade de produtos", origem.size(), destino.size());
        ok &= linha(r, "Σ estoque", soma(origem, p -> BigDecimal.valueOf(p.getEstoque())),
                                    soma(destino, p -> BigDecimal.valueOf(p.getEstoque())));
        ok &= linha(r, "Σ preço × estoque (R$)",
                soma(origem, p -> p.getPreco().multiply(BigDecimal.valueOf(p.getEstoque()))),
                soma(destino, p -> p.getPreco().multiply(BigDecimal.valueOf(p.getEstoque()))));
        boolean iguais = faltando.isEmpty() && sobrando.isEmpty() && diferentes.isEmpty();
        r.append("| produtos idênticos (campo a campo) | ").append(origem.size()).append(" | ")
         .append(origem.size() - faltando.size() - diferentes.size()).append(" | ")
         .append(iguais ? "✅" : "❌").append(" |\n");
        ok &= iguais;

        if (!iguais) {
            r.append("\n## Divergências (até 10 de cada)\n\n```\n");
            faltando.stream().limit(10).forEach(id -> r.append("FALTANDO no Mongo: id ").append(id).append('\n'));
            sobrando.stream().limit(10).forEach(id -> r.append("SOBRANDO no Mongo: id ").append(id).append('\n'));
            diferentes.stream().limit(10).forEach(id -> r.append("DIFERENTE id ").append(id)
                    .append("\n   MySQL: ").append(assinatura(origem.get(id)))
                    .append("\n   Mongo: ").append(assinatura(destino.get(id))).append('\n'));
            r.append("```\n");
        }

        if (corrigir && !iguais) {
            faltando.forEach(id -> mongo.salvar(origem.get(id)));
            diferentes.forEach(id -> mongo.salvar(origem.get(id)));
            sobrando.forEach(mongo::deletarPorId);
            r.append("\n🔧 Correção aplicada: ").append(faltando.size()).append(" copiado(s), ")
             .append(diferentes.size()).append(" recopiado(s), ")
             .append(sobrando.size()).append(" removido(s). Rode a reconciliação de novo para confirmar.\n");
        }

        r.append("\n**Resultado: ").append(ok ? "🟢 EQUIVALENTES" : "🔴 DIVERGENTES").append("**\n");

        System.out.println(r);
        try {
            Files.writeString(Path.of("relatorio-reconciliacao.md"), r.toString());
            System.out.println("📝 Relatório salvo em: " + Path.of("relatorio-reconciliacao.md").toAbsolutePath());
        } catch (IOException e) {
            System.out.println("⚠️ Não foi possível salvar o relatório: " + e.getMessage());
        }
        return ok;
    }

    private static Map<Long, Produto> indexar(List<Produto> lista) {
        return lista.stream().collect(Collectors.toMap(Produto::getId, Function.identity()));
    }

    private static BigDecimal soma(Map<Long, Produto> m, Function<Produto, BigDecimal> f) {
        return m.values().stream().map(f).reduce(BigDecimal.ZERO, BigDecimal::add);
    }

    private static boolean linha(StringBuilder r, String nome, Object mysql, Object mongo) {
        boolean ok = (mysql instanceof BigDecimal a && mongo instanceof BigDecimal b)
                ? a.compareTo(b) == 0     // compareTo: 10.0 == 10.00
                : Objects.equals(mysql, mongo);
        r.append("| ").append(nome).append(" | ").append(mysql).append(" | ").append(mongo)
         .append(" | ").append(ok ? "✅" : "❌").append(" |\n");
        return ok;
    }
}
