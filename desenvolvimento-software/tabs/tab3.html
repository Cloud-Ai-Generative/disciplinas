⓪ 🔷 Conhecendo o C# e o .NET (5 minutos de leitura)

Em uma frase: C# (lê-se "cê-charp") é uma linguagem de programação criada pela Microsoft em 2000, sob a liderança de Anders Hejlsberg. Ela roda sobre o .NET, a plataforma gratuita e de código aberto que transforma o seu código em programa — no Windows, no Mac e no Linux.

🤔 C# ou .NET? O C# é a língua em que você escreve. O .NET é a plataforma: o compilador, as bibliotecas prontas e a máquina que executa. É como "português" (a língua) e "a gráfica e a editora" (quem transforma o texto em livro).

Como o seu código vira programa

O .NET compila o C# para uma linguagem intermediária (IL), que fica dentro de um arquivo .dll. Na hora de rodar, o runtime do .NET traduz a IL para a linguagem da sua máquina. Igual à ideia do Java com a JVM (Tab 2). No VS Code, tudo isso acontece com Ctrl+F5.

1🖱️ Baixar e instalar o VS Code (Windows)

  5. Tela License Agreement (contrato de licença): marque I accept the agreement ("Eu aceito") → Next ("Avançar").
  6. Telas Select Destination Location (onde instalar) e Select Start Menu Folder (pasta no Menu Iniciar): não mude nada → Next → Next.

    • ☑ Add to PATH — deixa o Windows achar o VS Code a partir do terminal. Já vem marcado: não desmarque.
    • ☑ Create a desktop icon (opcional) — um atalho na área de trabalho.
    → Next.
  8. Tela Ready to Install (pronto para instalar) → Install ("Instalar"). Espere a barra encher (menos de 1 minuto).

2🖱️ Baixar e instalar o .NET 10 SDK (Windows)

  1. No navegador, entre em dotnet.microsoft.com/download/dotnet/10.0 (clique no link: abre numa aba nova).
  2. A página tem duas colunas. Procure a coluna SDK (à esquerda) — não a de Runtime. Na linha Windows, em Installers, clique em x64.
    ❓ x64 ou Arm64? Quase todo computador com Windows é x64. Só escolha Arm64 se o seu notebook tiver processador Snapdragon (ex.: alguns Surface e "Copilot+ PC"). Na dúvida: tecla Windows → digite "Sobre o seu PC" → veja Tipo de sistema.
  3. Abra o arquivo baixado (algo como dotnet-sdk-10.0.xxx-win-x64.exe) com dois cliques.
  4. Na janela do instalador, clique em Install ("Instalar") e em Sim quando o Windows pedir permissão.
  5. Espere aparecer Installation was successful ("A instalação foi concluída com sucesso") → Close ("Fechar").
⚠️ Instalou o .NET com o VS Code aberto? Feche o VS Code e abra de novo. Programas que já estavam abertos não "enxergam" o que foi instalado depois.

4🖱️ Instalar a extensão C# Dev Kit

Sozinho, o VS Code não entende C#. A extensão C# Dev Kit ensina: cores no código, autocompletar, avisos de erro enquanto você digita e o botão de rodar.

  1. Na barra de atividades (esquerda), clique no ícone de quatro quadradinhos ⊞ — é o Extensions (atalho Ctrl+Shift+X).
  2. Na caixa de busca que aparece no topo, digite C# Dev Kit.
  3. Clique no resultado C# Dev Kit, publicado pela Microsoft (confira o nome do autor: existem imitações).
  4. Clique no botão azul Install ("Instalar"). Ele instala junto a extensão C# e o .NET Install Tool — é normal.
  5. Se aparecer um pedido de login com conta Microsoft, pode fechar: para estudo, não é obrigatório.
💡 Outras extensões úteis (mesmo caminho, buscando pelo nome): REST Client (testar a API da parte ③), Portuguese (Brazil) Language Pack (deixa os menus em português — mas esta aba usa os nomes em inglês) e Container Tools (Docker, nas Tabs 5 e 7). O C# Dev Kit é gratuito para uso individual, acadêmico e open source; em empresas, pede licença do Visual Studio.

② 👋 Laboratório 1: seu primeiro programa em C# (Hello World)

Objetivo: criar, rodar e entender seu primeiro programa. Ele roda dentro do terminal (por isso se chama programa de console): escreve uma mensagem, pergunta seu nome e responde. Tempo: ~30 minutos.

📦 E o ZIP? O botão acima baixa os dois laboratórios prontos, para você conferir o seu com o gabarito. Mas, para aprender, faça os passos: é digitando e errando que a coisa entra na cabeça.

1🖱️ Criar uma pasta para os seus projetos

  1. Abra o Explorador de Arquivos do Windows (ícone de pasta amarela na barra de tarefas, ou Win+E).
  2. Entre em Documentos.
  3. Clique com o botão direito num espaço vazio → Novo → Pasta. Dê o nome Projetos e aperte Enter.
⚠️ Evite acentos, espaços e a área de trabalho no caminho das pastas de projeto (ex.: "Área de Trabalho\Meus Códigos"). Algumas ferramentas se confundem com eles. Documentos\Projetos é seguro.

2🖱️ Criar o projeto pelo VS Code

Um projeto é uma pasta com o seu código e uma "ficha" dizendo como transformá-lo em programa. O C# Dev Kit cria tudo para você:

  1. No VS Code, aperte Ctrl+Shift+P. Abre, no topo, a Command Palette ("paleta de comandos"): uma caixa de busca que acha qualquer comando do VS Code pelo nome.
  2. Digite .NET: New Project e clique nele quando aparecer.
    (Outro caminho: se nenhuma pasta estiver aberta, a barra lateral do Explorer mostra o botão Create .NET Project.)
  3. Aparece a lista de templates (modelos de projeto). Escolha Console App ("aplicativo de console").
  4. Escolha onde criar: navegue até Documentos\Projetos e clique em Select Folder ("Selecionar pasta").
  5. Digite o nome do projeto: HelloConsole e aperte Enter.
  6. Se perguntar o formato da solução (solution file format), escolha .sln. Depois clique em Create Project ("Criar projeto").
  7. Se o VS Code perguntar "Do you trust the authors of the files in this folder?" ("Você confia nos autores dos arquivos desta pasta?"), clique em Yes, I trust the authors — a pasta é sua.

Pronto: na barra lateral (Explorer) aparecem os arquivos criados, e o Program.cs abre sozinho no editor. Os dois que importam:

ArquivoO que é
Program.csO seu código. O .cs é a extensão dos arquivos C# (como .docx é do Word).
HelloConsole.csprojA ficha do projeto: diz qual versão do .NET usar. Você quase nunca mexe nele.
bin/ e obj/Aparecem depois da primeira execução: é onde o programa "traduzido" é guardado. Pode ignorar.

Lendo a linha, pedaço por pedaço:

✋Errou? Ótimo: veja como o VS Code avisa

Faça de propósito: apague o ; do final da linha do Console.WriteLine e salve (Ctrl+S). Nem precisa rodar: o VS Code já avisa.

  1. Abra a aba Problems: clique no ❌ da barra de status (ou Ctrl+Shift+M).
  2. Comece pelo primeiro problema da lista — quase sempre os outros são consequência dele. Clique nele: o cursor vai para a linha.
  3. Procure a mensagem ; expected ("esperava um ;"). Pare o mouse sobre o risquinho ou clique na 💡 lâmpada para ver sugestões.
  4. Devolva o ; e salve.
✅ Resultado esperado: a lista do Problems esvazia, o contador volta a 0 e o programa roda de novo com Ctrl+F5.

4Fazer o programa conversar com você — em 4 etapas

Agora você vai construir um programa que pergunta seu nome e responde. Vamos por partes: a cada etapa você acrescenta poucas linhas, salva, roda e vê o que mudou. As linhas novas estão marcadas com // ← NOVO.

Etapa A — escrever duas linhas

Apague tudo do Program.cs (Ctrl+A seleciona tudo, Delete apaga) e digite — de preferência digitando, não colando:

HelloConsole/Program.cs — etapa A 
Console.WriteLine("Hello World!");
Console.WriteLine("Estou aprendendo C#.");   // ← NOVO

Salve e rode (Ctrl+S, Ctrl+F5). Aparecem duas linhas, na ordem em que você escreveu: o programa lê o código de cima para baixo, uma instrução de cada vez.

💡 Enquanto você digita: o VS Code sugere o resto da palavra numa listinha (é o autocompletar). Aperte Tab ou Enter para aceitar. E se algo estiver errado, aparece um sublinhado vermelho ondulado — pare o mouse em cima para ler o erro.

Etapa B — perguntar o nome e guardar a resposta

HelloConsole/Program.cs — etapa B 
Console.WriteLine("Hello World!");
Console.WriteLine("Estou aprendendo C#.");

Console.Write("Qual é o seu nome? ");          // ← NOVO
string? nome = Console.ReadLine();             // ← NOVO

Console.WriteLine("Olá, " + nome + "!");       // ← NOVO
Pedaço novoO que significa
Console.Write(...)Igual ao WriteLine, mas sem pular linha: o cursor fica logo depois da pergunta, esperando a resposta.
Console.ReadLine()"Leia uma linha": o programa para e espera você digitar algo e apertar Enter.
string? nome = ...Cria uma variável chamada nome e guarda nela o que você digitou. Variável é uma caixa com etiqueta: você guarda um valor e usa depois pelo nome. string diz que a caixa guarda texto; o ? avisa que ela pode ficar vazia.
"Olá, " + nome + "!"O + junta textos. Se você digitou Ana, vira "Olá, Ana!".
⚠️ Ponto importante: onde digitar o nome. Rode com Run → Run Without Debugging (Ctrl+F5). A pergunta aparece no painel TERMINAL: clique nele, digite seu nome e aperte Enter.
Se a pergunta aparecer na aba DEBUG CONSOLE (outra aba do mesmo painel), você não vai conseguir digitar: essa aba só mostra mensagens, não aceita respostas. Nesse caso, pare o programa (botão ⏹ vermelho no topo, ou Shift+F5) e use o caminho do terminal: Terminal → New Terminal → digite dotnet run → Enter. Ali sempre funciona.
resultado esperado (você digita "Ana" e aperta Enter) 
Hello World!
Estou aprendendo C#.
Qual é o seu nome? Ana
Olá, Ana!

Etapa C — tomar uma decisão com if

Rode de novo e, na pergunta, só aperte Enter sem digitar nada. Sai "Olá, !" — feio. Vamos ensinar o programa a decidir:

HelloConsole/Program.cs — etapa C (só o trecho do meio muda) 
Console.Write("Qual é o seu nome? ");
string? nome = Console.ReadLine();

if (string.IsNullOrWhiteSpace(nome))           // ← NOVO
{                                              // ← NOVO
    nome = "visitante";                        // ← NOVO
}                                              // ← NOVO

Console.WriteLine("Olá, " + nome + "!");
Pedaço novoO que significa
if ( ... )"Se". O que está entre parênteses é uma pergunta de sim ou não.
string.IsNullOrWhiteSpace(nome)A pergunta: "o nome está vazio ou só tem espaços?"
{ ... }As chaves marcam o bloco: o que fica dentro só acontece se a resposta for sim.
nome = "visitante";Troca o que está guardado na caixa nome. O = em C# quer dizer "guarde", não "é igual".

Rode duas vezes: uma digitando o nome, outra só com Enter. Na segunda, sai "Olá, visitante!". O recuo (os 4 espaços antes de nome = ...) não é obrigatório, mas deixa claro o que está dentro do bloco — o atalho Shift+Alt+F arruma tudo sozinho.

Etapa D — números e frases com variáveis dentro

HelloConsole/Program.cs — etapa D (só o final muda) 
if (string.IsNullOrWhiteSpace(nome))
{
    nome = "visitante";

// ════════════════════════════════════════════════════════════════════════════

// ── 1) ESCREVER NA TELA ─────────────────────────────────────────────────────
// Console      = a janela do terminal
// WriteLine    = "escreva esta linha e pule para a próxima"
// "..."        = um TEXTO (em programação: uma "string"), sempre entre aspas
// ;            = o ponto final do C#: toda instrução termina com ele
Console.WriteLine("Hello World!");

// ── 2) PERGUNTAR E GUARDAR A RESPOSTA ──────────────────────────────────────
// Write (sem "Line") escreve SEM pular linha: o cursor fica esperando
// logo depois da pergunta, como num formulário.
Console.Write("Qual é o seu nome? ");

// ReadLine() espera você digitar algo e apertar Enter.
// O que você digitou vai para dentro de uma VARIÁVEL chamada 'nome'.
//   string  = o TIPO da variável: ela guarda texto
//   ?       = "pode ficar vazia (null)" — se o terminal fechar sem resposta,
//             o ReadLine devolve null. O C# exige que você admita isso.
string? nome = Console.ReadLine();

// ── 3) TOMAR UMA DECISÃO ───────────────────────────────────────────────────
// if = "se". Se a pessoa só apertou Enter (ou digitou espaços),
// trocamos o nome por "visitante" para a frase não sair estranha.
if (string.IsNullOrWhiteSpace(nome))
{
    nome = "visitante";
}

// ── 4) USAR NÚMEROS ─────────────────────────────────────────────────────────
// int = número inteiro. DateTime.Now é a data e hora do seu computador;
// .Year pega só o ano.
int ano = DateTime.Now.Year;

// ── 5) MONTAR UMA FRASE COM VARIÁVEIS ──────────────────────────────────────
// O $ antes das aspas liga a INTERPOLAÇÃO: o que estiver entre { } é
// trocado pelo valor da variável. {nome} vira "Ana", {ano} vira 2026.
Console.WriteLine($"Olá, {nome}! Bem-vindo ao C# em {ano}.");

// .Length = quantas letras o texto tem (espaços contam).
Console.WriteLine($"Seu nome tem {nome.Length} caracteres.");

// ════════════════════════════════════════════════════════════════════════════
//  DESAFIOS (tente sozinho, depois rode 'dotnet run' de novo):
//   1. Pergunte também a cidade e mostre: "Ana, de Recife".
//   2. Pergunte o ano em que a pessoa nasceu e calcule a idade.
//      Dica: int nascimento = int.Parse(Console.ReadLine()!);
//   3. Se o nome tiver mais de 10 letras, escreva "Que nome comprido!".
// ════════════════════════════════════════════════════════════════════════════

③ 🌐 Laboratório 2: o mesmo Hello World, agora como API

O que muda: no Lab 1, o programa conversava com você, pelo terminal. Agora ele vai conversar com outros programas — um navegador, um aplicativo de celular — pela rede. Em vez de escrever na tela, ele responde quando alguém acessa um endereço, como http://localhost:5078/hello. Isso é uma API, e é a base de tudo o que vem nas próximas abas. Tempo: ~25 minutos.

HelloDotnetApi/Program.cs 
// ════════════════════════════════════════════════════════════════════════════
//  Program.cs — o ponto de entrada da API (Minimal API, .NET 10)
//
//  Repare: não existe 'class Program' nem 'static void Main'. Isto se chama
//  TOP-LEVEL STATEMENTS — o compilador gera a classe e o Main por você, e as
//  linhas abaixo viram o corpo do Main. Menos cerimônia, mesmo resultado.
//
//  A leitura é de cima para baixo, em 4 passos:
//     1. builder  → MONTA a aplicação (serviços, configuração, logs)
//     2. app      → a aplicação PRONTA
//     3. MapGet   → liga cada ROTA a uma função
//     4. Run      → começa a escutar a porta
// ════════════════════════════════════════════════════════════════════════════

// ── 1) BUILDER ──────────────────────────────────────────────────────────────
// Prepara tudo ANTES de a aplicação existir: lê o appsettings.json e as
// variáveis de ambiente, configura o log e abre a "caixa" de injeção de
// dependência (builder.Services). 'args' são os argumentos da linha de
// comando — por exemplo: dotnet run --urls http://localhost:6000
var builder = WebApplication.CreateBuilder(args);

// ── 2) APP ──────────────────────────────────────────────────────────────────
// Build() fecha a caixa de serviços e entrega a aplicação pronta. Daqui para
// baixo não se registra mais serviço: só se define o que acontece com cada
// requisição que chega.
var app = builder.Build();

// ── 3) ROTAS ────────────────────────────────────────────────────────────────
// MapGet = "quando chegar um GET neste caminho, chame esta função".
// Existem também MapPost, MapPut e MapDelete para os outros verbos HTTP.
app.MapGet("/", Handlers.Raiz);
app.MapGet("/hello", Handlers.Hello);

// {nome} é um PARÂMETRO DE ROTA: em GET /hello/Ana, o .NET entrega "Ana"
// no parâmetro 'nome' do método (o nome precisa ser igual nos dois lugares).
app.MapGet("/hello/{nome}", Handlers.HelloNome);

// ── 4) RUN ──────────────────────────────────────────────────────────────────
// Começa a escutar a porta (5078, definida em Properties/launchSettings.json)
// e BLOQUEIA aqui até você apertar Ctrl+C no terminal.
app.Run();

// ════════════════════════════════════════════════════════════════════════════
//  Por que a classe vem DEPOIS do app.Run()?
//  Regra do C#: num arquivo com top-level statements, as INSTRUÇÕES vêm
//  primeiro e as declarações de tipo (class, record, enum) vêm depois.
//  O app.Run() não "esconde" a classe: ela é compilada normalmente.
//
//  Por que separar os handlers numa classe em vez de escrever tudo inline
//  (app.MapGet("/hello", () => ...))? Os dois funcionam. Separado fica mais
//  fácil de ler, de reaproveitar e de testar — é o primeiro passo para os
//  Controllers e Services que você vai ver na Tab 7.
// ════════════════════════════════════════════════════════════════════════════

/// <summary>Funções que respondem às rotas da API (os "handlers").</summary>
public static class Handlers
{
    /// <summary>GET / — página de boas-vindas: diz que a API está no ar e lista as rotas.</summary>
    // IResult = "uma resposta HTTP". Results.Ok(...) monta um 200 OK e
    // converte o objeto para JSON sozinho (sem você escrever serialização).
    public static IResult Raiz() => Results.Ok(new
    {
        status = "API .NET 10 no ar",
        rotas = new[] { "GET /hello", "GET /hello/{nome}" }
    });

    /// <summary>GET /hello — o "smoke test": se isto responde, o ambiente está pronto.</summary>
    // 'new { ... }' é um TIPO ANÔNIMO: um objeto criado na hora, sem
    // precisar declarar classe. Ótimo para respostas simples como esta.
    public static IResult Hello() => Results.Ok(new
    {
        mensagem = "Hello World com .NET 10!",
        runtime = Environment.Version.ToString(),   // versão do RUNTIME que está executando (ex.: 10.0.x)
        horarioUtc = DateTime.UtcNow                // sempre UTC em API: o fuso é problema de quem exibe
    });

    /// <summary>GET /hello/{nome} — mostra parâmetro de rota e um erro 400 de verdade.</summary>
    public static IResult HelloNome(string nome)
    {
        // Validação simples: nome gigante é recusado com 400 Bad Request.
        // Teste: curl -i http://localhost:5078/hello/um-nome-muito-muito-muito-muito-muito-muito-comprido
        if (nome.Length > 30)
            return Results.BadRequest(new { erro = "Nome deve ter no máximo 30 caracteres" });

        // $"..." é INTERPOLAÇÃO de string: {nome} é trocado pelo valor.
        return Results.Ok(new { mensagem = $"Olá, {nome}! Sua API .NET 10 está funcionando." });
    }
}
🔗 Repare na ligação com o Lab 1: a rota /hello/{nome} faz o mesmo que o seu "qual é o seu nome?" — só que o nome vem no endereço (/hello/Ana) em vez de ser digitado no terminal. E as mesmas peças aparecem: interpolação $"Olá, {nome}!", if, .Length.

④ 🧱 O que você acabou de usar

Agora que você já criou e rodou dois programas, os nomes técnicos ficam fáceis de entender — você já usou todos:

SDK × Runtime

O Runtime só executa um programa .NET já pronto — é o que vai no computador de quem só usa o programa, ou no servidor. O SDK é o kit de quem escreve o programa: traz o Runtime e mais as ferramentas para criar projetos e compilar. Você instalou o SDK. Analogia: o Runtime é o toca-discos; o SDK é o estúdio de gravação (que também tem um toca-discos dentro).

Por que o .NET 10?

O .NET 10 é LTS (Long Term Support, "suporte de longo prazo"): recebe correções de segurança até nov/2028, o curso inteiro. As versões anteriores, .NET 8 e .NET 9, perdem o suporte em 10/nov/2026.

O .csproj, o NuGet e o comando dotnet

O .csproj é a "ficha" do projeto — o equivalente ao pom.xml do Java (Tab 2). Compare os dois que você criou: o do Lab 1 começa com Microsoft.NET.Sdk; o da API, com Microsoft.NET.Sdk.Web — é essa palavra que traz tudo o que é preciso para responder pela rede. O NuGet é a "loja" de pacotes prontos do .NET (bibliotecas que outras pessoas escreveram e você pode usar).

Todo clique que você deu no VS Code virou, por baixo, um comando dotnet. Conhecê-los ajuda quando aparecer um erro ou quando você for usar outro editor:

⑤ 🔀 Guardar seu código no GitHub (pelo VS Code)

🔀 O que é Git? E o GitHub?

Git é um programa que guarda o histórico do seu código: cada vez que você "salva uma versão" (um commit), ele tira uma foto do projeto. Dá para ver o que mudou, quando e por quê — e voltar a qualquer foto antiga. Analogia: é o "salvar jogo" do código, com uma legenda em cada ponto de salvamento.

O GitHub é um site que guarda uma cópia desse histórico na nuvem: seu código fica seguro mesmo se o computador quebrar, e outras pessoas podem ver e colaborar. O GitLab é um site parecido, muito usado em empresas.

  • Repositório (repo): o projeto + todo o histórico.
  • Commit: uma "foto" das mudanças, com uma mensagem explicando o que foi feito.
  • Push: enviar seus commits para o site. Pull: trazer de lá o que mudou.
  • Branch: uma linha paralela de trabalho (ex.: feat/novo-endpoint); main é a principal.
  • Pull Request (PR): pedido para alguém revisar seu branch antes de juntá-lo ao main.

2Dizer ao Git quem é você (uma vez por computador)

Todo commit leva o nome e o e-mail de quem fez. Sem isso, o VS Code avisa "Make sure you configure your user.name and user.email" e não deixa fazer o commit. Este é o único passo do Git que precisa do terminal:

  1. No VS Code: Terminal → New Terminal.
  2. Digite as duas linhas abaixo, uma de cada vez, trocando pelos seus dados (use o mesmo e-mail da conta do GitHub) e apertando Enter depois de cada uma. Não aparece nenhuma resposta — é normal: no terminal, silêncio quer dizer que deu certo.
terminal do VS Code 
git config --global user.name "Seu Nome"
git config --global user.email "seu@email.com"

3🖱️ Publicar a API no GitHub

  1. No VS Code, abra a pasta da API: File → Open Folder… → Documentos\Projetos\HelloDotnetApi → Select Folder.
  2. Na barra de atividades (esquerda), clique no ícone Source Control 🔀 (três bolinhas ligadas por linhas; atalho Ctrl+Shift+G).
  3. Como a pasta ainda não tem Git, aparecem dois botões. Clique em Publish to GitHub ("Publicar no GitHub").
  4. O VS Code pede permissão para entrar na sua conta: clique em Allow ("Permitir"). O navegador abre o GitHub → faça login (se pedir) → Authorize Visual Studio Code ("Autorizar"). Volte ao VS Code (se o navegador perguntar se pode abrir o VS Code, clique em Abrir).
  5. No topo do VS Code, escolha Publish to GitHub private repository ("repositório privado", só você vê) ou public repository ("público", qualquer um vê). Para estudo, tanto faz.
  6. Aparece a lista de arquivos a enviar. Desmarque as pastas bin e obj se aparecerem (veja o aviso abaixo) → OK.
  7. No canto de baixo surge "Successfully published…" → clique em Open on GitHub: seu código está na nuvem. 🎉
⚠️ Por que não enviar bin/ e obj/? São pastas que o .NET gera sozinho toda vez que roda o programa. Enviá-las só deixa o repositório pesado e causa conflito entre colegas. O jeito definitivo de evitar: um arquivo .gitignore na pasta do projeto — uma lista do que o Git deve ignorar. O ZIP já traz um pronto; para criar o seu: Terminal → New Terminal → dotnet new gitignore.

4🖱️ O dia a dia: mudar, fazer commit, enviar

Daqui para frente, toda vez que mudar o código:

  1. Altere e salve algum arquivo (ex.: mude a mensagem do /hello).
  2. Abra o Source Control (Ctrl+Shift+G). O arquivo aparece na lista Changes ("alterações") com um M (modified). Clique nele: o VS Code mostra antes e depois lado a lado, em vermelho e verde.
  3. Na caixa Message do topo, escreva o que você fez, ex.: feat: muda a mensagem do hello.
  4. Clique em ✓ Commit. Se perguntar "There are no staged changes… Would you like to stage all your changes?" ("quer incluir todas as alterações?"), clique em Yes.
  5. Clique em Sync Changes ("sincronizar") para enviar ao GitHub.
✍️ Mensagem de commit: o prefixo diz o tipo da mudança — feat: coisa nova, fix: correção, docs: documentação. É o padrão Conventional Commits, o mesmo da Tab 2.
👥 Em equipe: ninguém faz commit direto no main. Cada tarefa ganha um branch: clique no nome do branch no rodapé do VS Code (canto inferior esquerdo, mostra main) → Create new branch… → nome, ex.: feat/novo-endpoint. Faça os commits nele, clique em Publish Branch e, no site do GitHub, abra um Pull Request para alguém revisar antes de juntar ao main.
⌨️ Prefere o terminal? O mesmo fluxo com comandos git (e chave SSH)

Crie antes, no site, um repositório vazio chamado HelloDotnetApi (sem README).

terminal — primeiro envio 
git init -b main                  # cria o repositório já com o branch 'main'
git add .                         # inclui todos os arquivos (o .gitignore barra bin/ e obj/)
git commit -m "feat: laboratório hello .NET 10"
git remote add origin git@github.com:SEU-USUARIO/HelloDotnetApi.git
git push -u origin main           # envia; nos próximos, basta 'git push'
terminal — dia a dia com branch e PR 
git switch main && git pull                  # começa do main atualizado
git switch -c feat/novo-endpoint             # cria o branch da tarefa
git status                                   # quais arquivos mudaram
git diff                                     # o que mudou dentro deles
git add Program.cs
git commit -m "feat: adiciona endpoint /hello/{nome}"
git push -u origin feat/novo-endpoint        # depois, abra o PR no site

O endereço git@github.com:... usa uma chave SSH (o "crachá" do seu computador). Para criar a sua:

terminal — chave SSH 
ssh-keygen -t ed25519 -C "seu@email.com"    # Enter em todas as perguntas
cat ~/.ssh/id_ed25519.pub                    # copie a linha e cole em:
                                             # GitHub → Settings → SSH and GPG keys → New SSH key
ssh -T git@github.com                        # esperado: "Hi SEU-USUARIO! You've successfully authenticated"

⚠️ src refspec main does not match any? O branch se chama master: rode git branch -M main e repita o push. A chave .pub é pública (pode mostrar); a outra, id_ed25519, é privada: nunca compartilhe.

⑥ 📌 Para ir além: o que há de novo no C# 14

Opcional — volte aqui depois das Tabs 6 e 7, quando "classe" e "propriedade" já forem palavras familiares.

O .NET é a plataforma (as ferramentas e bibliotecas); o C# é a linguagem. Cada .NET traz uma versão nova do C#: o .NET 10 traz o C# 14, sem configuração nenhuma — você já usou ele nos dois laboratórios. Duas novidades:

C# 14 — palavra-chave field e extension members (exemplo para ler) 
// ─────────────────────────────────────────────────────────────────────
// NOVIDADE 1: a palavra-chave 'field'
// Antes do C# 14, para validar um valor no 'set' você precisava declarar
// um campo privado à mão (private string _nome;). Agora 'field' é o campo
// que o compilador cria sozinho por trás da propriedade.
// ─────────────────────────────────────────────────────────────────────
public class Produto
{
    public string Nome
    {
        get;                                    // devolve o valor guardado
        set => field = string.IsNullOrWhiteSpace(value)
            ? throw new ArgumentException("Nome é obrigatório")
            : value.Trim();                     // guarda já sem espaços nas pontas
    } = "";
}

// ─────────────────────────────────────────────────────────────────────
// NOVIDADE 2: extension members (bloco 'extension')
// "Extensão" = acrescentar métodos a um tipo que não é seu (aqui, string)
// sem mexer nele. Antes só dava para criar MÉTODOS de extensão; agora o
// bloco 'extension' também permite PROPRIEDADES.
// ─────────────────────────────────────────────────────────────────────
public static class TextoExtensions
{
    extension(string texto)                     // "estou estendendo o tipo string"
    {
        public bool EstaVazio => string.IsNullOrWhiteSpace(texto);          // propriedade nova
        public string Resumo(int max) =>                                     // método novo
            texto.Length <= max ? texto : texto[..max] + "…";
    }
}

// Uso — parece que string sempre teve esses membros:
//   "   ".EstaVazio                → true
//   "Hello World".Resumo(5)        → "Hello…"

Outras do C# 14: atribuição com ?. (cliente?.Nome = "Ana"; só atribui se cliente não for null) e nameof com genéricos abertos (nameof(List<>)). Aprofundar: Novidades do C# 14 (Microsoft Learn).
