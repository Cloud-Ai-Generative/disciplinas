📦 .csproj, NuGet e a CLI dotnet

.csproj é o arquivo de projeto (o "cardápio": target framework, pacotes, opções) — o equivalente ao pom.xml do Java. NuGet é o gerenciador de pacotes (o "Maven Central" do .NET). A CLI dotnet faz tudo: new (criar), build (compilar), run (rodar), test (testar), publish (empacotar).

🔀 O que é Git? E GitHub vs GitLab?

Git é um sistema de controle de versão distribuído: registra o histórico de mudanças do código, permite branches (linhas paralelas), merge (junção) e rollback (voltar). Cada dev tem o repositório completo localmente.

  • Repositório (repo): o projeto + histórico.
  • Commit: um "snapshot" comentado das mudanças.
  • Branch: linha paralela (ex.: feat/x); main é a principal.
  • Remote / origin: a cópia no servidor (GitHub/GitLab).
  • push / pull: enviar / trazer mudanças do remote.
  • PR/MR (Pull/Merge Request): pedido de revisão p/ juntar um branch ao main.

GitHub vs GitLab

GitHubGitLab
HospedagemSaaS (Microsoft)SaaS ou self-hosted
RevisãoPull RequestMerge Request
CI/CDGitHub ActionsGitLab CI (integrado)

Aprofundar: git-scm (docs) · Livro Pro Git (PT-BR) · GitHub Docs · GitLab Docs.

3Git pela GUI do VS Code (Source Control)

  1. Abra Source Control (Ctrl+Shift+G): veja arquivos modificados.
  2. Campo de mensagem → digite o commit → ✓ Commit.
  3. Botão … → Push envia ao remote; Pull traz mudanças.
  4. Branch: clique no nome do branch (rodapé) → Create new branch. O PR/MR é aberto no site (GitHub/GitLab).

🔷 Laboratório 0: API Hello World com .NET 10 (do zero)

Objetivo: provar que SDK .NET 10 + VS Code + terminal + curl estão funcionando com uma Minimal API. (O que é curl? Veja explicação completa com flags na Tab 4.)

1Criar o projeto pelo terminal

🖥️ Terminal: VS Code Ctrl+`.
terminal 
# Cria a pasta do laboratório e entra nela
mkdir HelloDotnetApi && cd HelloDotnetApi
# Gera uma API web mínima (sem controllers), target .NET 10
dotnet new web -f net10.0
# Abre a pasta atual no VS Code
code .

2Substituir o Program.cs

No Explorer do VS Code, abra Program.cs, apague tudo e cole:

HelloDotnetApi/Program.cs 
var builder = WebApplication.CreateBuilder(args);
var app = builder.Build();

app.MapGet("/", Handlers.Raiz);
app.MapGet("/hello", Handlers.Hello);
app.Run();

/// <summary>Handlers de demonstração da Minimal API.</summary>
public static class Handlers
{
    /// <summary>GET / — healthcheck.</summary>
    public static IResult Raiz() => Results.Ok(new { status = "API .NET 10 no ar", roteiro = "GET /hello" });

    /// <summary>GET /hello — smoke test.</summary>
    public static IResult Hello() => Results.Ok(new
    {
        mensagem = "Hello World com .NET 10!",
        runtime = Environment.Version.ToString(),
        horarioUtc = DateTime.UtcNow
    });
}

3Compilar, rodar e testar com curl

🖥️ Terminal: VS Code Ctrl+`. Rode na pasta do .csproj.
terminal do VS Code 
# Restaura pacotes NuGet e compila o projeto (gera bin/ e obj/)
dotnet build
# Roda a API em modo desenvolvimento (anote a porta impressa, ex.: 5078)
dotnet run
# 2º terminal: testa o endpoint (troque 5078 pela porta real)
curl -i http://localhost:5078/hello
curl -i http://localhost:5078/
✅ Sucesso esperado: HTTP/1.1 200 OK + JSON {"mensagem":"Hello World com .NET 10!", ...}.
⚠️ Erros comuns: porta diferente da impressa (use a porta do console); esquecer dotnet build; commitar bin//obj/ (use dotnet new gitignore); certificado https (dotnet dev-certs https --trust).
✅ Checklist: SDK 10 ✓ · dotnet run sobe ✓ · curl 200 ✓ · repo sem bin/obj ✓.

🔒 global.json: por que travar o SDK?

Problema: você tem .NET 10, o colega 11 preview, o CI 9 — três compiladores diferentes p/ o mesmo código.

Solução: global.json commitado diz à CLI dotnet qual SDK usar naquele repo (equivalente ao .sdkmanrc do Java).

🎯 Versão do SDK:
global.json (commitado na raiz) 
{
  "sdk": {
    "version": "10.0.100",
    "rollForward": "latestFeature"
  }
}
terminal - gerar global.json 
# Gera o global.json na pasta atual com a versão informada
dotnet new globaljson --sdk-version 10.0.100
# rollForward: latestFeature (recomendado) | latestPatch | disable
