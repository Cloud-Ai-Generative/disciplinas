Do zero ao primeiro programa: instale o VS Code e o .NET 10, escreva seu Hello World em C# no console, transforme-o numa API web, entenda o que você acabou de usar (SDK, .csproj, CLI) e versione no Git pela GUI do VS Code (igual à Tab 2). IDE: VS Code

② 👋 Laboratório 1: Hello World em C# (console)

Objetivo: escrever, rodar e entender seu primeiro programa em C#. Ele roda no terminal (por isso "console"): escreve uma mensagem, pergunta seu nome e responde. Tempo: ~10 minutos.

1Criar o projeto

🖥️ Terminal: VS Code Ctrl+`, na pasta onde você guarda seus projetos.
terminal 
# Cria uma pasta para o programa e entra nela
mkdir HelloConsole
cd HelloConsole

# Pede ao .NET um projeto de CONSOLE pronto para o .NET 10
dotnet new console -f net10.0

# Abre esta pasta no VS Code (o "." quer dizer "a pasta atual")
code .

O comando criou 2 arquivos: HelloConsole.csproj (a "ficha" do projeto: qual .NET usar) e Program.cs (o seu código). O .cs é a extensão dos arquivos C#.

2Rodar o programa que veio pronto

Abra o Program.cs no Explorer (Ctrl+Shift+E). O .NET já escreveu um Hello World para você — é uma linha só:

HelloConsole/Program.cs (como o dotnet new console cria) 
// See https://aka.ms/new-console-template for more information
Console.WriteLine("Hello, World!");
terminal 
dotnet run
# esperado:
# Hello, World!
🎉 Parabéns: você rodou seu primeiro programa em C#! O dotnet run fez duas coisas: compilou (traduziu o C# para uma linguagem que o computador executa) e executou o resultado.
💡 Lendo a linha: Console é a janela do terminal · WriteLine é "escreva esta linha" · o texto vai entre aspas · o ; é o "ponto final" de toda instrução em C#. Esqueceu o ;? O compilador avisa: error CS1002: ; expected.

3Fazer o programa conversar com você

Apague tudo do Program.cs e cole o código abaixo. Agora ele pergunta seu nome, guarda numa variável, decide o que fazer e monta uma frase. Leia os comentários (as linhas com //): eles explicam cada linha.

HelloConsole/Program.cs (versão final, comentada) 
// ════════════════════════════════════════════════════════════════════════════
//  Program.cs — seu primeiro programa em C# (aplicativo de console, .NET 10)
//
//  Como ler: o programa roda de CIMA para BAIXO, uma linha de cada vez.
//  Tudo o que começa com // é COMENTÁRIO: o computador ignora, é só para você.
// ════════════════════════════════════════════════════════════════════════════

// ── 1) ESCREVER NA TELA ─────────────────────────────────────────────────────
// Console      = a janela do terminal
// WriteLine    = "escreva esta linha e pule para a próxima"
// "..."        = um TEXTO (em programação: uma "string"), sempre entre aspas
// ;            = o ponto final do C#: toda instrução termina com ele
Console.WriteLine("Hello World!");

// ── 2) PERGUNTAR E GUARDAR A RESPOSTA ──────────────────────────────────────
// Write (sem "Line") escreve SEM pular linha: o cursor fica esperando
// logo depois da pergunta, como num formulário.
Console.Write("Qual é o seu nome? ");

// ReadLine() espera você digitar algo e apertar Enter.
// O que você digitou vai para dentro de uma VARIÁVEL chamada 'nome'.
//   string  = o TIPO da variável: ela guarda texto
//   ?       = "pode ficar vazia (null)" — se o terminal fechar sem resposta,
//             o ReadLine devolve null. O C# exige que você admita isso.
string? nome = Console.ReadLine();

// ── 3) TOMAR UMA DECISÃO ───────────────────────────────────────────────────
// if = "se". Se a pessoa só apertou Enter (ou digitou espaços),
// trocamos o nome por "visitante" para a frase não sair estranha.
if (string.IsNullOrWhiteSpace(nome))
{
    nome = "visitante";
}

// ── 4) USAR NÚMEROS ─────────────────────────────────────────────────────────
// int = número inteiro. DateTime.Now é a data e hora do seu computador;
// .Year pega só o ano.
int ano = DateTime.Now.Year;

// ── 5) MONTAR UMA FRASE COM VARIÁVEIS ──────────────────────────────────────
// O $ antes das aspas liga a INTERPOLAÇÃO: o que estiver entre { } é
// trocado pelo valor da variável. {nome} vira "Ana", {ano} vira 2026.
Console.WriteLine($"Olá, {nome}! Bem-vindo ao C# em {ano}.");

// .Length = quantas letras o texto tem (espaços contam).
Console.WriteLine($"Seu nome tem {nome.Length} caracteres.");

// ════════════════════════════════════════════════════════════════════════════
//  DESAFIOS (tente sozinho, depois rode 'dotnet run' de novo):
//   1. Pergunte também a cidade e mostre: "Ana, de Recife".
//   2. Pergunte o ano em que a pessoa nasceu e calcule a idade.
//      Dica: int nascimento = int.Parse(Console.ReadLine()!);
//   3. Se o nome tiver mais de 10 letras, escreva "Que nome comprido!".
// ════════════════════════════════════════════════════════════════════════════
terminal 
dotnet run
# esperado (você digita o nome e aperta Enter):
# Hello World!
# Qual é o seu nome? Ana
# Olá, Ana! Bem-vindo ao C# em 2026.
# Seu nome tem 3 caracteres.
Você viuNome técnicoPara que serve
string? nome = ...Variável do tipo textoGuardar um valor para usar depois
int ano = ...Variável do tipo número inteiroGuardar números (contas, idades, quantidades)

⚠️ Erros comuns:
  • Couldn't find a project to run → o terminal não está na pasta do .csproj. Rode cd HelloConsole.
  • error CS1002: ; expected → faltou o ; no fim de uma linha. A mensagem diz o número da linha: Program.cs(14,35) = linha 14, coluna 35.
  • error CS0103: The name 'Nome' does not exist → C# diferencia maiúsculas de minúsculas: nome e Nome são variáveis diferentes.
  • O programa "travou" depois da pergunta → não travou: está esperando você digitar e apertar Enter.
🏋️ Desafios (estão no fim do Program.cs): perguntar a cidade · calcular a idade a partir do ano de nascimento · comentar se o nome é comprido. Altere, salve (Ctrl+S) e rode dotnet run de novo.

③ 🌐 Laboratório 2: o mesmo Hello World, agora como API

O que muda: no Lab 1, o programa falava com você, pelo terminal. Aqui ele vai falar com outros programas, pela internet: em vez de Console.WriteLine, ele responde a um endereço (http://localhost:5078/hello). Isso é uma API — a base de tudo o que vem nas próximas abas.

💡 Minimal API: é o jeito mais enxuto de criar uma API no .NET — uma rota é uma linha: app.MapGet("/hello", ...) = "quando alguém pedir /hello, chame esta função". Quando a API cresce, usam-se controllers para organizar (Tab 7).

1Criar o projeto

🖥️ Terminal: VS Code Ctrl+`. Volte para a pasta de projetos (cd .. se ainda estiver em HelloConsole).
terminal 
# Cria a pasta da API e entra nela
mkdir HelloDotnetApi
cd HelloDotnetApi

# Agora o template é "web" (e não "console"): projeto de API mínima
dotnet new web -f net10.0

code .

Além do .csproj e do Program.cs, o template "web" cria appsettings.json (configuração) e Properties/launchSettings.json (como rodar: porta, ambiente).

2Substituir o Program.cs e fixar a porta

Abra Program.cs, apague tudo e cole o código abaixo. São 3 rotas: /, /hello e /hello/{nome} — esta última é o "pergunta o nome" do Lab 1, só que pela URL.

HelloDotnetApi/Program.cs 
// ════════════════════════════════════════════════════════════════════════════
//  Program.cs — o ponto de entrada da API (Minimal API, .NET 10)
//
//  Repare: não existe 'class Program' nem 'static void Main'. Isto se chama
//  TOP-LEVEL STATEMENTS — o compilador gera a classe e o Main por você, e as
//  linhas abaixo viram o corpo do Main. Menos cerimônia, mesmo resultado.
//
//  A leitura é de cima para baixo, em 4 passos:
//     1. builder  → MONTA a aplicação (serviços, configuração, logs)
//     2. app      → a aplicação PRONTA
//     3. MapGet   → liga cada ROTA a uma função
//     4. Run      → começa a escutar a porta
// ════════════════════════════════════════════════════════════════════════════

// ── 1) BUILDER ──────────────────────────────────────────────────────────────
// Prepara tudo ANTES de a aplicação existir: lê o appsettings.json e as
// variáveis de ambiente, configura o log e abre a "caixa" de injeção de
// dependência (builder.Services). 'args' são os argumentos da linha de
// comando — por exemplo: dotnet run --urls http://localhost:6000
var builder = WebApplication.CreateBuilder(args);

// ── 2) APP ──────────────────────────────────────────────────────────────────
// Build() fecha a caixa de serviços e entrega a aplicação pronta. Daqui para
// baixo não se registra mais serviço: só se define o que acontece com cada
// requisição que chega.
var app = builder.Build();

// ── 3) ROTAS ────────────────────────────────────────────────────────────────
// MapGet = "quando chegar um GET neste caminho, chame esta função".
// Existem também MapPost, MapPut e MapDelete para os outros verbos HTTP.
app.MapGet("/", Handlers.Raiz);
app.MapGet("/hello", Handlers.Hello);

// {nome} é um PARÂMETRO DE ROTA: em GET /hello/Ana, o .NET entrega "Ana"
// no parâmetro 'nome' do método (o nome precisa ser igual nos dois lugares).
app.MapGet("/hello/{nome}", Handlers.HelloNome);

// ── 4) RUN ──────────────────────────────────────────────────────────────────
// Começa a escutar a porta (5078, definida em Properties/launchSettings.json)
// e BLOQUEIA aqui até você apertar Ctrl+C no terminal.
app.Run();

// ════════════════════════════════════════════════════════════════════════════
//  Por que a classe vem DEPOIS do app.Run()?
//  Regra do C#: num arquivo com top-level statements, as INSTRUÇÕES vêm
//  primeiro e as declarações de tipo (class, record, enum) vêm depois.
//  O app.Run() não "esconde" a classe: ela é compilada normalmente.
//
//  Por que separar os handlers numa classe em vez de escrever tudo inline
//  (app.MapGet("/hello", () => ...))? Os dois funcionam. Separado fica mais
//  fácil de ler, de reaproveitar e de testar — é o primeiro passo para os
//  Controllers e Services que você vai ver na Tab 7.
// ════════════════════════════════════════════════════════════════════════════

/// <summary>Funções que respondem às rotas da API (os "handlers").</summary>
public static class Handlers
{
    /// <summary>GET / — página de boas-vindas: diz que a API está no ar e lista as rotas.</summary>
    // IResult = "uma resposta HTTP". Results.Ok(...) monta um 200 OK e
    // converte o objeto para JSON sozinho (sem você escrever serialização).
    public static IResult Raiz() => Results.Ok(new
    {
        status = "API .NET 10 no ar",
        rotas = new[] { "GET /hello", "GET /hello/{nome}" }
    });

    /// <summary>GET /hello — o "smoke test": se isto responde, o ambiente está pronto.</summary>
    // 'new { ... }' é um TIPO ANÔNIMO: um objeto criado na hora, sem
    // precisar declarar classe. Ótimo para respostas simples como esta.
    public static IResult Hello() => Results.Ok(new
    {
        mensagem = "Hello World com .NET 10!",
        runtime = Environment.Version.ToString(),   // versão do RUNTIME que está executando (ex.: 10.0.x)
        horarioUtc = DateTime.UtcNow                // sempre UTC em API: o fuso é problema de quem exibe
    });

    /// <summary>GET /hello/{nome} — mostra parâmetro de rota e um erro 400 de verdade.</summary>
    public static IResult HelloNome(string nome)
    {
        // Validação simples: nome gigante é recusado com 400 Bad Request.
        // Teste: curl -i http://localhost:5078/hello/um-nome-muito-muito-muito-muito-muito-muito-comprido
        if (nome.Length > 30)
            return Results.BadRequest(new { erro = "Nome deve ter no máximo 30 caracteres" });

        // $"..." é INTERPOLAÇÃO de string: {nome} é trocado pelo valor.
        return Results.Ok(new { mensagem = $"Olá, {nome}! Sua API .NET 10 está funcionando." });
    }
}

Sem terminal: com a extensão REST Client, abra o requests.http e clique em Send Request acima de cada linha GET. O teste 4 provoca um 400 Bad Request de propósito.

@base = http://localhost:5078

⚠️ Erros comuns:
  • Failed to connect to localhost port 5078 → a API não está rodando (o terminal 1 precisa mostrar "Now listening"), ou a porta é outra: use a que aparece no console.
  • address already in use → outra API já usa a 5078. Pare a anterior com Ctrl+C.
  • Aviso de certificado HTTPS → só aparece se você usar o perfil https. No Windows e no macOS: dotnet dev-certs https --trust; no Linux, use o perfil http (o do ZIP).

4Ver o código parar: o depurador

Depurar é pausar o programa numa linha e olhar o que tem dentro das variáveis. É a ferramenta nº 1 para entender por que algo não funciona.

  1. Pare a API no terminal 1 (Ctrl+C).
  2. No Program.cs, clique à esquerda do número da linha do return Results.Ok(...) dentro de HelloNome. Aparece uma bolinha vermelha: é o breakpoint.
  3. Aperte F5 (se perguntar, escolha C#). A API sobe em modo depuração.
  4. No terminal 2, rode curl -i http://localhost:5078/hello/Ana. O VS Code para na linha marcada.
  5. Passe o mouse sobre nome: aparece "Ana". Aperte F5 de novo para continuar, ou Shift+F5 para encerrar.

④ 🧱 O que você acabou de usar

Agora que você já rodou dois programas, os nomes técnicos ficam fáceis de entender:

SDK × Runtime

O Runtime só executa um programa .NET já compilado — é o que vai no servidor. O SDK é o kit de quem escreve o programa: traz o Runtime e mais as ferramentas para compilar e criar projetos. Você instalou o SDK. Analogia: o Runtime é o toca-discos; o SDK é o estúdio de gravação (que também tem um toca-discos dentro).

Por que o .NET 10?

O .NET 10 é LTS (Long Term Support): recebe correções de segurança até nov/2028, e cobre o curso inteiro. As versões anteriores, .NET 8 e .NET 9, perdem o suporte em 10/nov/2026.

🔀 O que é Git? E GitHub vs GitLab?

Git é um sistema de controle de versão distribuído: registra o histórico de mudanças do código, permite branches (linhas paralelas de trabalho), merge (juntar linhas) e voltar a qualquer ponto do passado. Cada dev tem o repositório completo no próprio computador. Analogia: é o "salvar jogo" do código — cada commit é um ponto de salvamento com uma legenda.

  • Repositório (repo): o projeto + todo o histórico.
  • Commit: uma "foto" das mudanças, com uma mensagem explicando o porquê.
  • Branch: linha paralela (ex.: feat/novo-endpoint); main é a principal.
  • Remote / origin: a cópia no servidor (GitHub/GitLab). origin é o apelido padrão dela.
  • push / pull: enviar / trazer mudanças do remote.
  • PR/MR (Pull/Merge Request): pedido de revisão para juntar um branch ao main.

1Configurar identidade + SSH (uma vez por computador)

🖥️ Terminal: VS Code Ctrl+`.
terminal — identidade + chave SSH 
# Identidade dos commits (é o que aparece no histórico: quem fez o quê)
git config --global user.name "Seu Nome"
git config --global user.email "seu@email.com"
git config --global init.defaultBranch main   # todo repo novo já nasce com o branch 'main'
git config --global --list                    # confere o que foi gravado

# SSH: uma chave para o site saber que é você, sem digitar senha a cada push
ssh-keygen -t ed25519 -C "seu@email.com"       # aperte Enter nas perguntas (ou defina uma senha)
cat ~/.ssh/id_ed25519.pub                       # copie TODA a linha e cole no site:
                                                #   GitHub → Settings → SSH and GPG keys → New SSH key
                                                #   GitLab → Preferences → SSH Keys → Add new key

# Testa a conexão (use o do SEU site)
ssh -T git@github.com    # esperado: "Hi SEU-USUARIO! You've successfully authenticated..."
ssh -T git@gitlab.com    # esperado: "Welcome to GitLab, @SEU-USUARIO!"
🔐 Pública × privada: o ssh-keygen cria duas chaves. A .pub (pública) vai para o site — pode mostrar para qualquer um. A outra (id_ed25519, sem extensão) é privada: nunca copie, nunca commite, nunca mande para ninguém.

2Primeiro commit e primeiro push da sua API

🖥️ Terminal: VS Code Ctrl+`, na pasta HelloDotnetApi.

Antes: crie no site um repositório vazio chamado HelloDotnetApi — sem README, sem .gitignore (senão o primeiro push é recusado por históricos diferentes).

terminal — primeiro commit e primeiro push 
# 1) .gitignore: impede que bin/ e obj/ (lixo de build) entrem no Git.
#    Se você baixou o ZIP, ele JÁ VEM — pule esta linha.
dotnet new gitignore

# 2) Inicia o repositório já com o branch 'main'
#    (sem o -b main, algumas instalações criam 'master' e o push da linha 5 falha)
git init -b main

# 3) Primeiro commit
git add .
git commit -m "feat: laboratório hello .NET 10"

# 4) Liga ao repositório do site — URL SSH (a chave que você configurou acima)

#   GitLab: git@gitlab.com:SEU-USUARIO/HelloDotnetApi.git

# 5) Envia. Este é o ÚNICO push direto no main: é o commit inicial.
#    Daqui em diante, branch + PR (próximo passo).
git push -u origin main

3O fluxo de trabalho do dia a dia: branch → commit → PR

Regra de ouro do trabalho em equipe: ninguém faz push direto no main. Cada tarefa ganha um branch; o código entra no main só depois de revisado num PR/MR.

terminal — ciclo de uma tarefa, do início ao merge 
# 1) Começa SEMPRE do main atualizado
git switch main
git pull                                   # traz o que os colegas já juntaram

# 2) Cria um branch para a tarefa (o nome diz o que é)
git switch -c feat/novo-endpoint           # -c = cria e já troca para ele

# 3) ... edita o código ...

# 4) Revisa antes de gravar
git status                                 # QUAIS arquivos mudaram
git diff                                   # O QUE mudou dentro deles

# 5) Grava (commit) — escolha os arquivos e explique o porquê
git add Program.cs
git commit -m "feat: adiciona endpoint /hello/{nome}"

# 6) Publica o branch no servidor
git push -u origin feat/novo-endpoint      # -u lembra o destino: nos próximos, só 'git push'

# 7) No site, abra o Pull Request (GitHub) / Merge Request (GitLab).
#    Depois que o PR for aprovado e juntado ao main:
git switch main
git pull
git branch -d feat/novo-endpoint           # apaga o branch local que já foi juntado
✍️ Mensagem de commit: o prefixo (feat: nova funcionalidade, fix: correção, docs: documentação, refactor:, test:) segue o padrão Conventional Commits — o mesmo da Tab 2.

4O mesmo fluxo pela GUI do VS Code (Source Control)

  1. Branch: clique no nome do branch no rodapé (canto inferior esquerdo) → Create new branch… → digite feat/novo-endpoint.
  2. Abra Source Control (Ctrl+Shift+G): aparecem os arquivos modificados. Clique em um para ver o diff lado a lado.
  3. Passe o mouse no arquivo → + (é o git add).
  4. Digite a mensagem no campo de cima → ✓ Commit.
  5. Publish Branch (ou Sync Changes) envia ao servidor — é o git push.
  6. Abra o PR/MR no site. Para trazer mudanças dos colegas: … → Pull.

⑥ 📌 Para ir além: o que há de novo no C# 14

Opcional — volte aqui depois das Tabs 6 e 7, quando propriedades e classes já forem familiares.

O .NET é a plataforma (as ferramentas e bibliotecas); o C# é a linguagem. Cada .NET traz uma versão nova do C#: o .NET 10 traz o C# 14, sem configuração nenhuma — você já está usando ele nos dois laboratórios. Duas novidades:

C# 14 — palavra-chave field e extension members (exemplo para ler) 
// ─────────────────────────────────────────────────────────────────────
// NOVIDADE 1: a palavra-chave 'field'
// Antes do C# 14, para validar um valor no 'set' você precisava declarar
// um campo privado à mão (private string _nome;). Agora 'field' é o campo
// que o compilador cria sozinho por trás da propriedade.
// ─────────────────────────────────────────────────────────────────────
public class Produto
{
    public string Nome
    {
        get;                                    // devolve o valor guardado
        set => field = string.IsNullOrWhiteSpace(value)
            ? throw new ArgumentException("Nome é obrigatório")
            : value.Trim();                     // guarda já sem espaços nas pontas
    } = "";
}

// ─────────────────────────────────────────────────────────────────────
// NOVIDADE 2: extension members (bloco 'extension')
// "Extensão" = acrescentar métodos a um tipo que não é seu (aqui, string)
// sem mexer nele. Antes só dava para criar MÉTODOS de extensão; agora o
// bloco 'extension' também permite PROPRIEDADES.
// ─────────────────────────────────────────────────────────────────────
public static class TextoExtensions
{
    extension(string texto)                     // "estou estendendo o tipo string"
    {
        public bool EstaVazio => string.IsNullOrWhiteSpace(texto);          // propriedade nova
        public string Resumo(int max) =>                                     // método novo
            texto.Length <= max ? texto : texto[..max] + "…";
    }
}

// Uso — parece que string sempre teve esses membros:
//   "   ".EstaVazio                → true
//   "Hello World".Resumo(5)        → "Hello…"

Outras do C# 14: atribuição com ?. (cliente?.Nome = "Ana"; só atribui se cliente não for null) e nameof com genéricos abertos (nameof(List<>)). Aprofundar: Novidades do C# 14 (Microsoft Learn).
