🐳 Introdução

A receita que funciona em qualquer cozinha

Você já passou por isso: desenvolve uma aplicação Java no IntelliJ, tudo funciona perfeito na sua máquina. Entrega o código para o colega rodar no Linux dele e... "na minha máquina funciona, no servidor não". Frustrante, né?

O problema é que sua aplicação depende de um ecossistema específico: versão do JDK, configurações de sistema, dependências instaladas, variáveis de ambiente... É como tentar fazer uma receita complexa em uma cozinha diferente toda vez.

💡 Docker é sua "cozinha portátil": ele empacota não só o código, mas também o ambiente completo (dependências, configurações, sistema operacional) em um contêiner que roda igual em qualquer lugar.

Para quem já programa em Java no IntelliJ ou C# no VS Code, o Docker vai ser seu melhor amigo quando chegar a hora de:

  • Subir um banco MySQL em segundos (sem instalar nada no seu SO)
  • Garantir que seu projeto funciona na máquina do colega, no servidor de produção, ou até em um container na nuvem
  • Testar diferentes versões de bibliotecas sem quebrar seu ambiente de desenvolvimento
🎯 O que você vai aprender hoje: não é só "rodar comandos". É entender por que Docker resolve problemas reais de Engenharia de Software que você vai enfrentar no mercado de trabalho.

📦 Missão 1 — VM vs Contêiner

Antes de sair digitando comandos, você precisa entender o que é um contêiner. Não é mágica: é uma tecnologia com vantagens e limitações específicas.

🖥️ Máquina Virtual (VM)

Uma VM é um computador virtual completo. Ela roda um sistema operacional inteiro (Linux, Windows) em cima do seu sistema físico. É como ter um "computador dentro do computador".

Prós: isolamento total, roda qualquer SO.

Contras: pesada (GBs de RAM), lenta para iniciar (minutos), consome muitos recursos.

📦 Contêiner Docker

Um contêiner é um processo isolado que compartilha o kernel do sistema hospedeiro. Ele empacota só o que sua aplicação precisa: código, dependências, configurações.

Prós: leve (MBs), rápido (segundos), eficiente em recursos.

Contras: menos isolamento que VM, só roda Linux (no host Linux) ou Linux sobre VM (no Windows/Mac).

Código de conexão JDBC para IntelliJ:

// Adicione no pom.xml ou baixe o JAR do MySQL Connector
// <dependency>
//   <groupId>mysql</groupId>
//   <artifactId>mysql-connector-java</artifactId>
//   <version>8.0.33</version>
// </dependency>

import java.sql.Connection;
import java.sql.DriverManager;
import java.sql.ResultSet;
import java.sql.Statement;

public class ConexaoMySQL {
    public static void main(String[] args) {
        String url = "jdbc:mysql://localhost:3306/aula_ds3";
        String user = "root";
        String password = "senha123";
        
        try (Connection conn = DriverManager.getConnection(url, user, password)) {
            Statement stmt = conn.createStatement();
            ResultSet rs = stmt.executeQuery("SELECT * FROM alunos");
            
            while (rs.next()) {
                System.out.println("ID: " + rs.getInt("id") + 
                                 ", Nome: " + rs.getString("nome"));
            }
        } catch (Exception e) {
            e.printStackTrace();
        }
    }
}

Código de conexão para VS Code com MySqlConnector:

// Instale o pacote NuGet: dotnet add package MySqlConnector

using MySqlConnector;

class Program {
    static void Main() {
        string connectionString = "Server=localhost;Port=3306;Database=aula_ds3;User=root;Password=senha123;";
        
        using (var connection = new MySqlConnection(connectionString)) {
            connection.Open();
            
            var command = new MySqlCommand("SELECT * FROM alunos", connection);
            using (var reader = command.ExecuteReader()) {
                while (reader.Read()) {
                    Console.WriteLine($"ID: {reader.GetInt32("id")}, " +
                                    $"Nome: {reader.GetString("nome")}");
                }
            }
        }
    }
}

  1. docker stop mysql-aula
  2. docker start mysql-aula
  3. Conecte novamente e rode SELECT * FROM alunos; — os dados AINDA ESTÃO LÁ!
  4. Agora execute: docker rm -f mysql-aula

❓ Pergunta: Por que os dados sumiram quando você removeu o contêiner, mas não quando você apenas parou e reiniciou?

💾 Missão 4 — Volume + docker-compose

O desafio-surpresa revelou o problema: contêineres são efêmeros. Quando você remove um contêiner, a camada de escrita (onde ficam seus dados) é destruída.

💡 Solução: VOLUMES
Um volume é um diretório persistente fora do ciclo de vida do contêiner. É como um "HD externo" que você conecta e desconecta, mas os dados ficam lá.

Comando MySQL com volume nomeado

$ docker run --name mysql-aula -e MYSQL_ROOT_PASSWORD=senha123 -p 3306:3306 -v mysql_data:/var/lib/mysql -d mysql:latest

O que mudou: -v mysql_data:/var/lib/mysql cria um volume chamado mysql_data e o monta no diretório /var/lib/mysql (onde o MySQL armazena dados). Agora, mesmo que você remova o contêiner, os dados ficam no volume.

docker-compose.yml: orquestração simplificada

Em vez de rodar vários comandos docker run soltos, você define tudo em um arquivo YAML e sobe com um único comando: docker-compose up.

🎯 Por que docker-compose é melhor?
  • Reprodutibilidade: um único arquivo define toda a infraestrutura
  • Versionamento: você pode commitar o YAML no Git
  • Orquestração: sobe todos os serviços com um comando
  • Networking: serviços se comunicam pelo nome (ex: mysql em vez de localhost)
