💡 Conceito em 60 Segundos: A Ponte Digital

Uma API (Application Programming Interface) é um conjunto de regras, contratos e protocolos que permite que dois sistemas de software diferentes conversem e troquem dados de forma padronizada, sem precisar saber como o outro foi construído internamente.

🍽️
Analogia do Restaurante: Você é o Cliente (Frontend), a cozinha é o Servidor/Banco de Dados (Backend) e o Garçom é a API. Você lê o Cardápio (Contrato da API), faz seu pedido ao garçom (Request), o garçom leva até a cozinha, que prepara o prato e o garçom traz a comida quentinha até sua mesa (Response). Você não entra na cozinha nem mexe nos fogões!

💡 Conceito em 60 Segundos: Os Verbos HTTP (CRUD)

No protocolo HTTP, os Métodos (ou Verbos) indicam a intenção semântica sobre um Recurso (como /api/users), mapeando as operações fundamentais do CRUD:

GET (Read)
Buscar/consultar dados sem alterar o estado do servidor.
POST (Create)
Criar um novo recurso enviando dados no corpo (Body).
PUT / PATCH (Update)
Atualizar dados de um recurso existente.
DELETE (Delete)
Remover definitivamente um recurso.

💡 Conceito em 60 Segundos: O Semáforo e os Metadados da Web

O Status Code de 3 dígitos resume o desfecho da requisição (2xx Sucesso, 4xx Erro do Cliente, 5xx Erro do Servidor), enquanto os Headers carregam metadados cruciais (como autorização e formato JSON).

💡 Conceito em 60 Segundos: O que torna uma API RESTful?

O modelo REST (Representational State Transfer) estabelece princípios essenciais para a web: Cliente-Servidor, Stateless (sem guardar sessão de usuário na memória do servidor), Cacheable e Interface Uniforme baseada em substantivos no plural.

💡 Conceito em 60 Segundos: O Contrato Antes do Código

Na abordagem API-First, a interface de programação é tratada como um produto de primeira classe: o Contrato da API é planejado, documentado e validado antes de escrever qualquer linha de código backend ou frontend.

A especificação OpenAPI (antigo Swagger) é o padrão global da indústria (em YAML ou JSON) para descrever esse contrato de forma legível tanto para humanos quanto para computadores.

📐
Analogia da Planta Arquitetônica: Ninguém constrói um prédio colocando tijolos aleatórios para só depois descobrir onde vai passar o cano. O arquiteto desenha a Planta Baixa (Contrato OpenAPI). O encanador e o eletricista trabalham em paralelo com base na mesma planta, sem pisar no pé um do outro!

200 OK Status 2xx Requisição executada com sucesso pleno. GET /api/produtos retornando a lista.
201 Created Status 2xx Novo recurso criado com sucesso no banco. POST /api/usuarios após cadastrar conta.
204 No Content Status 2xx Sucesso, mas sem corpo de resposta para devolver. DELETE /api/tarefas/10 concluído.
400 Bad Request Status 4xx Corpo da requisição inválido ou JSON mal formatado. Enviar campo obrigatório faltando no schema.
401 Unauthorized Status 4xx Cliente não autenticado (falta token ou login). Acessar rota privada sem Bearer Token.
403 Forbidden Status 4xx Cliente autenticado, mas sem permissão de acesso. Usuário comum tentando deletar outro usuário.
404 Not Found Status 4xx Rota ou recurso inexistente no servidor. GET /api/clientes/999999 (não cadastrado).
500 Internal Error Status 5xx Exceção não tratada no código do servidor. Crash do backend ou falha de conexão com BD.
503 Service Unavail Status 5xx Servidor temporariamente sobrecarregado ou em manutenção. Queda de servidor em Black Friday.
Idempotência Conceito REST Executar a mesma requisição N vezes gera o mesmo efeito no estado final. GET, PUT e DELETE são idempotentes; POST não.
Stateless Conceito REST O servidor não guarda estado de sessão entre requisições. Token JWT trafega em cada chamada.
