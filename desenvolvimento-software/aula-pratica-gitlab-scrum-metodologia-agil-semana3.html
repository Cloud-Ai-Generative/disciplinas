Users API Implementar a persistência: conectar a API Java ao banco UsersCLI MySQL legado (schema sd3). POST /users · GET /users · conectado ao MySQL · API via Docker Criar & Listar (22/09) a partir da main via docker compose up

1.1 Padrões de qualidade e boas práticas (código nível comercial)

Nomenclatura em inglês descritiva — classes, métodos, variáveis e pacotes em inglês. Nada de UsuarioService: é UserService.
Javadoc / XML comments obrigatórios em APIs públicas (services, controllers, DTOs).
Mensagens, erros e logs em inglês — internacionalização real; o log nunca é PT-BR.
API roda via Docker — docker compose up é a demo; nada de rodar pela IDE em demo.

1.2 Estratégia de branching, code review e CI/CD

Branching: branches de feature a partir da main, uma por ticket. Commits atômicos com mensagens claras (tipo + escopo).
Fluxo de MR: CI verde → 1 aprovação de par → aprovação do Practitioner (professor) → merge na main.
Demos: sempre executadas a partir da main (única fonte da verdade).
CI obrigatória: compilação + testes. Pipeline vermelho bloqueia merge.

1.3 Schema legado sd3.users (referência de leitura)

schema legado (MySQL, não mude)

      
Este schema é legado: não gere via JPA (ddl-auto=none). A API se adapta ao banco existente.

8.4 O que é cada gráfico

      

        
🔥 BurndownQuantos pontos restam por dia. Linha real caindo = sprint saudável. Platô horizontal = impedimento (ex.: CI vermelha, revisão travada).

        
📈 Burn UpQuantos pontos foram concluídos por dia vs escopo (linha superior). Escopo subindo no meio da sprint = scope creep (ruim).
