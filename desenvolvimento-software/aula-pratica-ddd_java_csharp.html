💡 Conceito em 60 Segundos: A Linguagem Compartilhada

O maior gargalo no desenvolvimento de software complexo não é a linguagem de programação, mas a **perda na tradução** entre o que o Especialista de Domínio (Domain Expert) fala e o que o desenvolvedor codifica.

A Linguagem Ubíqua (Ubiquitous Language) é o vocabulário rigoroso e sem ambiguidade acordado por ambos. Se o especialista diz "Cancelar Pedido por Inadimplência", a classe de domínio deve ter um método pedido.cancelarPorInadimplencia(), e NUNCA um genérico pedido.setStatus(4).

🏥
Analogia da Equipe Cirúrgica: Na sala de cirurgia, o cirurgião não diz "me passa aquele negócio de metal pontudo". Ele pede o "Bisturi 10". Toda a equipe compartilha termos exatos para que ninguém erre por suposição.

💡 Conceito em 60 Segundos: Bounded Contexts & Context Mapping

Tentar criar um "Modelo Único Universal" para uma empresa inteira é a receita garantida para o fracasso. No DDD Estratégico, dividimos o problema em **Subdomínios**:

  • Core Domain: O coração do negócio, seu diferencial competitivo (ex: Algoritmo de precificação e risco).
  • Supporting Subdomain: Complemento necessário que apoia o Core (ex: Catálogo de produtos).
  • Generic Subdomain: Algo que você poderia comprar pronto (ex: Envio de e-mail / Autenticação).

Um Bounded Context (Contexto Delimitado) estabelece a fronteira onde uma palavra tem um único significado. A palavra "Produto" no contexto de Vendas significa preço e foto; no contexto de Logística, significa peso, volume e dimensões de caixa!

💡 Conceito em 60 Segundos: Identidade vs Valor

No Design Tático, a distinção entre Entidades e Objetos de Valor (Value Objects) é vital:

  • Entidade: Possui um Identificador Único (ID) que permanece o mesmo por toda a sua vida útil, mesmo que todos os seus atributos mudem (ex: Cliente com CPF ou Pedido com UUID).
  • Value Object (VO): É definido exclusivamente pelos seus valores. Não tem ID, é 100% imutável e duas instâncias com os mesmos dados são consideradas idênticas (ex: Dinheiro(100, "BRL"), CPF, Endereco).

💡 Conceito em 60 Segundos: A Raiz de Agregação e suas Regras

        

          

            Um Agregado (Aggregate) é um agrupamento de Entidades e Value Objects tratados como uma única unidade coesa de consistência transacional.
          

          

            Todo Agregado possui uma Raiz de Agregação (Aggregate Root). O mundo exterior só pode conversar diretamente com a Raiz! Ninguém pode alterar um ItemPedido por fora: você pede para o Pedido (a Raiz) adicionar o item, e é o Pedido que garante as **Invariantes** (regras que nunca podem ser violadas, como total não negativo e limite de itens).

💡 Conceito em 60 Segundos: Eventos de Domínio & Repositórios

        

          

            Um Domain Event (Evento de Domínio) registra algo importante que já aconteceu no passado do negócio (ex: PedidoPagoEvent, EstoqueEsgotadoEvent). Ele permite desacoplar subdomínios: quando o Pedido é pago, o contexto de Vendas dispara o evento e o contexto de Envio/Logística reage sem que um conheça o código do outro!
          

          

            Já o Repositório (Repository) fornece uma ilusão ao domínio de que todos os agregados estão em uma coleção na memória. Ele é definido por uma **Interface** no Domínio (IPedidoRepository) e sua implementação concreta com Entity Framework / Hibernate fica isolada na camada de **Infraestrutura**.

📋 Cola Rápida (DDD Terminology & Patterns)

        

        

          

            
              

                Padrão / Termo
                Tipo
                Definição Clara
                Exemplo Java / C#
              

            
            
              

                Linguagem Ubíqua
                Estratégico
                Vocabulário rigoroso compartilhado por especialistas e programadores.
                Método pedido.cancelarPorInadimplencia()
              

              

                Bounded Context
                Estratégico
                Fronteira conceitual onde um modelo e seus termos são válidos sem colisão.
                Microsserviço de Faturamento vs Logística
              

              

                Entity
                Tático
                Objeto definido por um identificador estável que sobrevive a mutações.
                class Cliente { UUID Id; string Nome; }
              

              

                Value Object (VO)
                Tático
                Objeto imutável sem ID, avaliado exclusivamente pelo valor de seus campos.
                record Dinheiro(decimal Valor, string Moeda)
              

              

                Aggregate Root
                Tático
                Entidade mestre que protege e governa todas as invariantes do seu grupo.
                Pedido protegendo seus Itens
              

              

                Invariante
                Tático
                Regra de negócio que deve permanecer 100% válida a cada operação.
                "Desconto não pode superar 20% do total"
              

              

                Modelo Anêmico
                Anti-Pattern
                Classes que só possuem getters/setters e transferem as regras para services.
                pedido.setStatus(2); service.validar(pedido);
              

              

                Domain Event
                Tático / Reativo
                Notificação que relata um fato relevante já ocorrido no domínio.
                public record PedidoPagoEvent(UUID PedidoId)
              

              

                Repository
                Tático / Porta
                Interface no Domínio para carregar e salvar raízes de agregação.
                interface IPedidoRepository { Task Save(Pedido p); }
